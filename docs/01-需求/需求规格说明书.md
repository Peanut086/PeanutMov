## 1. 项目概述

### 1.1 背景

用户为个人开发者，希望拥有一个**自用**的移动观影客户端，把散落在自有网盘、NAS 媒体服务器、以及自己配置的站点源中的影视内容统一到一个"海报墙 + 播放器"的体验里，并能离线缓存、系统投屏。市面 App 广告多、隐私差、不允许自定义源；用户希望数据完全留在本地。

### 1.2 产品目标

1. **开箱可用**：首次安装后无需任何配置，即可看到海报墙并成功播放一段公开版权样片，验证"浏览 → 详情 → 播放 → 记录"全链路。
2. **源可自配置**：支持网盘/媒体服务器（AList、WebDAV、Jellyfin 风格）、用户自建站点源、订阅 JSON 批量导入三类接入方式。
3. **本地优先**：全部数据（源配置、媒体元数据、历史、收藏、下载任务）存于本机 IndexedDB，无服务器、无账号、无云端同步。
4. **合规边界清晰**：App 不内置、不分发任何受版权保护的片源；只提供"播放用户自有/已授权内容"的工具能力。

### 1.3 成功指标（首版验收口径）

| 指标 | 目标 |
| --- | --- |
| 冷启动到海报墙可交互（演示源） | ≤ 2.0s（中端 Android 机） |
| 演示源首次点播起播 | ≤ 3.0s（4G / 家宽） |
| 海报墙滚动 | 稳定 60fps，无明显掉帧 |
| 断点续播误差 | 恢复播放位置与原位置偏差 ≤ 2s |
| 首版崩溃率 | 手工验收全流程 0 崩溃 |

### 1.4 运行平台

- **Android App**：**Android 10（API 29）及以上可安装运行**（`android/variables.gradle` 的 `minSdkVersion = 29`，OPT-06 决策，2026-11-06）；**回归基线为 Android 10（API 29）与 Android 14（API 34）真机**；Android 6.0–9.0（API 23–28）自 v1.10 起**不再支持安装**（原因见 §6.2 NFR-C01）；Vue 3 + Vite + TypeScript + Capacitor 打包。
- **浏览器**：Chrome 100+ / Edge 100+，作为开发调试与兜底运行环境（`npm run dev` 即可跑通非原生能力，原生能力做能力降级）。
- **不做**：iOS、桌面端、TV 端、平板专项适配（平板按大屏自适应即可，不单独立项）。

## 2. 用户画像与核心场景

### 2.1 用户画像

| 画像 | 描述 | 关键诉求 |
| --- | --- | --- |
| 主用户（本人） | 个人开发者，熟悉 Vue；有 NAS / 网盘会员 / 自建站点；重视隐私与无广告 | 一处看全部、能离线、能投屏、能续播 |
| 次要用户（家人） | 非技术用户，只会"点开 App 看剧" | 首页能直接继续观看、操作简单、不误触 |

**能力假设**：主用户能自行准备源配置（地址、账号、Token、订阅 JSON）；家人用户不配置任何东西，只消费已配置好的库。

### 2.2 核心场景

**场景 A：首次打开体验（零配置）**
安装 → 启动 → 合规提示（一屏，可"我知道了"）→ 海报墙展示演示源 12 部公开版权样片 → 点卡片 → 详情页 → 播放 → 系统播放器能力（倍速/字幕/手势）→ 退出后首页出现"继续观看"。

**场景 B：接入自有 NAS 并追剧**
设置 → 源管理 → 新增源 → 选择"Jellyfin/AList/WebDAV" → 填地址与凭据 → "测试连接"通过 → 保存 → 媒体库自动出现该源内容 → 进入剧集详情 → 选择第 3 集 → 播放到 12:30 退出 → 历史记录显示"看到第 3 集 12:30" → 次日首页"继续观看"一键回到 12:30。

**场景 C：订阅批量导入 + 站点源失效处理**
源管理 → 导入订阅 → 粘贴订阅 JSON 地址 → 预览 8 个源 → 确认导入（6 成功 / 2 因缺字段跳过并提示原因）→ 媒体库可按源筛选 → 某源播放失败 → 播放器提示"该源暂不可用"→ 一键切换备用线路 / 返回详情换源。

**场景 D：离线缓存 + 投屏**
详情页 → 下载第 1-2 集 → 下载页看到队列进度、暂停/继续 → 完成后断开网络仍可播放 → 在播放页点"投屏" → 调起 Android 系统投屏/分享选择器 → 选择电视设备。

## 3. 范围（Scope）

### 3.1 In Scope（首版必须交付）

1. 源管理：演示源、AList、WebDAV、Jellyfin 风格、站点源（用户自配）、订阅 JSON 导入（URL / 本地文件）。
2. 媒体库：海报墙、分类与筛选、搜索、分页加载、下拉刷新、离线缓存展示。
3. 详情与剧集：海报详情、多线路、剧集列表、收藏、继续观看入口。
4. 播放器：HLS(m3u8)/MP4 播放、倍速、字幕（外挂 srt/vtt）、手势（快进/音量/亮度）、断点续播、全屏与横竖屏、清晰度切换、错误恢复。
5. 历史与收藏：观看历史、进度、收藏夹、继续观看。
6. 下载缓存：应用内下载管理器（队列、进度、暂停/继续、取消、失败重试），Android 用 Capacitor Filesystem 落盘，Web 用 Blob 落 IndexedDB 兜底，支持离线播放。
7. 投屏：仅"调用 Android 系统投屏/分享选择器（Intent 层）"。
8. 设置：播放偏好、外观、数据备份（本地 JSON 导出/导入）、缓存清理、合规入口、关于。
9. 演示源：内置样例数据，开箱可播。
10. 合规提示：首次启动声明 + 源配置处提示 + 关于页说明。

### 3.2 Out of Scope（首版不做，明确排除）

| 项 | 说明 |
| --- | --- |
| 任何内置/分发受版权保护的片源、破解接口、盗版站点聚合 | 合规红线，永不做 |
| DRM（Widevine 等）内容解密/绕过 | 不做；遇到 DRM 内容仅提示"不支持受保护内容" |
| 账号体系、云同步、多设备同步、服务端 | 不做 |
| DLNA/UPnP 设备发现与协议投屏（自建 Renderer 控制） | 二期（Q-02 确认） |
| 评论、评分提交、社区 | 不做；**弹幕改为只读展示**（v1.7 / FR-54，2026-10-25 拍板修订；发送弹幕与社区仍不做） |
| 体育赛事直播 | 不做（直播 IPTV 已由 v1.4 / CHG-13 交付、v1.7 / FR-55 强化 EPG/收藏，原「不做」口径自 v1.4 起废止——2026-10-25 补注） |
| 自动刮削（TMDB 等第三方元数据 API 联网刮削） | 不做（首版仅用源返回的元数据；演示源内置静态元数据） |
| 跳过片头片尾、AI 字幕、字幕在线搜索 | 二期 |
| iOS / 桌面 / TV 端 | 不做 |
| 视频转码、码率自适应服务端能力 | 不做（仅客户端 HLS 多码率切换） |
| 应用内浏览器/网页抓取（HTML 解析站点） | 不做（Q-01） |
| **内置任何第三方线路 / 订阅地址** | **不做（FR-46 / v1.1 补充）**：仓库与打包产物中不得出现任何具体第三方 TVBox/影视接口地址（含用户实测提供的 49 条），用户需自行导入自己的源；App 只提供 TVBox 兼容解析能力与线路质量可见性，不预置、不共享任何线路清单；**v1.7 修订（2026-10-25 拍板）**：允许随版本内置一份人工筛选的「推荐订阅清单」（FR-56：不含成人内容、设置可整体关闭、仅评测展示、导入需用户逐项确认），其余红线不变 |

## 4. 术语表

| 术语 | 含义 |
| --- | --- |
| 源（Source） | 一个可浏览、可播放的内容提供方配置（演示源 / AList / WebDAV / Jellyfin / 站点） |
| 适配器（SourceAdapter） | 把不同源协议统一为 `search / browse / getDetail / resolvePlayUrl` 等能力的实现 |
| 媒体条目（MediaItem） | 一部影片 / 一部剧的聚合元数据 |
| 剧集（Episode） | 媒体条目下的一集（电影为单集） |
| 播放线路（PlayLine） | 同一集的不同播放地址/清晰度来源 |
| 续播点 | 上次播放位置（秒），用于断点续播 |
| 订阅（Subscription） | 一份包含多个源配置的 JSON（兼容 TVBox `sites[]` 风格） |
| 演示源 | App 内置、使用公开版权样片与公开测试视频的本地适配器 |

## 5. 功能需求（FR）与验收标准（AC）

> 约定：
> - 优先级：**P0** = 首版必须；**P1** = 首版应有，资源紧张可延后一个迭代；**P2** = 首版可做可不做。
> - 验证方式：`自动化` = 单元/组件测试可断言；`手工` = 需人工按步骤验收。
> - AC 类型标注：正常态 / 空态 / 错误态 / 边界态 / 性能 / 兼容。
> - 所有 AC 均可被第三方按步骤复现判定通过/不通过。

### 5.1 模块 A：源管理

#### FR-01 源列表与源类型总览（P0）

用户可在"源管理"页查看全部已配置源，以及 App 支持的源类型入口。

- 展示字段：源名称、类型徽标（演示/AList/WebDAV/Jellyfin/站点/订阅导入）、启用开关、最近一次连通状态（正常/异常/未检测）、条目数（可选）。
- 支持类型：`demo`（内置演示源）、`alist`、`webdav`、`jellyfin`、`site`（用户自配站点）。
- 源列表默认按用户排序值升序，演示源固定置底并打"内置"角标。

**AC**
- **AC-01**（正常态｜手工）进入"源管理"，已配置 3 个源时，列表按排序值升序展示 3 条，每条含名称、类型徽标、启用开关、健康状态；演示源显示"内置"角标且位于末尾。
- **AC-02**（空态｜自动化）除演示源外无任何源时，列表仅显示演示源 1 条，并展示引导文案"添加你自己的源"及"新增源 / 导入订阅"两个按钮；不出现空白页。

#### FR-02 新增 / 编辑 / 删除源（P0）

- 新增源：选择类型 → 填写类型对应字段 → "测试连接" → 保存。
- 字段校验：名称必填（1-30 字）；地址必填且必须为 `http(s)://`；端口/路径可选；账号/密码/Token 按类型条件必填。
- 编辑：可改名称、地址、凭据、启用状态；修改后条目缓存失效并提示"需刷新媒体库"。
- 删除：二次确认；删除源时同步删除其媒体条目缓存、剧集缓存、分类缓存（历史与收藏保留快照并标记"源已移除"）；正在下载的任务需用户确认是否一并取消。

**AC**
- **AC-03**（正常态｜手工）新增 Jellyfin 源，填入合法地址与 API Key，点"测试连接"显示"连接成功（耗时 320ms）"，保存后列表出现该源且开关为开。
- **AC-04**（错误态｜自动化）地址填 `ftp://x` 或空值、名称为空时，保存按钮禁用并就地提示字段错误；"测试连接"在地址非法时不发请求。连接失败（超时/401/404/证书错误）时展示对应错误文案与建议（检查地址/凭据/网络），且**不得**保存为"可用"状态。
- **AC-05**（边界态｜自动化）名称输入 30 个字符可保存，第 31 个字符被截断或禁止输入；地址末尾带 `/` 与不带 `/` 均能保存并在内部归一化为同一种存储形式。

#### FR-03 源启用 / 禁用 / 排序 / 默认源（P0）

- 启用开关实时生效：媒体库、搜索、首页聚合只使用已启用源。
- 支持拖拽或"上移/下移"调整顺序，顺序影响媒体库"全部"聚合展示顺序与"默认源"选择。
- 可设置"默认源"（首次进入媒体库时选中），默认源被禁用时自动回退到第一个已启用源。

**AC**
- **AC-06**（正常态｜自动化）禁用源 A 后，媒体库"全部"列表不再出现 A 的条目；重新启用后刷新可见 A 的条目；开关状态在重启 App 后保持。
- **AC-07**（边界态｜手工）将默认源设为 A 后禁用 A，再次进入媒体库时自动选中第一个已启用源，且设置页"默认源"显示同步更新；全部源（含演示源）被禁用时，媒体库展示空态"没有启用的源"并提供"去启用"入口。

#### FR-04 订阅地址导入（P0）

- 输入订阅 URL（http/https），点击"获取并解析"，展示解析结果预览（源名称、类型、可用性、跳过原因）。
- 支持导入前勾选要导入的源；支持"同名源覆盖 / 跳过 / 保留两份"策略（默认跳过并提示）。
- 导入结果给出汇总：成功 N 个、跳过 M 个（原因列表）、失败 K 个（原因）。
- 订阅 URL 与最近导入时间可记录在本地，便于"检查更新"（P1）。

**AC**
- **AC-08**（正常态｜手工）粘贴合法订阅 URL，解析出 8 个源，预览页展示 8 行且默认全选；确认导入后提示"成功 8，跳过 0，失败 0"，源列表新增 8 条。
- **AC-09**（错误态｜自动化）订阅地址返回 404 / 非 JSON / JSON 结构不合法时，分别提示"地址不可访问(404)""内容不是合法 JSON""订阅格式不支持"，不写入任何源，且保留用户已输入的 URL。
- **AC-10**（边界态｜自动化）订阅 JSON 含 200 个源时，导入在 10s 内完成（或分批导入并展示进度），UI 不卡死；含 `sites: []` 空数组时提示"订阅中没有任何源"。

#### FR-05 本地 JSON 文件导入（P0）

- 支持从设备选择 `.json` 文件导入（Android 用系统文件选择器；Web 用 `<input type="file">`）。
- 文件大小上限 2MB；超出提示"文件过大"。
- 解析与预览流程与 FR-04 一致，可与 URL 导入共用预览组件。

**AC**
- **AC-11**（正常态｜手工）选择本地 `subscription.json`（含 3 源）后，预览 3 行，导入后源列表新增 3 条，源类型与地址与文件内容一致。
- **AC-12**（错误态｜边界｜自动化）选择 2.5MB 文件提示"文件过大（上限 2MB）"且不解析；选择非 `.json` 后缀文件提示"仅支持 JSON 文件"；选择内容为空文件提示"文件内容为空"。

#### FR-06 导入预览、字段归一化与部分失败处理（P0）

- 归一化：把 TVBox 风格 `sites[]` 映射为内部 `SourceConfig`；识别 `type`（0/1/3 等数字或 `"alist"`/`"webdav"`/`"jellyfin"`/`"site"` 字符串）到内部类型。
- 单条源缺关键字段（`key` / `name` / `api` / `ext` 缺失且该类型必需）时：该条标记"跳过"并给出具体原因，不影响其它条导入。
- 导入为事务性操作：整体确认后一次性写入；写入失败（如 IndexedDB 配额不足）时全部回滚并提示。

**AC**
- **AC-13**（正常态｜自动化）给定 6 条合法 + 2 条缺 `api` 的 `sites`，导入结果为成功 6、跳过 2，跳过行显示"缺少 api 字段"，媒体库只出现 6 个源。
- **AC-14**（错误态｜自动化）模拟 `sources` 表写入抛错，导入结果为"失败，未导入任何源"，DB 中源数量与导入前一致（事务回滚验证）。

#### FR-07 源健康检查与失效降级（P1）

- 进入"源管理"时对已启用源做轻量连通性探测（每源 ≤3s 超时，并发上限 6；CHG-05 由 3 提升，见 FR-47）。
- 健康状态：`ok` / `auth_failed` / `timeout` / `unreachable` / `bad_config` / `unknown`，并在列表展示文案。
- 播放或浏览失败时将该源标记为 `unreachable` 并在详情/播放页提示"该源暂不可用，可切换其他源"。
- **不做**后台定时轮询（仅前台触发）。

**AC**
- **AC-15**（错误态｜手工）断开网络后进入源管理，3s 内所有源状态变为"连接超时"，页面仍可操作（不阻塞 UI），可手动"重新检测"。
- **AC-16**（边界态｜自动化）单源探测超时设为 3000ms，探测 5 个源时总耗时 ≤ 6s（并发上限 6，CHG-05 由 3 提升），且单源失败不影响其它源状态更新。

#### FR-47 线路质量分级与排序（P1）

- 在 `SourceHealth` 之外引入**面向用户的 6 档质量分级** `HealthTier`，让用户一眼看出"哪条快、哪条该删"：
  - `fast` 极速：`ok` 且延迟 ≤ 300ms；
  - `good` 快速：`ok` 且 301 ~ 800ms；
  - `fair` 一般：`ok` 且 801 ~ 2000ms；
  - `slow` 较慢：`ok` 且 > 2000ms；
  - `bad` 异常：非 `ok`（认证失败 / 超时 / 无法连接 / 配置有误），或 `ok` 但拿不到延迟；
  - `unknown` 未检测：尚未探测。
- 源卡片徽标展示档位文案（如"极速 128ms"）；`bad` 档保留具体故障文案（"认证失败""连接超时"等），因为"异常"本身对用户没有行动指引。
- 颜色：极速=紫、快速=绿、一般=黄、较慢=灰、异常=红、未检测=中性；不得仅靠颜色传达状态（必须有文字）。
- 源列表提供**排序模式切换**：`manual`（手动，默认，保持现有"内置源最后 + 手动顺序"）与 `tier`（按质量：档位 → 延迟 → 手动顺序 → 名称）。
- 排序偏好**仅本机记忆**（`localStorage` key `peanutmov.sourceSortMode`），不进备份、不跨设备。
- **批量测速提速**：全量探测并发上限 6，50 个源全量测速 < 25s；探测期间显示进度"检测中 12/49"（真实完成数 / 目标总数），不得只显示无限转圈。
- **不做**：不做线路质量排行榜、不上传/共享任何测速结果、不内置任何线路清单（FR-46）。

**AC**
- **AC-106**（正常态｜自动化）`healthTierOf()` 对 `(ok, 300)` → `fast`、`(ok, 301)` → `good`、`(ok, 800)` → `good`、`(ok, 801)` → `fair`、`(ok, 2000)` → `fair`、`(ok, 2001)` → `slow`；`('timeout', 500)` → `bad`、`(ok, null)` → `bad`、`('unknown', null)` → `unknown`；阈值取自 `HEALTH_TIER_THRESHOLDS`（`fastMaxMs=300`/`goodMaxMs=800`/`fairMaxMs=2000`），组件与测试中无 300/800/2000 字面量。

- **AC-108**（边界态｜自动化）`sortSources(sources, 'tier', latencyOf)` 输出满足：`fast` 全在 `good` 前、`good` 在 `fair` 前、`fair` 在 `slow` 前、`slow` 在 `bad` 前、`bad` 在 `unknown` 前；同档内按 `latencyMs` 升序，`latencyMs` 为 `null` 排在同档末尾；延迟与档位全相同时按 `sort` 升序、再按 `name`；`manual` 模式下输出与既有 `builtin → sort` 排序完全一致（含演示源恒最后）。切换模式后重启 App，选择仍为上次的 `tier`（`localStorage` key `peanutmov.sourceSortMode`）。

#### FR-48 失效线路自动跳过（P1）

- 用户在媒体库打开某个源、而该源**实际已失效**（`browse` 失败）时，若本机还存在其它 `health === 'ok'` 的启用源，则**自动切换到该源一次**并重新加载第 1 页，避免用户停在死胡同错误页。
- **不得静默切换**：切换时必须 Toast 说明「「源A」暂不可用，已自动切换到「源B」」，且媒体库当前源标识同步更新为 B（用户始终知道自己在看谁的内容）。
- **只切一次**：单次打开/刷新链路最多自动切换 1 次；同一 `(A → B)` 组合在一次 App 运行内最多尝试 1 次；切换后仍失败则不再切换，展示错误态并提示"可手动切换其他源"。
- 不触发自动切换的情形：源被禁用（`E_SOURCE_DISABLED`）、离线状态、用户主动取消、目标源无可用替代（无候选时不切换，按原错误提示）。
- 候选源按"内置源最后 → 质量档位 → 延迟 → 手动顺序"择优，与 FR-47 分级口径一致。

### 5.7 模块 G：投屏

> **版本号口径（v1.10）**：App 版本以仓库根 `package.json` 的 `version` 为**唯一来源**，设置页/关于页展示的 `APP_VERSION` 与 Android 安装包版本均派生自它，任何地方都不得单独维护版本号。
>
> - `versionName` = semver 核心 `x.y.z`（丢弃 `v` 前缀、`-prerelease`、`+build` 元数据；预发布信息由构建时间 `__BUILD_TIME__` 追溯）。
> - `versionCode` = `x * 10000 + y * 100 + z`，当前 `0.1.0` → **100**；因此 **minor / patch 必须 < 100**（满 100 先进位到高位），major ≤ 199（Android 上限 2100000000）。
> - 派生逻辑位于 `android/app/build.gradle` 的 `resolveVersion()`（REV-33 起在 `package.json` 缺失/损坏时回退字面值，回退值须与 `package.json` 同步，否则两条构建路径的 `versionCode` 会不一致）。
> - 已知限制：前端 `__APP_VERSION__` 由 `vite.config.ts` 从 `npm_package_version` 注入，**必须通过 `npm run build` 构建**才会带上版本；直接 `npx vite build` 会得到 `0.0.0`（前端侧修复项，不在后端范围）。
