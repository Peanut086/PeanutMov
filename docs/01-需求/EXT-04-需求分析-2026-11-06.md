## 1. 背景与目标

### 1.1 要解决的问题

现有下载能力（FR-30 ~ FR-35）已跑通"直链 + HLS 分片合并 + 断点续传 + 并发队列 + 前台服务通知"，但产出物与用户预期存在四项落差：

1. **产物是 MPEG-TS**：HLS 下载把所有分片顺序拼接为单一 `.ts`。中低端 WebView 与部分系统播放器不能直接播放 TS；用户把文件导出到相册/第三方播放器时经常"能播但拖不动/没缩略图/无法识别"。需要**转封装为 MP4**。
2. **批量与清晰度不可控**：详情页可选集下载（`EpisodePickerSheet`），但无单次批量上限、无队列容量保护、无批量失败重试；HLS 已在解析层支持多码流，下载链路却固定取最高码率（未把 `quality` 传到 `HlsDownloader`）。
3. **限速设置是死配置**：`settings.download.speedLimit` 只存在于类型与默认值中，JS 直链路径有粗糙实现、HLS 与原生 OkHttp 路径完全不受控，且没有设置界面，用户无法使用。
4. **字幕随片下载形同虚设**：`toDownloadInputs` 未传 `subtitleUrls`，`subtitlePaths` 从未写入；即便写入，`findLocalPlay` 返回 `subtitles: []`，离线播放无法使用已下载字幕。

### 1.2 可衡量目标（本次验收以 3.3 节 AC 为准）

| 目标 | 指标 | 现状基线 |
| --- | --- | --- |
| 产物兼容性 | Android 端 HLS 下载产物 100% 交付 `.mp4`（fMP4 直接交付）；ExoPlayer 与系统播放器均可播，时长误差 ≤1s | 交付 `.ts`，WebView 不可播 |
| 转封装开销 | 500MB 输入 ≤15s（中端机），内存峰值 ≤128MB，APK 增量 0 | 无此能力 |
| 批量可控 | 单次 ≤50 集；队列总上限 200；50 集创建 ≤2s 且主线程单帧阻塞 ≤50ms | 无上限，无批量重试 |
| 清晰度可选 | master playlist ≥2 变体时可选 720p/1080p/最高，续传不换流 | 固定最高码率 |
| 限速可用 | 四档限速对直链/HLS/原生三条路径统一生效，10s 稳态误差 ≤±30%（上限 ×1.15 / 下限 ×0.7） | 设置无 UI、HLS/原生不生效 |
| 字幕可用 | 完成态任务 30s 内字幕可离线挂载并切换；字幕失败不影响视频 | 未下载、未挂载 |
| 预检拦截 | DRM/格式/存储/网络策略在入队前拦截，单任务 P95 ≤3s | 仅 Web 端 HEAD 体积提示 |

## 3. 功能需求清单

> 编号沿用全团队 FR 序列：SRS 现行最大为 FR-59，本批新增 **FR-60 ~ FR-65**。
> 与 FR-30 ~ FR-35 的关系：**扩展而非重写**。FR-30（创建任务）、FR-31（队列并发）、FR-32（暂停/继续/取消/重试）、FR-33（落盘）、FR-34（离线播放）、FR-35（存储清理）的行为与 AC-69 ~ AC-80 全部保持有效；本批只补 6 个增量能力。

### FR-60 HLS → MP4 转封装（remux，非转码）P1

- **定义**：HLS 任务下载完成、产物为 MPEG-TS 时，在 Android 端将其**转封装**为标准 MP4（ISO BMFF），音视频编码保持不变（不解码、不重编码、不改变分辨率/码率/帧率）。
- **分支**：
  - 清单含 `#EXT-X-MAP`（fMP4）：分片本身就是 MP4 家族，直接以 `.mp4` 交付，**不执行**二次封装。
  - 直链 MP4/WebM 任务：不参与本能力（原样交付）。
  - Web 端：不执行转封装，保持既有 `.ts` 行为（见 5.3 Out of Scope）。
- **失败降级**：转封装失败、超时（120s）、磁盘不足、用户关闭开关时，**保留原 `.ts` 并标记任务为完成**，仅提示一次；不得因转封装失败把已完成任务置为 `failed`。
- **原子性**：输出写入 `{base}.mp4.part`，成功后原子 rename；失败/取消删除 `.mp4.part`，绝不留下半截 MP4。
- **顺序**：转封装在"任务完成态"落库之前完成，保证用户在下载页看到 `completed` 时文件已可播；转封装期间进度显示 100% + "转封装中"。
- **取消语义**：转封装阶段用户取消任务，等同于取消整个下载（中止转封装 → 删除 `.mp4.part` → 按既有取消流程删除 `.ts` 与记录）。

### FR-61 批量选集下载与队列治理 P1

- **定义**：详情页一次选择多集创建任务；本批补齐上限、分组与批量重试。
- **上限（可配置，默认值）**：单次提交 ≤ **50** 集（沿用 AC-70 口径）；队列（非终态任务）总上限 **200**（可配置 50/100/200/500）。
- **拒绝语义**：超出队列容量时按集号升序部分入队，其余返回 `rejected` 明细与"队列已满"提示；不得静默丢弃，不得整批失败。
- **分组**：同一批任务共享 `batchId`，下载页可按批展示"已完成 n/总数"，支持"重试本批失败项"与"删除本批已完成"。
- **重试策略**：批内失败任务重试沿用既有"自动重试 2 次 + 手动重试"（FR-32），批量重试不改变单任务 `retries` 语义。
- **UI**：选集面板显示"已选 n 集 / 队列剩余容量 m"，达到上限时禁用多余选中并给出原因。

### FR-62 下载清晰度选择 P1

- **定义**：创建下载任务前选择目标清晰度；HLS master playlist 有多个变体时按所选档位下载对应变体。
- **档位**：`max`（默认）/`1080p`/`720p`（沿用 `HlsDownloader.selectVariant` 的既有档位语义，不新增 4K 档）。
- **来源约束**：清晰度只能来自清单内的 `RESOLUTION`/`BANDWIDTH`/变体序号，**不得依赖最终 URL**（LocalProxy 不暴露落地地址，见 1.1 运行时约束）。
- **匹配规则**：
  1. 有 `RESOLUTION`：取高度 ≤ 档位上限中码率最高的变体；
  2. 无 `RESOLUTION`：按 `BANDWIDTH` 降序取第一个满足"档位上限对应码率"的变体，无匹配取最低码率；
  3. 续传：同一任务暂停/继续不重新选流（沿用已下载分片所属变体）。
- **直链任务**：不展示 HLS 清晰度选择器，仅展示线路自带 `quality` 文案（`PlayLine.quality`）。
- **默认值**：设置项 `download.hlsQuality`（默认 `max`）；单次选择覆盖默认值，不写回设置。

### FR-63 下载限速（全局带宽池）P2

- **定义**：对全部下载流量施加统一上限，四档：`low`=512KB/s、`medium`=2MB/s、`high`=5MB/s、`unlimited`=不限（沿用 `DOWNLOAD_SPEED_LIMITS`）。
- **口径**：**全局池**——所有并发任务（直链、HLS 分片、原生 OkHttp）共享同一额度，不是"每任务 × 档位"。
- **生效范围**：直链 JS 下载、HLS 分片下载（含并行 3/6/8）、Android 原生 OkHttp 下载（单连接与多 Range）。
- **动态切换**：运行中切换档位 ≤3s 生效，不暂停任务、不丢进度；重启后从设置恢复。
- **不参与限速**：m3u8/密钥/字幕/封面等元数据请求（体积小、影响体验）、转封装本地读写。
- **展示**：下载页展示"限速档位 + 当前合计速率"，并与 `DownloadSummary` 的单任务速度并列展示。

### FR-64 字幕随片下载与离线挂载（外挂 sidecar）P1

- **定义**：创建任务时把该集可用字幕（`PlaybackSource.subtitles`）随片下载到视频同目录同 basename；离线播放时作为可切换字幕轨挂载。
- **策略**：`download.attachSubtitles` = `preferred`（默认，仅首选语言 `player.subtitle.preferredLang`，未设置则取第一条）/ `all`（全部）/ `none`。
- **格式**：保留源格式（`vtt` 原样、`srt` 原样），文件名 `{videoBase}.{lang}.{ext}`；播放侧沿用既有 `SrtConverter` 转换能力。
- **失败隔离**：任一字幕失败只记 `logger.warn` 与任务详情"字幕：未下载"，不影响视频完成态，不进入失败重试。
- **挂载**：`findLocalPlay` 返回的 `PlaybackSource.subtitles` 必须包含已下载字幕（Android 用本地可播 URL，Web 用 Blob URL），`source='downloaded'`；字幕菜单可见、可切换，偏移设置（`player.subtitle.offsetSec`）继续生效。
- **明确不做**：硬字幕烧录（需转码）、MP4 内嵌软字幕轨（tx3g），理由见 5.3。

### FR-65 下载前预检（网络 / 存储 / DRM / 可达性 / 体积）P0

- **定义**：用户确认下载后、入队前，对每个待下载项做一次预检并汇总为"可下载 / 不可下载 + 原因 + 可选项"，由 UI 展示。
- **预检项**：
  1. **DRM/格式**：清单命中 `SAMPLE-AES`/`SESSION-KEY` 或 DASH/DRM 地址 → 直接拒绝（与 FIX-03 / AC-40 同一判定口径）；
  2. **可达性**：清单可拉取、可解析、至少 1 个分片探测成功（仅 HLS）；直链做 HEAD/首个区间探测；
  3. **体积**：HLS 用"变体码率 × 累计 EXTINF 时长"估算（含 ±20% 容差标记），直链用 `Content-Length`；
  4. **存储**：所需空间 = 估算体积 ×1.1 + 转封装临时副本（仅 TS→MP4 时按 1× 体积预留），与可用空间比较；
  5. **网络策略**：`download.wifiOnly=true` 且当前为蜂窝 → 标记 `wifi-only`，需用户显式确认才继续（可"本次仍下载"）。
- **失败处理**：
  - DRM/格式不支持 → **阻断**，不入队、不落库、不发起分片/密钥请求，重复触发仍被拒绝（不得因缓存变成可下载）；
  - 空间不足 → **阻断**，提示"需 X，可用 Y"；
  - 可达性失败 → **不阻断**（网络抖动不误判），提示"检测失败，已按可下载入队"；
  - `wifi-only` → **需确认**，用户确认后可入队。
- **性能**：单任务 P95 ≤3s；20 集批量 ≤10s（同一 master playlist 只拉取一次，结果复用 ≤60s）。
- **复用约束**：Android 上预检的全部网络请求必须走 LocalProxy（CapacitorHttp 拒 3xx）；相对引用按 302 落地地址解析。

## 4. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 转封装 ≥40MB/s（500MB ≤15s，中端机）；预检单任务 P95 ≤3s、20 集 ≤10s；50 集批量创建 ≤2s；限速模块 CPU 开销 ≤3%；转封装期间下载队列其它任务的吞吐下降 ≤20% |
| 并发 | 队列并发保持 1–3（FR-31 不变）；**转封装串行 1 个**（避免 CPU/IO 争抢）；预检并发 ≤4；限速为全局池，跨任务、跨下载路径共享同一额度 |
| 可靠性 | 转封装失败/超时/关闭开关 → 保留 `.ts` 且任务完成；预检网络失败 → 放行；`.mp4.part` → rename 原子提交；进程被杀 → 沿用既有僵尸任务处理（`downloading` 重启置 `failed`），`.mp4.part` 在下次启动清理 |
| 兼容性 | Android 10（API 29）及以上（`minSdkVersion=29`）；输出 MP4 需被 ExoPlayer 与系统播放器识别（H.264/AAC 为基线，HEVC 视平台支持）；Web 端不启用转封装，行为与现状一致 |

| 可维护性 | 不引入新的第三方运行时依赖（转封装使用平台能力）；新增能力不改变 `downloadQueue` 状态机语义；所有新增字段可选，老数据可读 |

## 5. 范围边界

### 5.1 本批包含

HLS→MP4 转封装、批量选集上限/分组/批量重试、下载清晰度选择、四档全局限速（含设置 UI）、字幕随片下载与离线挂载、下载前预检（DRM/可达性/体积/存储/网络策略）及其 UI。

### 5.2 与既有需求的边界

- FR-30 ~ FR-35 的接口语义、状态机、落盘路径规则、错误码文案**不变**；EXT-04 只做增量。
- FIX-03 的"克隆拒绝"先行判定仍然优先：预检只是把拒绝提前到入队前，不替代清单解析阶段的拒绝。
- FIX-04 的 302 语义不变：预检拉清单同样以落地地址为相对引用基线，且不得把落地地址透出给 UI。

### 5.3 明确不做（Out of Scope）

| 不做项 | 理由 |
| --- | --- |
| 视频转码（改变分辨率/码率/编码、压缩体积） | 与"remux 无损、速度快"目标冲突；CPU 与耗时不可接受，且需求未要求 |
| 硬字幕烧录（burn-in） | 必须重编码整条视频，500MB 级任务耗时数十秒至数分钟，违背 FR-60 性能目标 |
| MP4 内嵌软字幕轨（tx3g/`mp4s`） | 平台封装器不支持写文本轨；需自研字幕轨封装与时序换算，投入产出比低；外挂字幕已满足离线切换 |
| DRM/受保护内容的下载与解密 | 合规红线（Q-02 已确认 A：拒绝而非支持） |
| Web / iOS 端转封装 | 无平台封装能力；Web 端 `.ts` 行为保持不变（仅补字幕与限速） |
| 转封装断点续传 | 转封装是本地秒级操作，重跑成本低于持久化中间态 |
| 后台转封装（切后台继续） | 复用前台服务语义即可，不为转封装单独保活；任务在后台被暂停时按 FR-31 原有语义处理 |
| 自定义限速数值 / 时段限速 / 单任务独立限速 | 需求只要求四档与体验可用；`Q-11` 默认建议为全局池，不做单任务档 |
| 预检做"整片探测"（逐分片 HEAD） | 会触发防盗链/CDN 限流且耗时不可控；只做清单 + 单分片探测 |

## 6. 验收标准

> 格式：给定 / 当 / 则；每条标注溯源 FR。标注"自动化"的可写成单测或集成测试，"手工"的需真机/真网络验证。
> 编号沿用全团队 AC 序列：SRS 现行最大为 AC-141，本批为 **AC-142 ~ AC-154**。

**AC-142（正常态｜自动化+手工｜FR-60）** 给定 Android 环境、`download.remuxToMp4=true`、某 HLS 任务产物为 MPEG-TS（H.264+AAC）；
当 任务完成；
则 生成同名 `{base}.mp4`，任务 `format='mp4'`、`container='mp4'`、`remux.status='done'`，`.ts` 被删除；MP4 在 ExoPlayer 与系统播放器可播，时长与清单 `#EXTINF` 累加值误差 ≤1s；500MB 输入在中端机（骁龙 7 系）转封装 ≤15s。

**AC-143（错误态｜自动化｜FR-60）** 给定 转封装失败（不支持的编码/磁盘不足/超时 120s）、或 `download.remuxToMp4=false`、或 Web 端；
当 任务完成；
则 任务仍为 `completed` 且原 `.ts` 可播；`remux.status` 为 `failed` 或 `skipped` 并带 `reason`；`.mp4.part` 无残留；提示"已保留 TS 格式"至多 1 次；后续任务不被阻塞。

**AC-144（边界态｜自动化｜FR-61）** 给定 队列已有 195 个非终态任务、总上限 200、单次批量上限 50；
当 用户一次选择 50 集下载；
则 5 集入队成功、45 集返回 `rejected`（`E_INVALID_STATE` + "队列已满(200)"提示），已存在任务计入 `skipped`；整批不整失败；主线程最长单帧阻塞 ≤50ms。

**AC-145（正常态｜自动化｜FR-61）** 给定 一次批量下载 10 集（同一 `batchId`）中 3 集失败；
当 用户点击"重试本批失败项"；
则 3 集按集号升序重新入队，7 集已完成不受影响；下载页按批展示"已完成 7/10"，失败项可单独定位。

**AC-146（正常态｜自动化｜FR-62）** 给定 master playlist 含 1080p/720p/480p 三个变体（均带 `RESOLUTION`）、用户选择 720p；
当 创建并开始下载；
则 实际下载分片来自 height=720 的变体（日志与任务 `hlsQuality='720p'` 一致）；暂停后续传仍在同一变体；未选择时取 `download.hlsQuality` 默认值。

**AC-147（边界态｜自动化｜FR-62）** 给定 变体无 `RESOLUTION`、或档位无匹配、或任务为直链 MP4；
当 选择 720p 下载；
则 无 `RESOLUTION` 时按 `BANDWIDTH` 降序选第一个 ≤ 档位对应码率的变体、无匹配取最低码率，并写 `note`；直链任务 `hlsQuality=null` 且 UI 不展示清晰度选择器（仅展示线路 `quality` 文案）。

**AC-148（正常态｜手工｜FR-63）** 给定 限速 `low`(512KB/s)、并发 2、两任务同时下载；
当 稳定运行 10s 后统计；
则 两任务合计速率 ≤589824 B/s（×1.15）且 ≥358400 B/s（×0.7）；单任务无独立额度；切换 `unlimited` 后 3s 内合计速率超过该上限。

**AC-149（边界态｜自动化｜FR-63）** 给定 1 个直链任务 + 1 个 HLS 任务（分片并发 6）同时下载；
当 用户把限速从 `medium` 改为 `low`；
则 新档位 ≤3s 生效（切换后 5s 窗口内合计速率不超过 512KB/s×1.15），任务不暂停、`downloadedBytes` 单调递增、进度不丢；设置持久化，重启后仍为新档位。

**AC-150（正常态｜手工｜FR-64）** 给定 某集有 zh/en 两条远程字幕、`attachSubtitles='preferred'`、首选语言 zh；
当 视频下载完成；
则 30s 内写入 `{videoBase}.zh.vtt`（或源为 srt 时 `.srt`），任务 `subtitlePaths` 含该条；断网后从下载页播放，字幕菜单出现"中文（已下载）"并可切换，时间轴偏差 ≤1s，偏移设置仍生效。

**AC-151（错误态｜自动化｜FR-64）** 给定 字幕 URL 404 或 `attachSubtitles='none'`；
当 视频下载完成；
则 视频任务仍为 `completed`，`subtitlePaths` 为空或缺少该条；字幕菜单显示"该集无已下载字幕"且不抛异常；任务详情展示"字幕：未下载"。

**AC-152（错误态｜自动化｜FR-65）** 给定 清单含 `#EXT-X-KEY:METHOD=SAMPLE-AES`（或 `SESSION-KEY`）；
当 用户点击下载（预检阶段）；
则 `preflight` 返回 `drmProtected=true`、`canStart=false`、`blocked.code='E_DRM_PROTECTED'`；不创建 `downloads` 记录、不发起密钥/分片请求；重复触发仍被拒绝。

**AC-153（边界态｜自动化｜FR-65）** 给定 三种场景：(a) 预估 1.8GB、可用 1.2GB；(b) `wifiOnly=true` 且蜂窝网络；(c) WiFi + 空间充足；
当 触发下载预检；
则 (a) 阻断，`blocked.reason='storage'`、`code='E_STORAGE_QUOTA'`，不创建任何任务并提示所需/可用；(b) 标记 `reason='wifi-only'`、`code='E_NETWORK'`，用户确认后可继续入队；(c) 正常入队；单任务预检 P95 ≤3s，20 集批量预检 ≤10s 且同一 master 只拉取一次。

**AC-154（边界态｜自动化｜FR-60）** 给定 HLS 清单含 `#EXT-X-MAP`（fMP4 分片）；
当 下载完成；
则 直接以 `.mp4` 交付（`container='fmp4'`），**不执行**二次封装（无 MediaExtractor 调用、无临时副本）；文件可被 ExoPlayer 播放。

## 9. 边界场景自查（本能力特有）

| 场景 | 期望行为 | 覆盖 |
| --- | --- | --- |
| 队列为空 / 全部完成 | 预检、批量入口正常；不显示"重试本批" | AC-144/145 |
| 同一集重复下载 | 沿用 AC-70：返回 `existed`，不重复创建；预检仍可执行但不入队 | FR-61、AC-144 |
| 任务暂停/继续 | 转封装在完成前进行，暂停态不进入转封装；续传不换变体 | AC-146 |
| 转封装中杀进程 | 任务仍为 `downloading`（未提交完成），重启后被标记 `failed`（沿用 REV-24）；`.mp4.part` 于启动清理 | AC-143 |
| 转封装中取消 | 中止转封装、删 `.mp4.part` 与 `.ts`，按取消流程处理 | FR-60 |
| 磁盘写满 | 下载阶段 → `E_STORAGE_QUOTA`（既有）；预检阶段 → 入队前阻断；转封装阶段 → 回退 TS 并提示 | AC-143/153 |
| 限速切换/重启 | ≤3s 生效、进度不丢、重启恢复档位 | AC-149 |
| 网络切换（WiFi↔蜂窝） | 仅 `wifiOnly` 开启时影响"新任务预检"；已在下载的任务不因切网中断（沿用现状） | AC-153 |
| 302 签名地址 | 预检与下载均经 LocalProxy 跟随；相对引用以落地地址为基线；UI 不显示落地地址 | FR-65、技术方案 §8 |
| HLS 清单含 DRM | 预检阻断 + 解析阶段再次拒绝（双保险），不产出完成态文件 | AC-152、FIX-03 |
| fMP4 清单 | 不转封装，直接 `.mp4` | AC-154 |
| 字幕缺失/多语言/播放器无字幕 | 不阻塞视频；`preferred` 语言不存在时取第一条；`none` 时不下载、无入口报错 | AC-150/151 |
| 清晰度无匹配 / 续传换流 | 取最低码率并记 `note`；续传保持原变体 | AC-147 |
| 批量中部分集无播放地址 | 由 `toDownloadInputs` 既有 `failed` 分支返回；批量创建只处理有地址的集，并汇总提示 | FR-61 |
| 转封装期间下载其它任务 | 允许（转封装串行 1、下载并发不受影响），吞吐下降 ≤20% | NFR 性能 |
