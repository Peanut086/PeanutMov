## 1. 背景与目标

### 1.1 要解决的问题

FR-55 已交付"单 EPG 源 + 节目单页 + 频道收藏 + 失效沉底 + 数字换台"，但与真实 IPTV 使用场景仍有五项落差：

1. **只有一个 EPG 源，且硬绑定内置端点**：`epgService.programmes()` 的端点默认取 `EPG_DEFAULT_ENDPOINT`（`https://epg.112114.eu.org`），端点失效或该源缺频道时无任何替代路径，用户在直播页看到的是空节目单。用户手上有多个 EPG 端点（diyp 聚合、XMLTV 订阅、运营商 EPG），无法添加/切换。
2. **没有回看**：EPG 只看"现在播/接下来"，昨天的节目播完即不可达；而多数 IPTV 源实际提供时移地址，只是地址模板各源不同（查询参数式、路径式、UTC 秒偏移式、m3u `catchup-source` 自带模板），App 无任何配置入口。
3. **分组不可控**：分组完全来自 m3u `group-title` / txt `#genre#`，用户无法建立"央视/卫视/本地"这类符合自己习惯的分组；收藏只能置顶，不能组织。
4. **顺序不可控**：频道顺序即源文件顺序，用户无法把常看频道固定在前；`LiveView.visibleChannels` 只有"收藏置顶 → 失效沉底"的粗排序（`rank()`），同档内永远是源顺序。
5. **节目提醒缺失**：用户必须记时间点进直播页；App 未运行时更无任何触达手段（现有 LocalNotifications 仅服务定时备份与下载完成）。

### 1.2 外部依赖与数据来源（HIS 类外部系统口径）

| 依赖 | 数据来源 | 获取方式 | 未知/不确定部分 |
| --- | --- | --- | --- |
| 节目单（EPG） | **用户自行配置**的第三方 EPG 端点（diyp 风格 JSON 或 XMLTV 文本） | **按需实时 HTTP 拉取** + 本地 24h TTL 缓存；无后台定时任务（对齐 Q-05"启动 + 回前台按 TTL 判定"口径） | 各端点参数名、频道名/ID 命名规则不统一 → 见 Q-15、Q-21 |
| 回看（Catch-up） | 用户 IPTV 源自身提供的时移/回看地址 | 由用户配置的**地址模板** + 节目起止时间渲染生成，播放时直连源站 | 各源模板格式差异大、部分源不可用 → 见 Q-19、Q-20；本批不做能力枚举，只做模板 + 探测 |
| 频道列表 | 用户 IPTV 播放列表（m3u / TVBox txt） | 实时拉取 + 5min 内存缓存（既有 `liveService`） | m3u 的 `catchup-*` 属性格式存在方言 → 未识别即按"不支持回看"处理 |

> 授权边界：App **不内置**任何 EPG 端点、回看地址或频道清单（沿用 FR-46 红线）；全部由用户导入。EPG/回看内容的合法性由用户自行承担，App 只做"地址拼接 + 播放器拉起"，不代理、不缓存视频内容、不绕过鉴权。

### 1.3 可衡量目标（验收以第 6 节 AC 为准）

| 目标 | 指标 | 现状基线 |
| --- | --- | --- |
| 多源可用 | 可配置 ≤10 个 EPG 源、≤5 个同时启用；任一源失效时节目单仍可见（回落下一源） | 1 个硬编码端点 |
| 匹配确定性 | 频道↔节目单匹配按 4 级确定性规则，**零模糊相似度**；匹配结果可解释（显示命中的源与级别） | 只按频道名做 query 参数，命中即用，无匹配即空 |
| 合并性能 | 单频道合并 P95 ≤200ms（缓存命中 ≤20ms）；EPG 页首屏 ≤1.5s（缓存命中 ≤300ms） | 单源单请求（6s 超时），无并发控制 |
| 回看可用 | 覆盖 4 类主流回看地址格式；探测失败 6h 内不重复探测；窗口按源声明（默认 1 天，上限 7 天） | 无 |
| 分组/排序 | 自定义分组 ≤20 个；200 频道拖拽 ≥57fps、保存 ≤100ms；源刷新后配置保留 | 只能收藏置顶 |
| 提醒触达 | 后台/杀进程场景提前 N 分钟（0/5/10/15/30）触达，误差 ≤60s（已授权精确闹钟时）；权限被拒时降级为 App 内提醒 | 无 |

## 3. 功能需求清单

> 与 FR-55 的关系：**增量扩展**。FR-55 的行为（单源 EPG、24h 缓存、收藏、失效沉底、数字换台、AC-127/AC-128）全部保持有效；本批只补 6 项能力。

### FR-66 多 EPG 源管理（P1）

- **定义**：用户可维护多个 EPG 数据源，每个源独立配置名称、端点、协议与匹配方式，并参与优先级排序。
- **字段（需求级）**：名称（1~20 字符）、端点 URL（必须 `http(s)://`）、协议（`自动识别` / `diyp JSON` / `XMLTV`）、频道匹配方式（`自动` / `按频道名` / `按 XMLTV 频道 ID`）、优先级（1~N，唯一，数值小者优先）、启用开关。
- **内置默认源**：`EPG_DEFAULT_ENDPOINT` 预置为"内置默认源"，**可停用、不可删除**；用户新增源数量上限 **10**，同时启用上限 **5**。
- **添加校验**：保存前对端点做一次探测（单请求，超时 8s），必须解析出 ≥1 条节目才落库；重复端点拒绝；探测失败返回可读原因，不落库、不占用优先级槽位。
- **修改**：端点、协议、匹配方式任一变更 → 清空该源缓存并立即失效，下一次读取重新拉取。
- **删除**：允许删除用户源（内置源拒绝）；删除时清理该源缓存；引用该源的提醒**保留**但标记为"节目单源已移除"（不静默删除用户提醒）。
- **启停**：停用立即生效（不再参与合并、不再发起请求），已缓存数据不再返回。
- **失败降级**：任一源失败（网络/解析/超时）只影响该源，不影响其他源合并结果与直播播放。

### FR-67 多源节目单合并与频道匹配（P0）

- **定义**：给定频道与日期，按优先级依次向启用源请求节目单，使用第一个"匹配成功且当日有节目"的源作为结果来源；**不做节目级时间轴拼接**。
- **匹配规则（4 级确定性，命中即停）**：
  1. **L1 XMLTV 频道 ID**：频道的 `tvg-id` 与该源 XMLTV `<channel id>` / `<programme channel>` 精确相等（大小写敏感）；
  2. **L2 tvg-name**：频道的 `tvg-name` 与该源 XMLTV `<display-name>` 精确相等；
  3. **L3 归一化名称**：双方名称经"NFKC → 小写 → 去空白与分隔符（`-` `_` `·` `・` 全角空格）→ 去尾部画质后缀（高清/超清/标清/蓝光/FHD/HD/UHD/4K/8K）→ 去尾部"综合/频道"（仅当剩余长度 >2）"后**完全相等**；
  4. **L4 未命中**：该源视为"无此频道"，回落下一优先级源；全部未命中 → 返回空节目单（沿用既有空态文案"暂无节目单数据"）。
- **禁止**：不做编辑距离/包含匹配/拼音匹配等模糊算法；不因"看起来像"就把 A 频道节目显示给 B 频道。
- **合并规则**：同一源内按开始时间升序；`(startAt, title)` 完全相同的条目去重保留第一条；同一频道多级命中时以最高级别源为准（不混合两个源的节目）。
- **时间**：XMLTV `start/stop` 的时区偏移（如 `+0800`）必须参与换算为绝对时间（epoch ms），界面按**设备当前时区**展示；跨天节目（如 23:30–00:30）归属**开始日**；日期切换以设备本地 0 点为界。
- **缓存**：按 `(源, 频道, 日期)` 独立缓存，TTL 24h（沿用 `EPG_CACHE_TTL_MS`）；失败**不缓存**（避免 6s 超时的空结果被钉住 24h）。
- **展示约束**：节目单页需标明"节目单来源：<源名>"与命中级别（L1/L2/L3）；用户可据此发现配错（可解释性要求）。
- **一致性**：直播页"正在播/接下来"与节目单页"正在播"必须来自同一次合并结果口径（同一 `channelKey` + 同一日期 + 同一 `now` 判定规则）。

### FR-68 回看（P0）

- **定义**：对**已结束**且处于回看窗口内的节目，提供回看入口；地址由"模板 + 节目时间"渲染生成，直接交给播放器。
- **窗口**：取源级配置的 `回看天数`（1~7，默认 1）与频道级 m3u 声明（`catchup-days`）中**较大且不超过 7** 的值；条件为：`节目已结束` 且 `now - 节目开始时间 ≤ 回看天数 × 24h`。
- **模板占位符（固定 12 个 token / 9 组语义，不接受表达式与条件）**：`{base}`（源地址基址，取该频道 URL 去掉最后一段文件名后的目录，去除结尾 `/`）、`{channel}`（频道名）、`{tvgId}`、`{channelId}`（有 `tvg-id` 用其值，否则用归一化频道名）、`{date}`（`yyyyMMdd`，设备本地时区）、`{dateDash}`（`yyyy-MM-dd`）、`{start}` / `{end}`（`yyyyMMddHHmmss`，本地时区）、`{utc}` / `{utcend}`（`yyyyMMddHHmmss`，UTC）、`{startSec}` / `{durationSec}`（相对节目起点的偏移秒 / 节目时长秒）。
  > 分组口径：`{start}`+`{end}`、`{utc}`+`{utcend}`、`{startSec}`+`{durationSec}` 各算 1 组语义，加 `{base}`/`{channel}`/`{tvgId}`/`{channelId}`/`{date}`/`{dateDash}` 共 **9 组语义、12 个 token**。
- **编码口径**：`{channel}` 与 `{channelId}` 按 URL 组件编码（含中文/空格时必须编码）；其余占位符只产出 ASCII 数字与分隔符（`-` `.` `/` `:`）；渲染结果必须是可解析的 `http(s)` URL，否则拒绝。
- **配置方式**：源级模板（直播源设置内填写）+ 频道级覆盖（m3u `catchup-source` 自带模板优先）；保存模板时校验占位符白名单，出现未知占位符拒绝保存。
- **能力探测**：首次点击回看时探测一次（`HEAD`，失败再 `GET Range: bytes=0-1023`，超时 3s，不重试）；成功 → 标记可回看并缓存 6h；失败 → 入口置灰并给出原因（"该源可能不支持回看"），6h 内不再重复探测；**不跨源回退**（回看能力属于该直播源，不得换到别的源拼地址）。
- **播放**：回看进入独立播放页，支持暂停/继续、进度拖动、全屏；起播超时 5s 沿用直播口径给出错误与"返回节目单/重试"动作。
- **明确不做（本 FR 内）**：DRM/加密分片处理、鉴权头注入（cookie/token 由源 URL 自带或用户自行配置在模板中的 query 片段）、录制与时移缓存、跨天自动续播。

### FR-69 频道自定义分组（P1）

- **定义**：用户可创建自定义分组并把频道移入；自定义分组与源分组（m3u `group-title` / txt `#genre#`）并存展示。
- **上限与校验**：自定义分组 ≤**20** 个；名称 1~10 字符；同名拒绝；保留名"全部""未分组"不可用；空名拒绝。
- **归属**：一个频道最多属于 **1 个**自定义分组（多归属会造成"同一频道出现两次"，本批不允许）；未分配频道仍显示在其源分组内。
- **展示顺序**：`全部`（固定第一） → 自定义分组（按用户排序） → 源分组（按源内出现顺序）。
- **分组操作**：新建、重命名、删除、排序；删除分组后其内频道回落源分组，不丢失、不回退排序配置以外的任何数据。
- **空分组**：显示空态 + "从源分组添加频道"入口。
- **持久化作用域**：按**直播源**隔离（不同直播源的频道集合不同）；刷新/重启后保留；源内频道消失时归属记录保留但不展示，可在分组管理内一键清理。
- **一致性**：分组只影响展示组织，不改变 `LiveGroup` 解析结果与源文件内容。

### FR-70 频道自定义排序（P1）

- **定义**：用户可对频道顺序做手动排序并持久化，支持一键恢复源顺序。
- **入口与交互**：长按频道 500ms 或顶部"排序"按钮进入排序模式；拖拽调整；松手后立即保存（无"保存"按钮的隐式保存需一次 Toast 确认）；排序模式内点击频道不换台。
- **作用域**：当前所选分组（"全部"下排序即整源顺序；自定义分组/源分组下排序仅该组）。跨组不联动。
- **与既有排序的优先级**：`失效沉底` > `收藏置顶` > `自定义排序` > `源顺序`。即自定义排序只在同 `rank` 内生效，既有 `rank()`（`LiveView.vue:213`）语义不变。
- **新频道**：源新增频道追加到自定义顺序**末尾**，不插入已有序列中间，不打乱用户既有顺序。
- **失配处理**：频道改名/删除导致顺序项找不到频道 → 顺序项保留但不渲染，分组管理页提供"清理失效排序项（n）"。
- **性能与规模**：200 频道拖拽期间掉帧 ≤5%（60Hz 基准 ≥57fps）、单帧 ≤16ms；保存 ≤100ms；**>300 频道**进入排序模式时提示"当前分组频道过多，请先按分组筛选"，不进入拖拽。

### FR-71 节目提醒（P1）

- **定义**：对**未来**节目设置提醒，在开播前 N 分钟通过系统通知或应用内提示告知用户。
- **提前量**：`0 / 5 / 10 / 15 / 30` 分钟，默认 **5**；单条提醒可修改，不提供全局默认值设置项。
- **唯一性**：同一 `(直播源, channelKey, 节目开始时间)` 唯一；重复设置视为更新（提前量变化），不新增第二条。
- **上限**：待触发提醒 ≤**50** 条；超出拒绝并提示需先清理。
- **触发**：
  - App 在前台 → 应用内提示（Toast/横幅），文案含频道名、节目名、开播时间；
  - App 在后台或未运行 → Android 系统通知；点击通知进入直播页并定位该频道（不自动播放，避免后台流量与误触）。
- **权限**：`POST_NOTIFICATIONS` 被拒时，提醒**仍保存成功**，列表与详情标注"仅 App 内提醒"，并提供"去开启通知"入口；不得静默丢弃提醒。
- **时间精度**：已授权精确闹钟时误差 ≤60s；未授权（或系统不允许精确闹钟）时按系统近似闹钟触发，误差不承诺，UI 标注"可能延迟"。
- **校准**：App 启动与回前台时按 `notifyAt` 重算：已过期未触发 → 标记"已错过"；设备时间/时区变更 → 按绝对时间重新排期；已触发 → 标记"已提醒"。
- **失效**：节目开始后 10 分钟仍未触发 → 标记"已错过"并取消原生通知。
- **不做**：录制、自动切台/自动播放、每周重复提醒、自定义铃声与通知渠道。

## 4. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 单频道合并 P95 ≤200ms、缓存命中 ≤20ms；EPG 页首屏 ≤1.5s（缓存命中 ≤300ms）；300 频道列表首屏渲染 ≤300ms；200 频道拖拽 ≥57fps、保存 ≤100ms；分组切换 ≤100ms；提醒 reconcile ≤300ms（50 条上限内） |
| 并发 | 多 EPG 源并行拉取 ≤**3**；同 `(源, 频道, 日期)` 的并发请求合并为 1 个（in-flight 去重）；回看探测并发 ≤2；预取仅限"收藏频道 + 当前可见分组"，总量 ≤**30** 频道/次 |

| 兼容性 | 数据格式：diyp JSON（数组 / `{epg|list|data}` 包裹两种）与 XMLTV 1.0（`<tv>` `<channel id>` `<display-name>` `<programme start stop channel>` `<title>` `<desc>`，含单引号属性与 CDATA）；回看 4 类地址样本（查询参数式、路径式、UTC 秒偏移式、`catchup-source` 内置模板）；Android 10（API 29）及以上；Web 端功能可用但通知降级为页内提示 |

## 5. 范围边界

### 5.1 本批包含

多 EPG 源（增删改启停 + 优先级 + 探测）、多源合并与 4 级确定性频道匹配、时区正确的节目时间、回看（模板 + 探测 + 播放页）、自定义分组、自定义排序（拖拽）、节目提醒（系统通知 + 应用内 + 权限降级）。

### 5.2 与既有需求的边界

- FR-55 的 EPG 单源行为与 AC-127/AC-128 **不变**：未配置任何外部源时，默认端点仍按现有行为工作，`EpgView` 三天切换、自动滚动、`LiveView` "正在播/接下来"必须与 v1.9 一致（AC-170 作为回归门禁）。
- `parseEpgResponse` 的既有 3 个单测用例（`tests/unit/epgParser.spec.ts`）**不得改断言**；新增能力通过新增函数与可选字段实现。
- `liveService.channelsOf` 的 5min 缓存、失败回落上一次缓存、`channelCount` 回写语义不变。
- 下载/播放/历史/收藏链路零改动。

### 5.3 明确不做（Out of Scope）

| 不做项 | 理由 |
| --- | --- |
| 节目级跨源时间轴拼接（A 源 20:00–20:30 + B 源 20:30–21:00 拼成一条） | 时间边界与广告插播会导致错位，且无法判定正确性；需求只要"有节目单" |
| 模糊/拼音/包含匹配自动绑定频道 | 错配比"无节目单"危害大（显示错误节目名 + 回看拼错地址）；Q-15 默认 A |
| 自动按关键词/国家规则分组、跨源同名频道合并 | 需求只要求用户自定义；自动分组需词表维护且易误伤 |
| 录像 / 时移缓存 / 本地录制回看 | 存储与合规成本高，超出"拼接地址并播放"范围 |
| 回看写入观看历史与断点续播 | 直播口径（`LiveView.vue` 头注）明确不写历史；引入需改历史模型，另立需求 |
| DRM/加密流回看、鉴权头注入、cookie 自动携带 | 与 Q-02 合规红线一致；本批只做地址拼接 |
| 分组/排序/提醒纳入 JSON 备份与云同步 | 备份 schema 属 EXT-05，跨设备同步属 EXT-09；本批只做本地持久化（Q-17 默认 A） |
| 全局提醒默认值设置项、每周重复提醒、自定义通知渠道 | 需求只要求单次提醒 + 提前 N 分钟 |
| EPG 周视图/网格视图、直播页内回看入口 | 需求只要求节目单页回看；周视图无用户诉求 |
| EPG 源自动健康切换（按失败率改优先级） | 优先级由用户显式控制；自动调整会让"为什么换了节目单"不可解释 |
| iOS 端适配 | 项目运行平台为 Android + Web（SRS §1.4） |

## 6. 验收标准

> 格式：给定 / 当 / 则；每条标注类型（正常态/边界态/错误态/性能/并发/回归）、验证方式（自动化/手工）与溯源 FR。

**AC-155（正常态｜自动化｜FR-66）** 给定 全新安装（无用户 EPG 源）；
当 依次添加 (a) diyp 端点 `https://a.example.com/epg`、(b) XMLTV 端点 `https://b.example.com/x.xml`，并把 (b) 拖到首位（整表重排优先级）；
则 列表含"内置默认源 + 2 个用户源"，优先级自 1 起连续重排为 `(b)=1 → 内置=2 → (a)=3` 并按此顺序展示；重启后启用状态与优先级不变；同一 URL 再次添加返回 `E_INVALID_INPUT`；第 11 个用户源、第 6 个启用源被拒绝。

**AC-156（错误态｜自动化｜FR-66）** 给定 端点返回 HTML 或空节目；
当 添加该源；
则 返回 `E_PARSE`（可读原因），不落库、不占优先级、列表数量不变；已存在源把端点改成不可达地址后保存 → `E_TIMEOUT`/`E_NETWORK`，原配置保持不变；删除内置源返回 `E_INVALID_STATE`。

**AC-157（正常态｜自动化｜FR-67）** 给定 频道 `{name:'CCTV-1 综合', tvgId:'cctv1', tvgName:'CCTV1'}`，源 A（优先级 1）的 XMLTV 含 `channel id="cctv1"` 与当日 3 条节目，源 B（优先级 2）含同名但无该 ID；
当 请求该频道今日节目单；
则 结果全部来自源 A，`matchedSource.matchLevel=1`；移除 A 的 `channel id` 后重试 → 命中 L2；再移除 `display-name` → 命中 L3（`CCTV-1 综合` 与 `CCTV1` 归一化后相等）；`EpgView` 显示"节目单来源：A（L1）"。

**AC-158（边界态｜自动化｜FR-67）** 给定 源 A 无该频道、源 B 有该频道但今日无节目、源 C 有 2 条节目且含 2 条 `(startAt,title)` 完全相同的重复条目；
当 合并请求；
则 结果为源 C 的节目（重复项去重后 1 条），`matchLevel=3`；三源全空 → 返回空数组且不抛错；同一请求 1s 内重复触发只发 1 次网络请求（in-flight 去重）；失败结果不写缓存（同一 key 下次仍会请求）。

**AC-159（正常态｜自动化｜FR-67）** 给定 XMLTV 节目 `start="20261025200000 +0800"`；
当 设备时区为 `Asia/Shanghai` 渲染；
则 显示 `20:00`、`startAt` 等于对应 UTC epoch；设备时区为 `UTC` 时显示 `12:00`；`start="20261025233000 +0000" stop="20261026003000 +0000"` 在 `Asia/Shanghai` 下归属日期为 **2026-10-26**（开始日按设备时区换算），且列表中排在 10-26 的第 1 条。

**AC-160（性能｜自动化+手工｜FR-67）** 给定 100 个频道 × 2 个启用源（各有完整当日节目），首次全量合并后再次请求；
当 逐频道请求今日节目单；
则 缓存命中时单频道合并 P95 ≤20ms；缓存未命中 P95 ≤200ms 且同时 in-flight 网络请求 ≤3；节目单页首屏 ≤1.5s（缓存命中 ≤300ms）；预取频道数 ≤30。

**AC-161（正常态｜手工｜FR-68）** 给定 直播源配置模板 `https://cdn.example.com/{channelId}/{date}/{start}-{end}.m3u8`、回看天数 2；
当 对昨日 20:00–21:00 的节目点击"回看"；
则 生成 URL `https://cdn.example.com/cctv1/20261105/20261105200000-20261105210000.m3u8`（与手工拼接逐字一致），播放成功，可暂停、拖动到 10 分钟处、全屏；起播失败时展示可读原因与"返回节目单/重试"两个动作。

**AC-162（边界态｜自动化｜FR-68）** 给定 探测返回 404 / 超时 3s / 403；
当 用户点击回看；
则 入口置灰并提示"该源可能不支持回看"（403 额外提示"可能需要鉴权，请在模板中补齐地址"）；能力缓存 6h，期间再次点击不再发起网络请求；节目未结束或 `now - startAt > 回看天数×24h` → 不展示回看入口；未配置模板且频道无 `catchup-source` → 不展示回看入口。

**AC-163（兼容性｜自动化+手工｜FR-68）** 给定 4 类回看地址样本：(a) 查询参数式 `{base}/{channelId}.m3u8?start={start}&end={end}`；(b) 路径式 `{base}/timeshift/{channelId}/{dateDash}/{start}/index.m3u8`；(c) UTC 秒偏移式 `{base}/stream/{channelId}?begin={startSec}&dur={durationSec}`；(d) m3u `catchup-source="{base}/catchup/{tvgId}/{utc}-{utcend}.m3u8"`；
当 渲染并播放；
则 输出无残留 `{...}` 占位符、中文频道名与空格均正确 URL 编码、`{startSec}`/`{durationSec}` 与节目时长一致（误差 0）；模板含未知占位符 `{foo}` 时保存被拒绝并提示合法占位符清单。

**AC-164（正常态｜自动化｜FR-69）** 给定 某直播源 60 个频道；

**AC-165（边界态｜自动化｜FR-69）** 给定 已有 20 个分组；

## 9. 边界场景自查（本能力特有）

| 场景 | 期望行为 | 覆盖 |
| --- | --- | --- |
| 无任何用户 EPG 源 | 仅内置默认源生效，行为与 v1.9 一致 | AC-170 |
| 全部 EPG 源停用 | 节目单空态 + 提示"未启用 EPG 源，去添加"；直播播放不受影响 | AC-156、FR-66 |
| 节目单为空 / 该频道无 EPG | 空态文案沿用"暂无节目单数据"，不报错、不反复请求 | AC-158 |
| 重复节目条目 | `(startAt,title)` 相同去重保留 1 条 | AC-158 |
| 重复设置提醒 | 覆盖更新（1 条），原生排期只保留 1 条 | AC-169 |
| 已结束节目（类似"过号"） | 超过回看窗口不提供入口；提醒不再可设 | AC-162、AC-169 |
| 中途新增频道 / 新导入直播源 | 新频道追加顺序末尾；分组/排序配置不被重置 | AC-167 |
| 设备离线 | 命中缓存可看，过期缓存标注"可能过期"；新建 EPG 源探测失败给出网络原因 | AC-156、NFR 可靠性 |
| 跨天重置（00:00） | 日期以设备本地 0 点切换；23:30–00:30 节目归属开始日；"正在播"不因跨天丢节目 | AC-159 |
| 直播页与节目单页显示不一致 | 同一 `channelKey`＋同一日期＋同一 `now` 口径，来自同一合并结果 | FR-67、AC-157 |
| 时区/设备时间被修改 | 回前台 reconcile 重算提醒与"正在播"；缓存 key 含日期，跨时区不串日期 | AC-159、AC-169 |
| EPG 源删除 | 提醒保留并标记"节目单源已移除"；缓存清理；其他源不受影响 | FR-66 |
| 回看探测失败 | 6h 内不再探测；置灰 + 原因；不跨源回退 | AC-162 |
| 通知权限被拒 / 精确闹钟不可用 | 提醒保存 + 标注降级；不静默失败 | AC-169 |
| 设备重启（未打开 App） | 重启后到首次启动前不承诺触发；启动 reconcile 将过期项标记"已错过" | FR-71、技术方案 §9 R-04 |
| 300+ 频道 | 排序模式给规模提示，仅可分组内排序；列表滚动沿用既有渲染策略 | AC-167 |
| 频道改名/删除 | 顺序项保留不渲染，可一键清理；分组归属保留 | AC-167 |
