## 1. T1 / CHG-25：ExoPlayer 播放路由接线

### 1.1 现状与差距（已核实）

**已就绪**：
- 插件 `android/.../ExoPlayerPlugin.java`：isSupported / prepare / setRect / play / pause / seek / setRate / progress / release + `exostate` 事件（ready/error），surface 模式（WebView 之上叠 PlayerView）。
- 前端代理 `src/native/exoPlayerPlugin.ts`：接口定义、`isExoPlayerAvailable()`、`exoHeadersOf()`。
- 设置开关 `experimentalNativePlayer`（`settingsService.ts:60` 默认 false；SettingsView 已渲染开关，真机验收 PASS）。

**缺口**（本任务补齐）：
1. `PlayerController.attachEngine()`（`src/player/PlayerController.ts:185`）只会在 HlsEngine/VideoEngine 二选一，原生引擎零接线。
2. Java 侧缺事件：`STATE_ENDED`（自动下一集依赖 `handleEnded`）、`STATE_BUFFERING`、音量 `setVolume`、丢帧计数（AC-125 的量化指标）。
3. Java `prepare` 每次直接 `new ExoPlayer.Builder(...)`，**未释放旧实例**（切集即泄漏，`ExoPlayerPlugin.java:91`）。
4. rect 只在 prepare 时传一次，全屏/旋屏/窗口变化后画面错位。
5. 原生 overlay 盖在 WebView 之上：弹幕 canvas、外挂字幕 DOM、清晰度面板都在 WebView 内，会被盖住/挡触摸。

### 1.2 设计

**引擎层**（新增 `src/player/NativeEngine.ts`，实现 `PlayableEngine`（`src/player/types.ts:82`））：
- `attach(container)`：记录容器，建占位 div，挂 `ResizeObserver`（全屏/旋屏引起容器尺寸变化即重算 rect）。
- `load(source, headers)`：`getBoundingClientRect()` → `Exo.prepare({url, headers: exoHeadersOf(headers), rect})`；订阅 `exostate`：`ready` → 回调 onLoadedMetadata(duration)；`ended` → onEnded；`error` → onError（映射 AppError）；启动 500ms 轮询 `progress()` 驱动 onTimeUpdate（buffered 用 position 近似）。
- `getQualities()` 恒 `[]`（清晰度面板天然隐藏）；`setQuality` no-op；`capabilities = { kind:'hls', supportsHeaders:true }`。
- `destroy()`：解绑事件 + 清轮询/Observer + `Exo.release()`。

**路由层**（`PlayerController.attachEngine`）：
- `PlayerLoadOptions` 增 `preferNativeEngine?: boolean`——由 PlayerView 读 `settings.settings.experimentalNativePlayer` 注入。**保持 PlayerController「不调用任何 Service」的分层约束**（`PlayerController.ts:10`）。
- 选择顺序：`preferNativeEngine && await isExoPlayerAvailable()` → 试 NativeEngine；**prepare 失败或 ready 前出错 → 静默回退 WebView 分支 + toast「原生引擎不可用，已切回内置引擎」**（不算播放失败，不触发 PlayerView 换线 failover）。NativeEngine 分支同样套 `withMetadataTimeout`。
- 网络重试路径（`handleEngineError` 的 E_NETWORK 重试重新 attachEngine）天然兼容，无需改。

**z-order 与交互互斥**（PoC 边界内处理，见 §8 决策点①）：
- 原生模式下禁用弹幕 HUD 按钮（toast「实验引擎暂不支持弹幕」）；外挂字幕选择面板同理隐藏。
- 手势快进/双击/HUD 控制条保留：验证 overlay 触摸穿透（`setUseController(false)` 的 PlayerView 理论上不消费事件；若被挡，Java 侧 overlay `setClickable(false)` + 空白 FrameLayout 不消费，触摸回落 WebView）。

**Java 增量**（`ExoPlayerPlugin.java`）：
1. `prepare` 首行：旧 player 非空先 `release()`。
2. Listener 补 `STATE_ENDED` → `exostate {state:'ended'}`、`STATE_BUFFERING` → `{state:'buffering'}`。
3. 新增 `setVolume(volume: 0..100)` 方法。
4. 新增丢帧计数：`AnalyticsListener.onDroppedVideoFrames` 累计，`progress()` 返回值带上 `droppedFrames`（AC-125 采样用）。
5. 移除/降级 `ensureOverlay` 里的调试 Toast（`ExoPlayerPlugin.java:226`）。

### 1.4 验收标准

- **AC-125（转正门槛）**：公共 4K HLS 测试流（如 Mux/Apple bipbop 4K 变体）播放 ≥3 分钟，`droppedFrames` 增长率可忽略（对比 WebView 引擎同流软解掉帧显著）；进度/倍速/seek/自动下一集可用。
- 开关关→开→关往返，播放链路无残留（切回后 overlay 隐藏、无声音残留）。
- 原生 prepare 失败（构造 404 URL）自动回退 WebView 且 toast 提示，不计入换线 failover。
- 退出播放页 → `release()`，二次进入无泄漏（Java 引用可复用）。

## 2. T2：AC-123 换线换源链确定性验证（CHG-21 验收补课）

**现状**：`PlayerView.vue:562-658` 已实现「起播窗口内失败 → ①自动换线（一次）→ ②同名同年换源（一次，`pickPlayCandidates`）→ 错误面板」，但仅有单测，真机从未确定性触发过（v1.7 验收报告 §3）。

**做法**：
1. `scripts/mock-subscription-server.cjs` 增 fixtures：
   - 坏线路源：线路 A play 地址 404 / 挂起，线路 B 正常（触发①）。
   - 同名同年双源：源 1 全线路坏，源 2 可播（触发②换源链）。
   - 复用现有 `/bulk`、`/live.m3u` 模式，路由命名如 `/badline.json`、`/twin-a.json`、`/twin-b.json`。
2. `scripts/mumu-driver.cjs` 场景：导入 fixture 源 → 播放坏线路剧集 → 断言 toast「自动切换到其它线路…」→ 播放成功；再播全坏源 → 断言「正在尝试其它来源…」→ 落到源 2 成功；最后构造两者全坏 → 断言错误面板出现且「重试/切换线路」可用。
3. 顺带验证：起播成功后 failover 标志复位（`PlayerView.vue:416-418`）、`preloadNext`（剩 90s 触发预载、切集 <1s）。

**退出标准**：三条链路（换线成功/换源成功/兜底面板）各有一条真机证据截图/日志，写入 `docs/05-测试报告/`。

## 3. T3 / CHG-26：错误态可操作化（推广 CHG-15 模式）

**原则**：复用搜索空态（`SearchView.vue:52-58,173-176`）的「给原因 + 动作按钮」模式，不发明新交互。

### 3.1 播放失败面板（`src/components/player/PlayerErrorPanel.vue`）

现有：重试/切换线路/返回/复制错误。增补：
- **「换源重播」**：手动触发 `findAlternateSource()`（现仅自动 failover 会调）——自动链只各试一次，用户手动应可再推一把。
- **「源体检」入口**：错误码为 `E_SOURCE_UNAVAILABLE`/`E_HTTP_5xx` 类时显示，跳转 `/settings/sources` 源管理页（那里已有一键禁用失效源）。
- 手动动作触发前复位 `failoverLineTried/failoverSourceTried`，让自动链重新可用。

### 3.2 导入失败（`src/views/ImportSubscriptionView.vue`）

- **「复制诊断」**：复制 URL + 错误码 + 归一化建议（拼写提示已有数据，`urlNormalize` hints）。

## 4. T4 / CHG-27：catvod JS 模块规则支持

### 4.1 现状

- `DrpyRuntime.java:93-97`：检测到 `^\s*import\s` 即抛「catvod JS 模块规则（assets:// 导入），暂不支持」——生态里相当一部分源（如夜猫秒播）因此不可用。
- 已有可复用资产：QuickJS 引擎（whl wrapper 3.2.3）、`assets/drpy_host.js` 宿主（req/pdfa/pdfh/pd/local）、DrpyPlugin 线程池+看门狗、SpiderAdapter 对 `ext.kind==='js'` 的路由。
- 注意：`DrpyRuntime` 已 import `com.github.catvod.crawler.SpiderApi`（Java jar 爬虫路径），本任务处理的是 **JS 模块规则**，与 Java Spider 无关。

### 4.2 阶段

**A. Spike（0.5 天）**——先盘点再动手：
- 从用户订阅池收集 3~5 个真实 catvod 模块规则，盘点：import 图（相对路径/完整 URL/assets://）、依赖的宿主 API 面（与 drpy_host 重合度）、导出形态。
- **产出决策**：路线①「import 预解析改写」——加载期把 import 目标拉回文本、按拓扑序 evaluate、以全局命名空间注入（完全复用现有同步 evaluate，风险低，推荐默认）；路线②「QuickJS ES Module loader」（whl wrapper 的 compileModule/ModuleLoader，若支持且样本普遍用 ESM 语义则更干净）。Spike 后二选一。

**B. 实现（1.5 天）**：
- 模块加载器（Java 侧，DrpyRuntime 内或新类 `CatvodModuleLoader`）：import 解析 → HTTP/缓存取模块文本（`filesDir/catvod-modules/{md5}` 复用 drpy 规则缓存模式，8MB 上限）→ 拓扑序注入。
- 判定点改造：`DrpyRuntime.java:93` 的 import 检测从「抛错」改为「走模块加载器」。
- 宿主 API 补齐：按 Spike 盘点结果补 `drpy_host.js` 缺口（预计 cat.* 命名空间部分函数）。
- 前端：导入/告警文案更新（不再提示不支持）。

**C. 真机验证（1 天）**：≥2 个真实 catvod 源 home/category/search/player 四方法全通；不支持的模块（如依赖 native bridge 的）给出明确报错；加载时长记录（对照 drpy 725ms 基线）。

### 4.3 退出标准

- ≥2 个真实 catvod 源四方法全通（真机）。
- 明确不支持的能力清单落文档（哪些模块 API 不做，报错文案可读）。
- 若 Spike 结论是工程量远超预期（如模块图过深/native 依赖过重），允许降级为「catvod 检测 + 更精准的引导文案」，但需在验收报告说明。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 原生 overlay 挡住 WebView 触摸（手势/HUD 失效） | 先验证穿透；不行则 overlay `setClickable(false)`；仍不行 PoC 边界内声明「原生模式仅按钮控制」 |
| MuMu 模拟器帧率数据不代表真机 | AC-125 结论只对 MuMu 负责，真机 4K 留待用户设备复验；转正决策分两级 |

| 换镜像重试变体顺序不当引发限流 | 沿用 importService 现有变体顺序与超时，不新增并发 |

## 8. 决策点（需拍板）

1. **原生模式 vs 弹幕/字幕互斥**：推荐 PoC 期互斥（禁用 + toast），原生绘制弹幕属转正后另立 CHG。
2. **catvod 实现路线**：Spike 后定（默认倾向路线① import 改写）。
3. **v1.7.1 发版节奏**：D2 末是否真的打 tag 发一版，还是与 v1.8 合并一次发（推荐合并，v1.7.1 仅作为里程碑名）。

## 9. 明确不做

- Link3.cc 类 JS 渲染短链的无头浏览嗅探（重、收益低，维持明确报错）。
- 弹幕发送、原生层弹幕渲染。
- 投屏增强、DLNA。
- MuMu 模拟器 CapacitorHttp 域名屏蔽问题（环境特性，真机不受影响）。
