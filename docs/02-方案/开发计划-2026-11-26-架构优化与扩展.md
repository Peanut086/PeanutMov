| 项目 | 内容 |
| --- | --- |

## 1. 现状判断

1. **基础工程质量明显高于同规模个人项目。**
   - src 约 13 万行（views 30,290 / components 26,749 / services 33,511 / sources 10,044 / player 8,548），测试 346 个文件。
   - 全仓 `any` 仅 7 处、`@ts-ignore` 0 处、TODO 0 处。
   - views / stores / components 中没有任何直接 `fetch(` 或 `openDB(`。
   - HTTP 层统一做超时、取消、有限重试与错误码映射（`src/sources/base/httpClient.ts:36`）。
   - IndexedDB 17 个 store、v7 只增式迁移（`src/db/migrations.ts`）。
2. **瓶颈一：巨型视图。** `src/views/PlayerView.vue` 共 5831 行，其中 script 4353 行，含 61 个 ref、84 个 computed、29 个 watch、约 123 个函数、101 条 import。播放页改动因此只能靠真机验收。
3. **瓶颈二：源健康闭环没接通。** 搜索扇出失败只记会话级连击（`src/stores/libraryStore.ts:519`），不回写源健康；被截止的源要用户手点才续搜（`src/stores/libraryStore.ts:708`）。按 2026-11-13 真机基线，真首装只覆盖 15/130 个源。
4. **瓶颈三：本地数据的持久性保证不足。**
   - 全仓没有调用 `navigator.storage.persist()`，只用了 `estimate()`（`src/stores/cacheStore.ts:54`）。
   - 自动备份与被备份的数据同存在一个 IndexedDB 的 kv 里（`src/services/backupService.ts:108`）。
   - `cacheStore` 只有手动清理，未见按容量上限的淘汰。
5. **瓶颈四：运行时安全面宽于必要。**
   - 全局明文放行、`allowMixedContent` 与 `cleartext` 开启（`capacitor.config.ts:17`），`index.html` 无 CSP。
   - App 会执行用户自带的第三方 jar / 规则并渲染外部文本。
   - 合规定位本身清晰：演示样片固定、`allowBackup=false`、门禁在路由层；唯一的 `v-html` 已做转义（`src/components/search/SearchSuggestion.vue:65`）。

**未核实项：**
- PlayerView 内部逻辑没有通读。
- `getDetail` / `resolvePlayUrl` 的参数对象是否带 `signal` 没有确认。
- 备份恢复前是否有差异预览没有确认。

## 2. 优化建议

### O1 拆分 PlayerView（P1）

| 项 | 内容 |
| --- | --- |
| 关联层 | views → composables → player |
| 依据 | 见 §1 第 2 条；已有 `src/composables/usePlayerController.ts` 可延续同一做法 |
| 实施动作 | 按「播放会话（选集/换线/failover）」「手势与 HUD」「诊断导出」「氛围光」「弹幕面板」抽成 composable 或子组件；每抽一块补组件测试；目标 script ≤ 1500 行 |
| 预期收益 | 播放页可单测，回归不再只靠真机 |
| 影响范围 | 仅表现层；不碰 `PlayerController` 与原生引擎 |
| 验证指标 | script 行数；新增测试数；首屏 entry 体积不超过当前 591,654B |

### O2 搜索扇出回写源健康，并自动续搜被截止的源（P0）

| 项 | 内容 |
| --- | --- |
| 关联层 | stores/libraryStore、services/libraryService |
| 依据 | `markSourceFailedByError` 只在重试失败源、手动切源、详情加载三处调用（`src/services/libraryService.ts:1849`），搜索本身不写健康；`bad_config` 的候选排除因此要等用户重试一次才生效 |
| 实施动作 | ① 在 `onPartial` 失败分支对确定性错误码（`E_AUTH`、jar 冲突、解析错误）回写健康并去抖，超时类只累计；② `skippedSourceIds` 非空时自动追加一轮（原批次 E），保留手动入口 |
| 预期收益 | 死源逐轮退出候选，首装召回缺口收敛 |
| 影响范围 | 源健康状态与搜索候选过滤 |
| 验证指标 | 真首装覆盖数从 15/130 提升；下一轮失败源数下降 |
| 风险 | 误判瞬时故障为死源 → 超时不回写，保留 `forceAll` 翻案入口。F7 预热与线程池争抢的账未结清，需加一组「F7 关闭」对照再下结论 |

### O3 存储持久化与缓存上限（P1）

| 项 | 内容 |
| --- | --- |
| 关联层 | stores/bootstrap、stores/cacheStore、native/mediaToolPlugin、db |
| 依据 | 见 §1 第 4 条。浏览缓存 TTL 5 分钟、播放地址 30 分钟（`src/services/libraryService.ts:182`），但条目数没有上限 |
| 实施动作 | ① Web 端在首次写入下载或缓存前调用 `persist()`；② `media/lines/episodes` 按源设 LRU 上限（复用 v6 的按时间索引做法）；③ Android 用原生可用空间查询，低空间时暂停入队 |
| 预期收益 | 浏览器不会在磁盘压力下回收数据；库体积可控 |
| 影响范围 | 启动流程多一个不阻塞的调用；可能需要 v8 迁移加索引 |
| 验证指标 | Chrome DevTools → Application → Storage 的 persisted 状态；各 store 行数峰值；连续浏览 20 个源后的占用 |
| 依赖与兼容 | 无新依赖；v8 迁移保持只增式，旧客户端忽略新索引 |

### O4 备份：异故障域、完整性、补 subscriptions（P1）

| 项 | 内容 |
| --- | --- |
| 关联层 | services/backupService、services/backupEncryption、db |
| 依据 | 导出集合不含 `subscriptions` store（`src/services/backupService.ts:907`，该文件只有两处 `subscriptionId` 字段归一化）；非加密备份没有摘要字段；备份文件存在被备份的同一个库里 |
| 实施动作 | ① 导出加入 `subscriptions` 并升 `schemaVersion`；② 明文备份加 SHA-256 字段，导入时校验（加密备份已有 GCM 认证标签）；③ 定时备份可选写到用户指定目录：Android 用 SAF，Web 用 File System Access API |
| 预期收益 | 库损坏时仍有可用备份；损坏文件在导入前被拒；订阅自带名称不丢 |
| 影响范围 | 旧备份仍可读（走 `normalizeBackupFile` 的宽松解析） |
| 验证指标 | 清库后恢复，源/收藏/历史/订阅名条数一致；篡改文件被拒 |
| 依赖与兼容 | 无新 npm 依赖；SAF 需要原生 Activity，替代方案是只保留现有手动导出并加强引导 |

### O5 运行时安全收口（P1）

| 项 | 内容 |
| --- | --- |
| 关联层 | index.html、capacitor.config.ts、android/app/src/main/res/xml/network_security_config.xml、vite.config.ts |
| 依据 | 见 §1 第 5 条；`sourcemap: false` 使线上 JS 堆栈无法还原 |
| 实施动作 | ① 分阶段加 CSP：先用 JS 监听 `securitypolicyviolation` 事件接入 logBus 收集违规，再收紧策略；② 明文流量保留私有网段与回环白名单，公网 http 源逐条评估；③ sourcemap 改 `hidden` 并随 Release 归档；④ 复核 `MANAGE_EXTERNAL_STORAGE` 是否只在首次添加爬虫或网盘源时申请 |
| 预期收益 | 第三方页面文本注入时拿不到 Capacitor 桥接；崩溃堆栈可定位 |
| 影响范围 | Android 全链路回归 |
| 验证指标 | CSP 违规事件为 0；播放、下载、爬虫、海报四条链路真机通过 |
| 风险 | hls.js worker、blob 播放地址、任意域名海报都需逐条放行，可能拖慢；无服务端，CSP 不能上报，只能本地收集。全局明文是用户 http 源的功能需要，不能直接关 |

## 5. 合规与风险边界（不可跨越）

- 不内置、不预置、不推荐任何第三方影视源或解析接口；测试只用 mock 订阅服务（`scripts/mock-subscription-server.cjs`）或用户自备的源。
- 演示样片保持 12 条公开版权，不扩充。
- 首启同意门禁不新增跳过开关，路由守卫不弱化。
- 不引入账号、统计 SDK、云端同步或常驻服务端；备份导出默认脱敏，不含视频内容。
- 第三方 jar 与网盘保持「用户自带」，不逆向第三方 API。
- 新增依赖（libass、vite-plugin-pwa 等）需过许可证审查。
- CSP 放行清单逐条留痕，不为省事直接放开 `unsafe-eval`。
- IndexedDB 迁移保持只增式，不改名、不删除既有 store 与索引。
