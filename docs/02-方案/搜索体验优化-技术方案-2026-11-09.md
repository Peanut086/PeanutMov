## 1. 全局前置：typecheck 门禁（SO-03 的一部分）

**现状**：`package.json:9` `build = vue-tsc --noEmit -p tsconfig.json && vite build`，`：10` `build:only = vite build`（跳过类型检查）。2026-11-06 体检记录 typecheck 有 35 个错误（src 6 + tests 29），导致 `npm run build` 被挡，团队改用 `build:only`，潜伏错误（含 SEARCH_FAILURE_LABELS 缺键）被带上线。

**改动**
1. 修复阻塞 `npm run typecheck` 的既有错误（src 6 处优先；tests 29 处可单独建任务清理）。SO-03 补标签会消掉其中 1 处 src 错误。
2. 约定：**禁用 `build:only` 作为交付构建**；CI / 本地交付一律 `npm run build`（含 vue-tsc）。
3. 可选：加 `prebuild` 钩子或 CI step 显式跑 `npm run typecheck`，红灯即失败。

**验收**：`npm run typecheck` 退出码 0；`npm run build` 成功；故意制造一个 Record 缺键错误时构建红灯。

**风险**：既有 35 错误修复可能牵涉测试夹具，工作量不确定 → 作为独立子任务先行，不阻塞 SO-01/02 的逻辑改动（逻辑改动本身保证新增代码类型正确）。

## 2. SO-01 预算超时改判 E_TIMEOUT（P0-A，最高优先）

### 目标
让"单源预算到期"与"用户主动取消"分流：预算超时 → `E_TIMEOUT`（计入 failed、可重试、触发退避）；用户取消 → `E_ABORTED`（静默）。对齐 `searchBudget.ts:9-10` 声明的契约。

### 现状证据
- `src/services/libraryService.ts:396` `const timer = setTimeout(() => controller.abort(), budgetMs)` —— 无 timedOut 标志。
- `src/services/libraryService.ts:668-669` catch 里 `done += 1; if (isCanceled(e)) return;` —— E_ABORTED 静默丢弃。
- `src/sources/spider/SpiderAdapter.ts:294` `onAbort → E_ABORTED`；`:678/684` 搜索 invoke 原生超时 30s > 预算 20s → 预算 abort 先到 → 永远 E_ABORTED。
- `src/shared/errors.ts:167-168` isCanceled 含 E_ABORTED。
- `src/stores/libraryStore.ts:535` recordTimeoutStreak 只认 E_TIMEOUT。

### 改动设计（`libraryService.ts:384-405` searchOneSource）
```ts
async function searchOneSource(source, keyword, signal, pageSize): Promise<MediaItem[]> {
  const adapter = await adapterFor(source);
  prewarm(adapter, source);
  const controller = new AbortController();
  const budgetMs = resolveSearchTimeoutMs(/* SO-05 后含 ext.timeout */ adapter.searchTimeoutMs ?? TIMEOUT_SEARCH_MS, await searchBudgetPreset());
  let timedOut = false;                                   // ← 新增
  const timer = setTimeout(() => { timedOut = true; controller.abort(); }, budgetMs);  // ← 改
  const onAbort = (): void => controller.abort();
  signal?.addEventListener('abort', onAbort, { once: true });
  try {
    return await adapter.search({ source, keyword, page: 1, pageSize, signal: controller.signal });
  } catch (e) {                                            // ← 新增 catch
    if (timedOut) {
      throw new AppError('E_TIMEOUT', `搜索超时（${Math.round(budgetMs / 1000)} 秒）`, { detail: source.name });
    }
    throw e;
  } finally {
    clearTimeout(timer);
    signal?.removeEventListener('abort', onAbort);
  }
}
```
- `settleOne`（`:651-675`）**无需改动**：超时现在抛 E_TIMEOUT，`isCanceled` 为 false → 自动走 `failed.push` + `onPartial(error)`；用户取消仍 E_ABORTED → 静默。
- 退避（`libraryStore.ts:535`）**无需改动**：E_TIMEOUT  now 能到达 recordTimeoutStreak，连续 3 次自动退避生效。

### 接口变更
无（仅内部逻辑）。`AppError('E_TIMEOUT', …)` 已是既有错误码。

### 测试要点
- 单测：mock adapter.search 永不 resolve → 预算到期 → searchOneSource 抛 E_TIMEOUT（非 E_ABORTED）。
- 单测：外部 signal.abort() → 抛 E_ABORTED（仍静默）。
- 单测：settleOne 收 E_TIMEOUT → failed 含该源 + onPartial(error) 调用；收 E_ABORTED → 不计 failed。
- 集成：连续 3 轮同源 E_TIMEOUT → searchBackoffSources 含该源 → 下一轮 scopeSourceIds 排除。
- 既有 `tests/` 中 searchBudget / libraryService 搜索用例回归。

### 风险与回滚
- 风险：failed 列表会"变多"（以前隐藏的超时现在显形）→ 失败面板更热闹，但这是**正确的可见性**；配合 SO-03 标签与 SO-02 披露。
- 回滚：移除 timedOut 标志与 catch 即恢复原状（单文件 hunk）。

### 验收
真机用饭太硬/潇洒搜热门片名：超时源出现在失败面板（"解析超时"），可"只重试失败源"；同源连续 3 轮超时后第 4 轮被跳过。

## 3. SO-02 全局截止披露"仅搜 N/M" + 继续搜剩余（P0-B）

### 目标
全局 28s 截止丢弃的源不再"隐形"：如实披露"仅搜索 N/M 个源，剩余 K 个因超时未搜索"，并提供"继续搜索剩余"增量动作。

### 现状证据
- `src/services/libraryService.ts:648` 全局 28000；`:686` 截止 return（剩余源不启动、不计失败）；`:683-690` worker 共享 cursor。
- `src/services/libraryService.ts:715` 抛错需 `failed.length===enabled.length`（叠加 SO-01 后超时进 failed，但 skipped 仍不在内）。
- `src/views/SearchView.vue:104-110` zeroCandidates 仅 `candidates===0 && filteredOut>0` 触发；`:679-686` 进度 resolve 即消失。
- `src/stores/libraryStore.ts:492-528` retryFailedSources 已有"增量合并 + 不闪空"范式可复用。

### 改动设计
**类型**（`src/types/index.ts:307-318` SearchResult）新增：
```ts
export interface SearchResult {
  // …既有字段…
  /** SO-02：全局截止后未启动搜索的源 ID（按 enabled 顺序） */
  skippedSourceIds: string[];
}
```
**服务**（`libraryService.ts:619-727` search）：
- worker 循环（`:683-690`）在 `const idx = cursor++` 后递增 `launched`（或直接以 cursor 终值为准）。因 cursor 单线程原子自增，已启动索引 = `[0, cursor)`。
- `Promise.all(workers)` 后：`const skippedSourceIds = enabled.slice(cursor).map(s => s.id);`
- 返回值（`:726`）追加 `skippedSourceIds`。
- 抛错条件（`:715`）调整为：`merged 空 && failed.length>0 && (failed.length + skippedSourceIds.length)===enabled.length` → 抛首个 failed（让"全超时/未搜"进错误态而非伪空态）；否则返回带 skipped 的正常结果。

**状态**（`libraryStore.ts`）：
- 新增 `searchSkippedIds = ref<string[]>([])`、`searchLaunched = ref(0)`。
- search 成功分支（`:444-465`）写入 `searchSkippedIds.value = result.skippedSourceIds`。
- 新增 `continueSearchSkipped()`：仿 retryFailedSources（`:492-528`），`libraryService.search({ keyword, sourceIds: searchSkippedIds.value })`，增量并入 searchResultsAll，成功后从 searchSkippedIds 移除已搜源；进行中禁止并发。

**视图**（`SearchView.vue`）：
- 空态（`:464-495`）与结果区（`:498-510`）增加披露条：`v-if="library.searchSkippedIds.length>0"` → "仅搜索 {{ launched }}/{{ candidates }} 个源，剩余 {{ skipped }} 个因超时未搜索" + 按钮"继续搜索剩余"（调 continueSearchSkipped）。
- 进度（`:679-686`）结束后保留终态摘要（由上述披露条承担），不再"消失即无信息"。
- emptyDescription（`:107-111`）：skipped>0 时文案改为"部分源因超时未参与，可继续搜索剩余源"，优先于"换个关键词"。

### 接口变更
- `SearchResult.skippedSourceIds: string[]`（新增必填字段；所有构造 SearchResult 的位置需补，grep `candidates:` 定位）。
- store 新增 `searchSkippedIds`、`searchLaunched`、`continueSearchSkipped()` 并 export。

### 测试要点
- 单测：enabled=20、并发 8、mock 每源耗时 > 截止 → 返回 skippedSourceIds.length>0 且 items 可能为空；launched+skipped===candidates。
- 单测：continueSearchSkipped 只搜 skipped 源、增量合并不重排已上屏。
- 组件：空态/结果区披露条渲染 + 按钮触发。
- 回归：retryFailedSources 不受影响。

### 风险与回滚
- 风险：SearchResult 新增必填字段 → 所有 mock/构造点需同步（类型门禁会强制暴露，配合 SO-03）。
- 回滚：移除字段与披露条；服务恢复原返回。

### 验收
导入潇洒（112 源）搜索：结果区显示"仅搜索约 12/112，剩余 100 个未搜索"+"继续搜索剩余"按钮；点击后增量补充结果，已上屏不闪空。

## 5. SO-05 档位透传采集管道 + 消费 ext.timeout（P1-B/D）

### 目标
搜索预算档位（fast/standard/patient）真正作用于站点源采集管道与爬虫原生调用；订阅声明的 `ext.timeout` 被消费为单源预算基准。

### 现状证据
- `src/sources/pipeline/scheduler.ts:55` `DEFAULT_BUDGET_MS.search=8000` 固定；`:269` `crawl` 已支持 `options.budgetMs ?? DEFAULT`；`CrawlOptions`（`:98`）含 budgetMs。
- `src/sources/site/SiteAdapter.ts:392-397` `crawl({intent,url,headers,signal})` **未传 budgetMs**；search→request（`:127-134`）。
- `src/sources/spider/SpiderAdapter.ts:678/684` invoke 固定 `NATIVE_INVOKE_TIMEOUT_MS=30s`。
- `src/services/subscriptionParser.ts:416-456` 解析 ext.timeout/quickSearch/playerType；`src/sources` grep 零消费。
- `src/services/libraryService.ts:395` budgetMs 仅用于外部 controller。

### 改动设计
**类型**（`src/types/index.ts:285-288` SearchParams）：
```ts
export interface SearchParams extends PageQuery {
  source: Source;
  keyword: string;
  budgetMs?: number;   // ← SO-05：调用方解析后的单源预算
}
```
**服务**（`libraryService.ts:384-405` searchOneSource）：
- 读 `ext.timeout`（新增 helper `extTimeoutOf(source): number|null`，取 `source.ext.timeout` 有限正数）。
- `const base = extTimeoutOf(source) ?? adapter.searchTimeoutMs ?? TIMEOUT_SEARCH_MS;`
- `const budgetMs = resolveSearchTimeoutMs(base, await searchBudgetPreset());`
- `adapter.search({ source, keyword, page:1, pageSize, signal: controller.signal, budgetMs })`。
- 外部 timer 仍用 budgetMs（与 SO-01 timedOut 联动）。

**站点适配器**（`SiteAdapter.ts`）：
- search（`:132`）→ request 透传 `budgetMs: params.budgetMs`（request opts 增字段）。
- send→crawl（`:392-397`）追加 `budgetMs: opts.budgetMs`（undefined 时 scheduler 回落 DEFAULT，行为不变）。

**爬虫适配器**（`SpiderAdapter.ts`）：
- search（`:751`）invoke 透传 budgetMs；invoke（`:656-693`）签名增 `budgetMs?: number`，raceNative 超时用 `budgetMs ?? NATIVE_INVOKE_TIMEOUT_MS`（`:678/684`）。
- 效果：原生超时与外部预算一致；patient 档爬虫可到 30s（钳制上限），fast 档收紧。

**quickSearch/playerType**：本项只消费 `timeout`。`quickSearch` 留待 SO-04/调度排序可选消费（标记优先候选）；`playerType` 属播放侧，不在搜索方案范围（停止在搜索 ext 解析或保留供播放，二选一，建议保留并另立播放任务）。

### 接口变更
- `SearchParams.budgetMs?`、SpiderAdapter.invoke 私有签名增参、SiteAdapter.request opts 增字段。均为向后兼容（可选）。

### 测试要点
- 单测：ext.timeout=12000 + standard → budgetMs=12000；patient → 18000；fast → 7200（钳制内）。
- 单测：SiteAdapter.search 传 budgetMs → crawl 收到同值（spy crawl options）。
- 单测：SpiderAdapter.invoke raceNative 超时 = 传入 budgetMs。
- 回归：未传 budgetMs 时站点仍 8s、爬虫仍 30s（DEFAULT 回落）。

### 风险与回滚
- 风险：patient 档爬虫 30s 会拖长全局收敛 → 由 SO-02 截止披露兜底；ext.timeout 异常大值被 resolveSearchTimeoutMs 钳制 30s。
- 回滚：移除 budgetMs 透传，恢复固定超时。

### 验收
设置"耐心"后站点源采集管道预算 > 8s（日志/ spy 证实）；订阅含 timeout 字段时单源预算按该值缩放。

## 6. SO-06 导入后分批预热爬虫 jar（P1-C）

### 目标
扩大预热覆盖（不止 top5），降低首搜冷启动超时；节流避免网络/CPU 尖峰。

### 现状证据
- `src/stores/sourceStore.ts:207-238` warmupSpiderSources：候选 enabled+spider+health!==unreachable，只 `slice(0,5)`，并发 2。
- `src/sources/spider/SpiderAdapter.ts:528-550` warmup：handles/warmingUp 去重、死健康跳过、失败静默。
- `src/services/libraryService.ts:392` prewarm fire-and-forget。

### 改动设计（`sourceStore.ts:207-238`）
- 优先级排序：当前源 → 默认源 → 健康 tier/延迟（复用 `libraryService.ts:600-614` 排序口径或 sourceStore.latencyOf）→ 其余。
- 分两段：① 前 N（常量 `WARMUP_EAGER_LIMIT`，建议 10~20，真机调参）立即预热；② 其余健康源后台 best-effort 分批（每批 5、并发 2、批间让出事件循环）。
- 守卫：`isOnline()` 为 false 时停止；搜索进行中（libraryStore.searchState==='loading'）暂停后台批，避免与搜索抢网络。
- 触发点：`sourceStore.load()`/`reload()` 后调用；导入完成（importService 成功回调）后调用。
- 适配器侧 warmup 已去重，重复调用无副作用（`:540`）。

### 接口变更
- 新增常量 `WARMUP_EAGER_LIMIT`（constants.ts 或 sourceStore 内）。warmupSpiderSources 签名不变。

### 测试要点
- 单测：30 个健康爬虫源 → eager 段 ≤ N，后台段覆盖其余；offline 时不发起。
- 单测：handles 已有的源不重复 load（spy load 调用次数）。
- 真机：导入饭太硬后首搜成功率较基线提升（logcat 预热完成日志计数）。

### 风险与回滚
- 风险：预热上百 jar 耗流量/电 → 必须有 offline 守卫 + 搜索期暂停 + 上限；建议加设置开关"后台预热爬虫"（默认开，可关）。
- 回滚：恢复 slice(0,5)。

### 验收
导入订阅后 logcat 出现 > 5 条"爬虫源预热完成"；首搜爬虫超时率下降；离线/搜索中无预热请求。

## 7. SO-09 站点搜索直走 videolist（P1-E）

### 目标

### 改动设计（`SiteAdapter.ts:411-418`）
```ts
// search 意图直接用 MacCMS 搜索约定 ac=videolist，跳过无效的 detail 首请求
const firstAc: 'detail' | 'videolist' = action === 'search' ? 'videolist' : 'detail';
const first = await send(firstAc);
if (usesCustomPath) return first;
if (action === 'search') return first;          // 搜索不再二次回退
if ((first.list?.length ?? 0) > 0) return first;
const fallback = await send('videolist');
return (fallback.list?.length ?? 0) > 0 ? fallback : first;
```
- list/detail 保持既有回退（不影响浏览/详情）。
- 可选增强（另立）：list 的 detail/videolist 改并行竞速——本项不做，避免扩大范围。

### 接口变更
无。

### 测试要点
- 单测：action='search' → crawl 仅调用 1 次且 URL 含 `ac=videolist&wd=`。
- 单测：action='list' 空结果 → 仍 2 次回退（回归）。
- 真机：老版 CMS 站点源搜索耗时下降。

### 风险与回滚
- 风险：极少数 CMS 搜索只认 ac=detail → 保留自定义路径（usesCustomPath）兜底；若真机发现反例，可对 search 加"videolist 空再试 detail"的回退（但默认不启用）。
- 回滚：恢复 firstAc='detail'。

### 验收
站点源搜索网络面板只见 1 次 videolist 请求；慢网下超时率下降。

## 9. SO-07 仅看可播扩大预检 + 区分未检测（P2-B）

### 目标

**过滤语义**（`libraryStore.ts:84-88`）：
- playableOnly 改为"隐藏**确认不可播**（empty/error）的组"，保留 playable + unknown/verifying：
```ts
const rep = selectRepresentative(g, …);
const st = rep ? playabilityOf(rep.id) : 'unknown';

```

**searchState 解耦**（`libraryStore.ts:465`）：
- 空态判定基于"有无原始结果"而非 playableOnly 过滤后：`searchState = searchGroups.value.length===0 ? 'empty' : 'success'`（避免开关翻空）。retryFailedSources（`:520`）同步。

### 接口变更
无（逻辑 + 文案）。

### 测试要点

### 风险与回滚

### 验收
