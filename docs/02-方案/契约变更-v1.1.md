## 1. 为什么要改

E2E 联调实测（源管理三页 + 订阅导入页）发现两处契约缺口，UI 只能显示"暂未开放"，功能无法落库：

| 缺口 | 现象 | 根因 |
| --- | --- | --- |
| CHG-01 | 新增/编辑/删除源、测试连接全部不落库（`SourceFormView.vue` 保存仅 Toast "暂未开放"；`SourceListView.vue` 删除同样） | API-14 `sourceStore` 只有 `load/select/setEnabled/reorder/refreshHealth`；`sourceService.create/update/remove/testConnection` 虽已实现，但按《开发任务拆分》2.2 白名单 UI 不能 import `@/services/sourceService` |
| CHG-02 | 订阅导入只能临时解析，`commit()` 提示"应用内订阅导入暂未开放" | `importService`（API-05）不在 2.2 白名单，API-14 也无导入相关 action |

> 受影响 AC：AC-03/04/05（新增/校验/边界）、AC-08~AC-14（订阅导入全链路）、AC-103/104（导入页合规提示）；FR-02、FR-04、FR-05、FR-06。

## 2. 改了什么

### 2.1 CHG-01：`sourceStore` 补 4 个 action（API-14）

```ts
create(input: SourceInput): Promise<Source>;
update(id: string, patch: Partial<SourceInput>): Promise<Source>;
remove(id: string, opts?: { removeDownloads?: boolean }): Promise<void>;
testConnection(input: SourceInput): Promise<{ ok: boolean; message: string; latencyMs?: number }>;
```

- 签名与 `src/services/sourceService.ts` 实际导出**一致**：`create`/`remove` 逐字相同；`update` 的 `Partial<SourceInput>` 与 Service 的 `Partial<SourceInput> & { enabled?; sort? }` 结构等价；`testConnection` 入参是 `TestConnectionInput` 的超集（Store 透传，多余字段被忽略），返回值为 `ConnectionResult` 的 UI 投影（`ok`/`latencyMs`/`message`），**不抛错**。
- 成功路径：Service 发 `sources:changed` → Store `reload()`；失败：写 `error` 并 re-throw，由 UI 出 Toast。
- 既有 5 个 action、state、getters **零改动**。

### 2.2 CHG-02：新增 `importStore`（API-14）

```ts
state: { preview: ImportPreview | null; parsing: boolean; committing: boolean; error: AppErrorShape | null; records: ImportRecord[] };
actions: {
  previewFromUrl(url: string): Promise<void>;
  previewFromFile(file: File): Promise<void>;
  previewFromText(text: string, fileName: string): Promise<void>;
  commit(options: ImportCommitOptions): Promise<ImportResult>;
  reset(): void;
  loadRecords(): Promise<void>;
}
```

- 内部调用 `importService.previewFromUrl/previewFromFile/previewFromText/commit` 与模块级导出 `listImportRecords()`；`ImportRecord` 由 Store 再导出，UI 不触达 Service 文件。
- `commit()` 只消费 `state.preview`（保证预览/提交同快照），`preview === null` 抛 `E_INVALID_STATE`；失败 re-throw，`previewFrom*` 失败只写 `error` 不抛（保留用户输入）。
- 导入成功后不直接写 `sourceStore`，靠 `sources:changed` 事件联动刷新，避免双写。
- **二选一的取舍**：未选"放开 `@/services/importService` 白名单"，因为导入的 `parsing/committing/error/preview` 是需跨组件共享的会话态，且白名单一旦为单个 Service 开口将逐层失效。

### 2.3 同步补充（不改接口）

- API-05 补注模块级导出 `ImportRecord` + `listImportRecords()`（实现中已存在，此前未写入契约）。
- 技术方案 3.8 Store 划分、8.3 状态归属：补 `importStore` 一行（共 9 个 Store：UI 2 + DATA 7）。
- 开发任务拆分 0 章 PKG-B 文件数 54 → 55；3.1 数据 Store 6 → 7；4.1 目录归属 6 → 7。
