| D1-D2 | — | 媒体库/详情/历史/收藏/设置/源管理页面 | 5 个适配器 + Source/Import/Library 服务 |

| D6 | 集成 | 去 mock、联调、Android 打包 | 同上 + 性能与配额处理 |
| D7 | 验收 | 按 SRS 第 9 章主线自测 + 交叉验收 | 同左 |

**硬规则**

1. 两包文件清单**零重叠**（见第 3 章校验）。
2. 任一方**不得**创建/修改对方清单内的文件；需要改动先提 PM。
3. `src/types/index.ts` 只允许 SCF 创建，之后**只读**。
4. 集成期如需临时改动对方文件（如修复类型），必须提 issue 由对方 owner 执行。
5. 每日 18:00 各跑 `npm run typecheck && npm run test:run`，绿了才算当天完成。

## 7. 沟通与阻塞处理

| 场景 | 处理 |
| --- | --- |
| 需要新增字段/改签名 | 停手 → 提 PM → 需求&方案方出 `v1.1` → 双方同步 |
| 对方文件有 bug | 提 issue 给对方 owner，不改对方文件 |
| 契约有歧义 | 以本文 + 技术方案为准；仍不清 → PM |
| mock 与真实实现行为不一致 | 以 `src/types/index.ts` + 技术方案 API 章节为准，PKG-B 修 mock |
| 进度落后 | 优先保 P0 AC，P1/P2 可延后；不得为赶工改契约 |
