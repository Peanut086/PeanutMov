## 1. 为什么要改

v1.7 真机验收后用户反馈四大方向全痛：播放卡/换线不灵、搜不到/源少、UI 不顺手、导入订阅麻烦。逐项比对代码后收窄为：

- **ExoPlayer 插件/开关/前端代理 v1.7 已就绪，但 `PlayerController` 未接线**——开关打开无任何效果，4K 软解天花板（AC-125）无从验证；且插件 `prepare` 重复调用泄漏旧实例、缺 `ended`/音量/丢帧事件。
- **换线换源链（AC-123）从未确定性真机触发**——机制在（单测覆盖），「点开转圈圈」场景缺端到端证据。
- **错误态「只报错不给路」**——搜索空态 CHG-15 已有「给原因 + 动作按钮」模式，播放失败面板与导入失败仍是死文案。
- **catvod JS 模块规则直接报「暂不支持」**——drpy 生态已通（CHG-16），但 FongMi 系 `import` 形态规则（jadehh/TVSpider 等仓库）整族不可用，是「源少」的最大单一剩余因素。

## 2. 改了什么

### 2.1 CHG-25：ExoPlayer 播放路由接线（FR-57）

**引擎层**——新增 `src/player/NativeEngine.ts`（实现 `PlayableEngine`）：

- `load()`：订阅插件 `exostate`（ready/buffering/ended/error）→ ready 结算 load、error 在 ready 前拒绝/其后走 onError；500ms 轮询 `progress()` 驱动 `onTimeUpdate`（buffered 以 position 近似）；
- rect 对齐：`ResizeObserver` + `resize`/`orientationchange` 防抖 150ms 重算 `setRect`（全屏/旋屏生效）；
- `getDroppedFrames()`：暴露会话累计丢帧（AC-125 采样）；清晰度恒空数组（面板天然隐藏）。

**路由层**——`PlayerController.attachEngine`：

- `PlayerLoadOptions.preferNativeEngine?: boolean`——由 PlayerView 读 `experimentalNativePlayer` 设置注入，**控制器保持「不调用任何 Service」分层约束**；
- 选择顺序：开关开且 `isExoPlayerAvailable()` → NativeEngine（套元数据超时）；**不可用/失败 → 静默回退 WebView 分支 + `notice` 事件**（不计播放失败，不误触发 FR-53 换线兜底）；
- 新事件：`enginechange {kind: 'native'|'hls'|'video'}`（composable 同步 `playerStore.engineKind`）、`notice {message}`（View 转 toast）。

**互斥（决策 1）**——PlayerView：进入 native 引擎自动关弹幕（toast 说明）+ 关闭激活的外挂字幕；弹幕按钮与字幕面板入口在 native 下 toast 拦截。

**Java 增量**（`ExoPlayerPlugin.java`）：prepare 先释放旧实例（修复切集泄漏）；`STATE_ENDED`/`STATE_BUFFERING` 事件；`setVolume`；`AnalyticsListener.onDroppedVideoFrames` 累计并在 `progress()` 上报；overlay/PlayerView 不可点击（触摸回落 WebView）；移除调试 Toast。

**验收**：AC-131 开关往返无残留（overlay 隐藏/无声音残留/二次进入可复用）；AC-132 prepare 失败自动回退 + toast 且不触发换线兜底；AC-133 = v1.7 AC-125 复验（4K ≥3 分钟丢帧可忽略，需真机）。

### 2.2 CHG-26：错误态可操作化（FR-58）

- **播放错误面板**（`PlayerErrorPanel.vue`）：新增「换源重播」（手动触发 `findAlternateSource`，触发前复位 failover 标志使自动链重新可用；页面级解析失败面板同加）与「去源体检」（错误码 ∈ {E_SOURCE_UNAVAILABLE, E_NETWORK, E_TIMEOUT, E_HTTP_401/403/429/5XX} 时显示，跳 `/settings/sources`）。
- **导入失败动作条**（`ImportSubscriptionView.vue`）：解析失败时给「重试 / 用修正地址重试（`normalizeImportUrl().url`，如 blob→raw）/ 换镜像重试（变体首项，如剥 gh-proxy 直连）/ 复制诊断（地址+错误+归一化提示）/ 去批量评测（带 url 预填）」；归一化 notes（拼写提示）随错误显示。

**验收**：AC-134 播放失败三动作真机可点且行为正确；AC-135 导入失败动作条全路径（对 gh-proxy 前缀地址触发换镜像重试）。

### 2.3 CHG-27：catvod JS 模块规则支持（FR-59）

**Spike 结论（2026-10-25，样本 jadehh/TVSpider）**：

- 规则形态：`import {_} from '../lib/cat.js'` 等相对导入 + `export function __jsEvalReturn() { return {init, home, homeVod, category, detail, play, search, proxy}; }`；
- `lib/cat.js` 为**自包含 UMD bundle（约 1.5 万行，自身零 import）**，导出 `_ / Crypto / dayjs / cheerio / load / Uri / ...`，**不导出 req**——网络/DOM 原生面（req/pdfh/pd/local）即 drpy_host.js 已有绑定，可完全复用；
- 模块图深度：规则 → 基类 spider.js → cat/vod/utils/log/hls/... 约 10 个 lib，部分再引 encoding 大文件；据此维持路线①（改写拼接）而非 ES Module loader。

**实现**——新增 `android/.../drpy/CatvodLoader.java`：

1. 递归解析 import（相对说明符按规则 URL 解析；`assets://` 明确不支持），HTTP 拉取并缓存 `filesDir/catvod-modules/{md5}.js`（单模块 8MB / 总量 16MB / ≤40 模块）；
2. 依赖拓扑序（DFS 后序，循环依赖明确报错）拼接为单脚本：`import {A as B}` → `var B = <依赖顶层原始名>;`（cat.js 的 `Sh as _` 别名导出是关键）；`import * as N` → `var N = {导出名: 原始名,...};`；`export default E` → `var __catDefault_i = (E);`（命名函数/类去前缀尾部绑定；匿名多行默认导出明确报不支持）；`export` 声明去前缀成为顶层声明；
3. `DrpyRuntime`：import 形态不再报错 → CatvodLoader 拼接 → evaluate → `globalThis.__catvod = __jsEvalReturn()`（或入口 default）；
4. `drpy_host.js`：`__drpyCall` 检测 `__catvod` 存在则走 `__catvodDispatch`（参数适配 TVBox quickjs 签名：`home(filter)` / `category(tid,pg,filter,extend)` / `detail([id])` / `play(flag,id,vipFlags)` / `search(wd,quick)`；init(cfg) 首调用以 `__drpyExt` 传入），复用异步结果槽；
5. `DrpyPlugin.load` 把 ruleUrl 传入运行时（相对 import 基地址）；加载看门狗 40s → 75s（多模块下载 + 大 bundle 编译）。

**已知边界（验收清单）**：顶层 const/let 跨模块重名 → 编译期报错按词法冲突暴露；不支持动态 `import()`、循环依赖、匿名多行默认导出、`assets://`。

**验收**：AC-136 ≥2 个真实 catvod 源 home/category/search/detail/play 真机全通（MuMu，注意域名屏蔽环境特性）；AC-137 加载时长记录（对照 drpy 725ms 基线）。
