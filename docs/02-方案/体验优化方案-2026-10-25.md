# 体验优化方案（2026-10-25）

> 输入：用户提供的 116 条社区订阅/接口清单（tvbox 导航页复制）。
> 现状基线：v1.6（CHG-01~17 已落地）。本文档是**方案提案**，未实现；CHG 编号为建议占用，立项时以契约变更为准。

## 0. 结论摘要

两条主诉的根因不在「解析器写错了」，而在**生态本身就是脏的**：

1. **「导入之后无法使用」** —— 116 条里约 25% 是死链/家庭宽带/垃圾/成人内容，约 10% 根本不是 TVBox 配置（官网主页、短链落地页、GitHub 仓库页、CMS 采集 API 直连、单流 m3u8、gitee blob 页）。当前解析器对「合法单仓 JSON」已经很好（容错 JSON/GBK/注释、jar 预检、drpy QuickJS、GitHub 镜像回退），但对「不是配置的东西」只会报 FORMAT_UNSUPPORTED，用户感知就是「导入失败/导入了不能用」。
2. **「检索一塌糊涂」** —— 现状是逐源流式追加结果（`libraryStore.search`），同一部片在每个源各出现一次、无归并、无相关度排序；爬虫源 20s 超时导致结果迟到被截断；全部源平铺无筛选。缺的是**跨源聚合层**，不是再调超时。

方案分七个模块、四期落地，优先把「导入成功率」和「检索可用性」打穿，弹幕作为独立新能力立项。

## 2. 方案

### 3.1 订阅解析与导入归一化（建议 CHG-18）—— 直接解决「导入后不能用」

在 `importService.previewFromUrl` 拉取前/失败后加两级处理，全部为纯函数 + 可单测：

**A. 拉取前 URL 归一化（新增 `src/shared/urlNormalize.ts`）**
1. `blob/` → `raw/` 重写：gitee / gitlab / jihulab / github / cnb.cool（#108 等直接修复）。
2. gh-proxy / ghfast 前缀剥离登记：把 `https://gh-proxy.org/https://raw.githubusercontent.com/...` 拆成「裸链 + 可选代理」二元组，代理失败自动剥前缀直连、再失败走 `GITHUB_MIRROR_HOSTS` 其它镜像（现有 `withGithubMirrorFallback` 只认裸链，扩展为前缀也认）。
3. CDN 变体矩阵：jsdelivr（#27）↔ raw.githubusercontent ↔ ghfast 互为变体。
4. 明显拼写修复提示：`?id-3` → `?id=3`（#95）给 warning 不静默改写。
5. 直播特征预判：URL 以 `.m3u`/`.txt` 结尾或命中已知直播 host → 预览阶段直接给「这是直播源，是否加入直播页」的分支（复用 CHG-13 解析器），而不是等 FORMAT_UNSUPPORTED。

**B. 拉取后内容识别扩展（`sources/pipeline/rules/defaults.ts` 加规则）**
1. **HTML 落地页嗅探**：`looksLike.html` 且 intent=subscription 时，抽取页面里 `.json/.txt/api.php` 候选链接（限同域，最多 3 条）二次拉取 —— 覆盖 #5 影视仓.com、#109 Link3.cc、#38 蚂蚁这类「官网即索引页」。
2. **短链解析**：3xx 跟随已由 fetch 处理；meta refresh / `location.href` JS 跳转由嗅探规则处理（#96 teach.link）。
3. **macCMS 直连识别**：响应 JSON 含 `code+list/class` 形态且无 `sites[]` → 生成一条 `type:0` site 源（api=该 URL）进预览（#73 极速）。这让「资源站 API」不必包一层 TVBox 配置。
4. **单流 m3u8**：内容是 `#EXTM3U` 且无 `#EXTINF` 或仅 1 路 → 提供「加入自定义频道」动作（#85/#87）。
5. **GitHub 仓库页**：host=github.com 且非 /raw/ → 文案指引 + 尝试 README 内 m3u/json 链接抽取（#104）。

**验收**：上述清单中 E/F/I 类（约 16 条）全部变成「可导入」或「给出明确可操作的引导文案」；其余类别不回退。

### 3.2 订阅评测与生命周期闭环（建议 CHG-19）—— 解决「导入了慢慢坏掉」

现状：CHG-12 评测是手动一次性；导入后源坏了没有后续。

1. **多仓自动展开评测**：`EvalSubscriptionView` 对 `repos[]` 并发（复用 `SUBSCRIPTION_EVAL_CONCURRENCY`）逐仓评测，结果聚合为「最优仓库推荐」，一键选仓导入。
2. **评测 → 导入闭环**：评测结果行加「导入该订阅最优 N 源」按钮（按 `aliveEstimate` 取 top，跳过 jar 判死与成人标记）。
3. **订阅生命周期**（`SubscriptionListView` 扩展）：
   - 订阅级健康摘要卡：源数 / 存活 / jar 死 / 最近刷新时间；
   - 定时刷新：app 启动 + 每 24h 后台跑 `refreshSubscription`（并发限 2，失败静默累计）；
   - **健康退化自动禁用**：连续 3 次体检失败（`healthService`）→ 源置 `enabled:false` 并在源管理页标「已自动禁用」，一键恢复；
   - 刷新冲突策略沿用 overwrite 语义，保留用户手动排序。
4. **gh 代理失效自愈**：源/订阅记录里存「裸链 + 实际命中变体」，变体挂了下次刷新自动换。

**验收**：连续一周不打开 app 的源清单，重新打开后 30s 内完成体检，失效源不再出现在检索候选里。

### 3.3 聚合检索（建议 CHG-20）—— 解决「检索一塌糊涂」

现状：`libraryStore.search` 流式追加、按 `item.id` 去重（等于没去重）、无排序。

1. **跨源聚合层**（新增 `searchAggregate.ts` 纯函数）：
   - 分组键 = 片名归一化（复用 `douban/playMatch` 的归一化：去 `HD/4K/修复版/国语` 等后缀、全半角/繁简归一）+ 年份（可缺省）；
   - 组卡片显示「N 个来源」，进详情后走现有换源面板；组内按 源健康 tier → 延迟 → 是否含清晰度信息 排序；
   - 保留「按源平铺」视图开关（老用户习惯）。
2. **相关度排序**：标题包含 > 前缀 > 分词包含 > 其它；keyword 空格分词 AND 匹配；同分按源健康。
3. **快慢源分区**：站点源（8s）先出第一屏；爬虫源（20s）结果到达时以「+N 条新结果」提示刷新列表，不重排已浏览内容。
4. **检索范围筛选**：全部 / 仅站点 / 仅爬虫 / 仅豆瓣（元数据），外加「仅这些源」多选（沿用 CHG-17 筛选交互）。
5. **热搜与联想**：豆瓣实时热门（`DoubanAdapter` 已有数据源）做初始页「大家都在搜」；历史 + 热词前缀联想。
6. **失败源退避**：同源连续 3 次检索超时 → 本次会话内跳过并在明细里标注（候选过滤逻辑已有，补会话级记忆）。

**验收**：搜「庆余年」出现 ≤3 张聚合卡（剧/动漫/相关），每卡可见来源数；首屏结果 ≤3s 出现；点击任一卡可播放或一键换源成功。

### 3.4 播放优化（建议 CHG-21）

1. **失败自动换线/换源链**：现状 `FALLBACK_ERROR_CODES` + `pickAlternate`（按健康 tier/延迟排序）已有雏形，补：起播 10s 内失败 → 自动换线路 → 再失败自动换源 → 仍失败才弹 `PlayerErrorPanel`；全程保留集号与进度（`episodeFallback` 已有定位逻辑）。Toast 告知「已切换到 线路2/源B」。
2. **下一集预载**：`NextEpisodePrompt` 倒计时触发时，预取下一集播放地址与 m3u8 清单（不拉分片），切换 0 感知。
3. **高码率缓冲调优**（`HlsEngine`）：level 高度 ≥1080 时 `maxBufferLength` 30→60s、`backBufferLength` 收紧控内存；ABR 起始 level 按上次选择记忆。
4. **直播低延迟**：`liveSyncDurationCount: 3` + 追帧策略；频道切换超时 5s 自动切同组下一 URL（多路同名频道已有数据结构）。
5. **原生引擎 PoC（评估项，不承诺）**：WebView+hls.js 软解在低端盒子上跑不动 4K。做 Capacitor ExoPlayer/Media3 插件 PoC（surface 模式），达标（MuMu 上 4K 不掉帧）再决定是否作为可选引擎，默认仍 WebView。

### 3.5 弹幕（建议 CHG-22，范围变更）

需求规格 §95 现为「弹幕：不做」→ 改为做，需走契约变更。自用、无服务端定位不变：弹幕**只读不发**。

1. **数据源 Provider 抽象**（`src/danmaku/`）：
   - 主源：dandanplay 匹配/弹幕 API（需申请 appId/secret，缓存共享）；
   - 备源：社区聚合端点（如 danmu.ai 风格的 title+episode 匹配）；
   - 本地：下载目录 `.xml`（B 站格式）直接解析；
   - 匹配：片名归一化 + 年份 + 集号，相似度阈值内才采用；结果（含偏移）落 IndexedDB，二次观看离线可用。
   - 隐私：第三方请求只带片名/年份/集数。
2. **渲染引擎**：`<canvas>` 覆盖层（`requestAnimationFrame` 驱动），滚动/顶部/底部三模式；同屏密度上限（默认 150 条）、重复弹幕合并、字幕安全区（底部 15% 默认禁显）。
3. **UI**：播放器 HUD 弹幕开关 + 设置 sheet（开关/字号/速度/透明度/显示区域/合并程度）；首次开启引导一条。
4. **联动**：`ProgressReporter` 进度对齐弹幕时间轴；倍速>2x 自动暂停拉取。

**验收**：热门剧任意一集 5s 内出弹幕；低端设备（MuMu）弹幕开启时播放不掉帧（帧率降幅 <10%）。

### 3.6 IPTV/直播强化（建议 CHG-23，对齐既定 P1）

1. EPG：diyp `?epg=` 风格 XMLTV 解析 + epg.pw 数据源，节目单显示「现在播/接下来」；
2. 频道收藏 + 数字快速换台；同名多路频道自动测速择优；
3. 失效频道（起播 5s 超时 ×2）自动沉底并标记；
4. m3u 大列表（iptv-org 全量 1w+ 频道）虚拟滚动 + 按国家/分组过滤。

### 3.7 内置推荐订阅清单（建议 CHG-24）

从这 116 条人工精选稳定项随 app 内置一份版本化 JSON（如：#10 饭太硬、#12 潇洒、#2/#13 kstore 系、#77 PG drpy、#53 御制、#54 影视仓多仓、#69 fanmingman ipv6、#93 Guovin iptv-api、#103 iptv-org），首启「推荐订阅」页一键评测后导入；支持云端清单 URL 更新。成人条目默认隐藏，设置里显式开关。

### 3.8 UI/交互横切

1. **订阅中心**（合并 `SubscriptionListView` + `EvalSubscriptionView` 入口）：评测/导入/健康摘要/自动刷新设置一页搞定；
2. **源管理批量操作**：按体检结果批量禁用/删除失效源、失败原因分类标签（jar 死/域名失效/超时/成人）；
3. **错误态可操作化**：所有「导入失败/检索为空/播放失败」都带下一步动作按钮（换镜像/强制重试/换源/去体检）——搜索空态 CHG-15 已做，推广到导入与播放；
4. **首页**：豆瓣榜单 tab + 继续 watching 已有，补「最近导入的源」快速入口。
