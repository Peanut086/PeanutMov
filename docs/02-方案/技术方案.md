## 1. 架构总览

### 1.1 设计原则

1. **单机、离线优先**：IndexedDB 是唯一事实源（Source of Truth），网络只用于"补齐/刷新"；无服务端、无账号。
2. **适配器隔离差异**：所有源协议差异收敛在 `SourceAdapter` 之后，UI 只面向统一的 `MediaItem/Episode/PlaybackSource`。
3. **服务层唯一入口**：UI 不直接读写 DB、不直接 `fetch` 源地址，一律经 `src/services/**`，利于并行开发与测试。
4. **原生能力可降级**：所有 Capacitor 能力（投屏、文件、亮度、横屏）在 Web 下都有明确降级路径与错误码，保证 `npm run dev` 全流程可跑。
5. **契约先行**：`src/types/index.ts` 与本文 API 章节冻结后，两包并行开发不互相阻塞。

### 1.3 关键数据流

**浏览**：`View` → `libraryStore.browse()` → `LibraryService.browse()` → 命中 IndexedDB 缓存则即时返回 → 后台 `SourceRegistry.get(source).browse()` → 归一化为 `MediaItem[]` → upsert DB → 事件刷新 store。

**播放**：`PlayerView` → `LibraryService.getDetail()` 得线路/剧集 → `SourceAdapter.resolvePlayUrl()` 得 `PlaybackSource` → `PlayerController` 选择引擎（native HLS / hls.js / video）→ 每 5s `HistoryService.saveProgress()`。

**下载**：`DownloadService.create()` 写 `downloads` 记录（queued）→ `DownloadQueue` 调度 → `DownloadEngine`（fetch 流）→ sink（Android Filesystem append / Web Blob→IDB）→ 事件推送进度 → 完成后写 `filePath`/`blobKey` → 播放走本地 URL。

## 2. 技术选型

| 领域 | 选型 | 版本基线 | 理由 |
| --- | --- | --- | --- |
| 框架 | Vue 3（Composition API + `<script setup>`） | ^3.5 | 用户熟悉；单文件组件适合快速搭建播放器 UI |
| 构建 | Vite | ^6 | 快速 HMR；`build.target: es2020`；可拆 hls.js 独立 chunk |
| 语言 | TypeScript（`strict: true`） | ^5.6 | 契约类型即文档，两包并行开发依赖类型约束 |
| 状态 | Pinia | ^2.2 | 轻量、TS 友好；不做持久化插件（持久化交给服务层，避免双写） |
| 路由 | Vue Router | ^4.4 | hash 模式（Capacitor `file://`/本地服务下更稳） |
| 本地库 | idb | ^8 | 轻量 Promise 封装，完全掌控 object store/索引/事务；比 Dexie 更贴近原生 IndexedDB 语义 |
| HLS | hls.js | ^1.5（**懒加载**） | 覆盖 Android WebView 无原生 HLS 的场景；支持多码率、字幕、错误恢复 |
| 原生 | Capacitor | ^7 | 与 Vue/Vite 无缝；Filesystem、Share、ScreenOrientation、App、Network 官方插件齐全 |
| 测试 | Vitest + @vue/test-utils + happy-dom + fake-indexeddb | ^2.1 / ^2.4 / ^15 / ^6 | 与 Vite 同源配置；IDB 可在 Node 中测 |
| 图表/UI 库 | 无（自写 CSS + 设计 token） | — | 避免体积与样式对抗；播放器/海报墙均为定制布局 |
| 图标 | 内联 SVG 组件（`src/components/icons`） | — | 无字体依赖，离线可用 |

**不引入**：Element Plus / Vant（移动端样式定制成本高）、Axios（`fetch` 足够，且 CapacitorHttp 只 patch fetch/XHR）、vue-i18n（首版单语言，但文案集中管理）。

## 5. IndexedDB 表结构

- 数据库名：`cinema-db`；版本常量 `DB_VERSION = 1`（`src/shared/constants.ts`）。
- 封装：`idb` 的 `openDB<CinemaDB>(DB_NAME, DB_VERSION, { upgrade, blocked, blocking })`。
- 所有写操作用单事务；跨表原子写（如导入）使用 `db.transaction([...], 'readwrite')`。
- 统一 `withTx(stores, mode, fn)`，禁止在事务内 `await` 非 IDB Promise（idb 事务会自动提交）。

### 5.1 Object Store 一览

| Store | 主键 | 索引 | 值类型 | 说明 |
| --- | --- | --- | --- | --- |
| `sources` | `id` | `by-sort(sort)`、`by-type(type)`、`by-enabled(enabled)`、`by-key(key)` **unique** | `Source` | 源配置 |
| `media` | `id` | `by-source(sourceId)`、`by-source-updated(sourceId, updatedAt)`、`by-title(titleLower)`、`by-type(type)`、`by-demo(isDemo)`、`by-cached(cachedAt)` | `MediaItem` | 条目缓存 |
| `lines` | `id` | `by-media(mediaId)`、`by-source(sourceId)` | `PlayLine` | 播放线路 |
| `episodes` | `id` | `by-media(mediaId)`、`by-media-number(mediaId, number)`、`by-line(lineId)`、`by-source(sourceId)` | `Episode` | 剧集 |
| `categories` | `id` | `by-source(sourceId)`、`by-source-order(sourceId, order)` | `Category` | 分类 |
| `history` | `id` | `by-updated(updatedAt)`、`by-source(sourceId)` | `HistoryRecord` | 观看历史 |
| `favorites` | `id` | `by-created(createdAt)`、`by-source(sourceId)` | `FavoriteRecord` | 收藏 |
| `downloads` | `id` | `by-status(status)`、`by-media(mediaId, episodeId)`、`by-created(createdAt)`、`by-priority(priority)` | `DownloadTask` | 下载任务 |
| `blobs` | `key` | 无 | `{ key: string; blob: Blob; size: number; mime: string; createdAt: number }` | Web 端下载内容 |
| `kv` | `key` | 无 | `{ key: string; value: unknown; updatedAt: number }` | 设置、演示种子标记、导入记录 |

### 5.2 关键约束与写策略

- **时间戳**：`updatedAt` 一律在写入时刷新；`cachedAt` 仅在首次入库或显式刷新时更新。
- **去重**：`sources.by-key` 唯一索引；`media` 主键由 `stableId(sourceId, sourceItemId)` 生成；`history` 主键 `sourceId:mediaId`；`favorites` 同；`downloads` 去重靠 `by-media(mediaId, episodeId)` 查询（非唯一，因取消任务保留历史记录）。
- **删除源级联**（`SourceService.remove`）：删除 `sources`、该源 `media/lines/episodes/categories`；`history`/`favorites` 保留但写 `sourceRemoved`（favorites）与不做改动（history 在展示时按源存在性判断）；`downloads` 按 `removeDownloads` 选项处理。
- **历史上限**：`historyRepo.save` 后若 `count() > 500`，按 `updatedAt` 升序删除超出部分（同一事务内）。
- **批量写**：`upsert` 循环 + 每 200 条让出事件循环，避免长任务。
- **配额**：捕获 `QuotaExceededError` → `AppError('E_STORAGE_QUOTA')`，不吞异常。

### 5.3 版本升级策略

```ts
// src/db/migrations.ts 契约
export function upgrade(db: IDBPDatabase<CinemaDB>, oldVersion: number, newVersion: number): void {
  if (oldVersion < 1) { /* 创建全部 store 与索引（见 5.1） */ }
  // 未来：if (oldVersion < 2) { /* 只允许新增 store / 索引；字段变更必须在代码层做兼容读取 */ }
}
```

规则：
1. 只做**加法**升级（新增 store / 非唯一索引）。禁止在 upgrade 中修改已有索引名，如需改则新建索引。
2. 删除字段走"代码层兼容"（读取时 `?? null`），不删数据，避免旧备份导入失败。
3. 版本不匹配：`db.version > DB_VERSION` → 打开失败 → 展示 `E_VERSION_UNSUPPORTED` 页面（"请升级 App"），**不得**调用 `deleteDatabase`。
4. 每次升版必须在 `docs` 或 `migrations.ts` 注释里登记：版本、变更、回滚方式。
5. 升级中断（`blocked`）时提示"请关闭其它窗口后重试"。

## 6. 内部服务契约（API）

> 约定：所有服务为模块级单例（`export const xxxService`），方法均为 `async`；失败一律 `throw AppError`（`src/shared/errors.ts`），**不返回 `{error}`**（查询类返回 `null` 表示不存在）。`AppError` 结构：`{ code, message, detail, retryable, httpStatus }`。

### API-01 `SourceAdapter`（适配器接口）

已定义于 `src/types/index.ts`。**实现约束**：

| 方法 | 入参 | 返回 | 错误语义 |
| --- | --- | --- | --- |
| `testConnection(source, signal?)` | 源配置 | `ConnectionResult`（本方法**不抛错**，错误放入 `result.error`） | 超时 3000ms |
| `listCategories(source, signal?)` | 源 | `Category[]`；失败抛错 | 认证失败 → `E_AUTH`；网络 → `E_NETWORK` |

| 方法 | 错误 | 说明 |
| --- | --- | --- |
| `previewFromUrl` | `E_NETWORK`/`E_TIMEOUT`/`E_HTTP_*`/`E_PARSE` | 10s 超时；响应体 >2MB 直接 `E_INVALID_INPUT`（"文件过大"） |
| `previewFromFile` | `E_INVALID_INPUT`（后缀非 .json / >2MB / 空） | 读取用 `file.text()` |
| `commit` | `E_INVALID_INPUT` / `E_DB` / `E_STORAGE_QUOTA` | 单事务写全部源；失败回滚；`onDuplicate` 语义见需求 FR-04 |

`commit` 细节：`overwrite` 时保留原 `id`/`createdAt`，更新配置并清空该源缓存；`keep-both` 生成新 key（`${key}-2`）。

**`commit` 的计数口径与 `selectedKeys` 语义（v1.1 / CHG-03）**

| 字段 | 口径 |
| --- | --- |
| `success` | 本次真正写入的条目数（含 `overwrite` 更新、`keep-both` 新建） |
| `skipped` | **未被写入**的条目数 = ① 预览阶段即判定无效（`!valid` 或 `normalized === null`）的条目 + ② 与已有源重复且 `onDuplicate === 'skip'` 的条目 |
| `failed` | 逐条写入失败数；单事务模式下写入失败整体抛错（`E_DB`），正常恒为 0 |
| `issues` | ① 汇总为一条 `info` / `SKIPPED_INVALID`；② 逐条 `SKIPPED_DUPLICATE` |

- 不变量：`success + skipped + 未勾选的合法条目 = ImportPreview.total`，即预览"共 N 个源 / 可导入 M 个"与提交结果可对账（AC-13）。
- `selectedKeys: []` = **导入全部有效项**（等价全选）；非空 = 仅导入 key 命中项。合法但未勾选的条目既不计 `success` 也不计 `skipped`（用户主动排除 ≠ 跳过）。
- 该"空数组 = 全选"是程序化调用的便捷语义，UI 仅按当前做法无需改动：`ImportSubscriptionView` 在 `importableCount === 0` 时按钮置灰并提前 return，"一个都没勾选但存在有效项"不会走到 `commit`。新增调用方须遵守同一约束（全不选时不要调用 `commit`）。
- 健壮性补充（同属 CHG-03）：`onDuplicate: 'overwrite'` 下若预览快照未标 `duplicateOf` 但 key 已被占用（预览后新增源、或重复提交同一份预览），按覆盖处理而非写入重复 key，避免唯一索引 `ConstraintError`。

- 导入：`E_VERSION_UNSUPPORTED`（`schemaVersion > 1` 或缺失）、`E_PARSE`、`E_INVALID_INPUT`；`overwrite` 前弹二次确认由 UI 负责（Service 只执行）。
- 导入为单事务写 `sources/favorites/history`，失败全回滚（`E_DB`）。

**`downloads`（下载任务元数据）口径（v1.1 / CHG-04，对应 FR-40）**

FR-40 原文："导出：源配置、设置、收藏、历史、**下载任务元数据**，生成 JSON 文件；**不含视频文件与 Blob**。"

- **导出包含下载任务**：`collectBackup` 读 `downloads` 表全量任务，按 `BackupFile.downloads`（`Omit<DownloadTask, 'sink' | 'filePath' | 'blobKey'>`）投影后写入。备份页"下载任务元数据"文案因此成立，`summarizeBackup().downloads` 为真实条数。
- **只含元数据**：① 不读 `blobs` 表，故不含任何视频内容；② 剔除 `sink`/`filePath`/`blobKey`（它们指向导出机器的本地存储，换机后必然失效，且 `filePath` 可能泄漏本机目录结构）；③ `parseBackup` 对导入文件同样强制剔除这三个字段，即使备份被人为塞入也不采纳。
- **凭据**：`includeCredentials=false` 时，除源配置的 `auth.password`/`auth.token` 外，下载元数据里的**凭据类 header**（`Authorization`/`Cookie`/`*token*`/`apiKey`/`secret`/`password`）与 URL query 中的同名参数一并剔除（播放直链常带 token）；`true` 时原样保留。非凭据 header（如 `User-Agent`）始终保留。
- **导入不恢复下载任务**：视频文件与源缓存不在备份内，单独恢复任务只会产生无法播放/续传的死任务。`importData` 不写 `downloads` 表；`BackupImportReport.downloads` 仅表示"备份文件中携带的任务条数"，UI 不应把它展示为"已恢复 N 个下载"。
- 该口径不改变任何类型定义与导出签名（`BackupFile.downloads` 与 `BackupImportReport.downloads` 早已存在）。

## 7. 订阅 JSON 格式规范

### 7.1 兼容目标

兼容 **TVBox 风格** `sites[]` 的**最小字段集**，并接受一种等价简化格式（便于用户手写）。不认识的多余字段全部忽略（不得报错）。

### 7.2 顶层结构

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sites` 或 `sources` | `array` | 是（二选一） | 源数组；同时存在时取 `sites` |
| `urls` | `array` | 否 | 多仓索引：元素为 URL 字符串或 `{ url, name }`；命中时 `entries` 为空、`repos` 有值，由 UI 选择仓库展开 |
| `name` | `string` | 否 | 订阅名称 |
| `version` | `number` | 否 | 订阅格式版本，当前仅识别 1 |
| 其它（`lives`/`parses`/`flags`/`spider`） | any | 否 | 忽略 |

> 多仓索引也接受**逐行 URL 的纯文本**（常见 `dc.txt`）：不是 JSON 时按行收集 `http(s)` 地址。展开由 `importService.previewFromRepo` 二次拉取，解析器保持纯函数。

### 7.3 `sites[]` 条目字段

| 字段 | 类型 | 必填 | 映射到 |
| --- | --- | --- | --- |
| `key` | string | **是** | `Source.key`（去重键） |
| `name` | string | **是** | `Source.name` |
| `type` | number \| string | **是** | `Source.type`（映射见下表） |
| `api` | string(http/https) | **是** | `Source.baseUrl`（站点 API / AList / Jellyfin 根地址）；WebDAV 为目录 URL |
| `ext` | object \| string(JSON) \| null | 否 | `Source.ext`；字符串会尝试 `JSON.parse` |
| `searchable` / `search` | 0\|1\|boolean | 否 | 是否支持搜索（默认 true） |
| `filterable` / `filter` | 0\|1\|boolean | 否 | 是否支持筛选（首版忽略，保留） |
| `quickSearch` | 0\|1 | 否 | 忽略 |
| `playerType` | number | 否 | 忽略（首版不解析播放器类型） |
| `headers` | object | 否 | `Source.headers` |
| `timeout` | number | 否 | 忽略 |

**type 映射表**

| 输入 | 内部 `SourceType` |
| --- | --- |
| `"alist"`、`3` | `alist` |
| `"webdav"`、`4` | `webdav` |
| `"jellyfin"`、`5` | `jellyfin` |
| `"site"`、`0`、`1`、`2` | `site` |
| `"spider"`、`3` + `api` 为 `csp_*`/`py_*` | `spider` |
| `"douban"`、`3` + drpy 规则指向豆瓣 | `douban` |
| 其它字符串/数字 | 跳过（`TYPE_UNKNOWN`） |

> `2` 在 TVBox 里也常指 CMS 站点，故与 `0`/`1` 同样映射为 `site`。非爬虫源的 `api` 仍必须是 `http(s)` 地址。

**爬虫源判定（CHG-07，v1.3）**

`type: 3` 的 `api` 有两种形态，按形态改判为 `spider`：

| `api` 形态 | 判定 | 说明 |
| --- | --- | --- |
| `csp_XBPQ` / `py_cctv_full` | `spider`（`kind: 'jar'`） | jar 爬虫，原生 `DexClassLoader` 执行 |
| drpy 规则地址含 `douban` | `douban`（`kind: 'douban'`） | 豆瓣类规则，用 TS 原生客户端实现（见下） |
| 其它 `https://…/xxx.js` | `spider`（`kind: 'js'`） | drpy JS 爬虫，**当前版本不执行**，导入时带告警 |
| 其它 `http(s)`（非 `.js`） | `alist` | 维持原行为 |

> **drpy JS 引擎决策（2026-10-24，`scripts/scan-drpy-sources.cjs` 实测）**：
> 95 个订阅地址仅 8 个可解析、共 15 个 drpy 源，其中规则自带播放能力的只有 4 个
> （夜猫秒播、虎牙直播、斗鱼直播、荐片P2P——均为直播/P2P 小众源）。
> 对比 jar 爬虫（单个 4k.json 订阅即 53 条），接 QuickJS 的覆盖收益不足，**暂不内置 JS 引擎**；
> drpy 条目维持「可导入、带告警、浏览不可用」。重新评估条件：订阅生态中
> 自带播放能力的 drpy 影视源占比显著上升时，再评估 QuickJS 方案。

`jar` 来源：条目自带 `jar` 优先，缺失时回落到订阅顶层 `spider`；两者都没有则该条判 `MISSING_FIELD`。
jar 地址允许 `url;md5;hash` 形式，原生侧下载后校验 md5。

`Source.ext` 对爬虫源的形状（由解析器写入，适配器与原生插件读取）：

```ts
{
  kind: 'jar' | 'js',
  api: string | null,      // jar 爬虫类名；JS 爬虫为 null
  jarUrl: string | null,   // jar 地址（含 ;md5; 后缀时原样保留）
  initExt: string,         // 原样传给 Spider.init(context, ext)
  searchable?: boolean
}
```

> 爬虫源的 `baseUrl` 用 jar 地址占位（爬虫没有站点根地址），供源地址校验与原生侧定位。
> 爬虫的 `ext` 常是 TVBox 的 `key:value` 纯文本而非 JSON，因此爬虫源不校验 ext 的 JSON 合法性。

**爬虫运行时（原生）**

| 层 | 职责 |
| --- | --- |
| `src/sources/spider/SpiderAdapter.ts` | 调原生插件 → 解析 TVBox JSON → 复用 `tvboxNormalize` 归一化 |
| `src/native/spiderPlugin.ts` | Capacitor 插件 `Spider` 的 JS 契约 |
| `android/.../SpiderPlugin.java` | 下载/校验/缓存 jar → `DexClassLoader` → 反射调用 |
| `android/.../com/github/catvod/crawler/` | TVBox 框架 stub：`Spider` / `SpiderApi` / `SpiderDebug` |

方法映射：`homeContent` → 分类、`categoryContent` → 浏览、`detailContent` → 详情、
`searchContent` → 搜索、`playerContent` → 播放地址、`proxy` → 换回直链。

> **代理播放（CHG-07）**：`playerContent` 返回 `proxy: 1` 或地址为 `proxy://` 协议时，
> `SpiderAdapter` 先调用插件 `proxy({handle, url})` 换回直链再走协议白名单校验，
> 代理返回的 headers 并入 `PlaybackSource.headers`。注意原生侧语义是
> 「调爬虫 `proxy(Map)` 后返回直链」，非 TVBox 原版的本地流式代理服务器（流式转发留二期）。

> **两段式探活（CHG-09，2026-10-24）**：爬虫源 `probe` 拆两段——
> **A 段** HEAD jar 地址（剥 `;md5;` 后缀，3s 超时、不重试），403 / 域名失效等
> 死源在秒级归类（403 → `auth_failed`、404 → `unreachable`），不再走 20~30s 的原生下载；
> **B 段** A 段通过或结论不确定时执行完整加载 + `homeContent`，测「jar 活着但源站死了」。
> 结论不确定的口径：`E_TIMEOUT`（可能是慢网络下的活源）与 HTTP 405/501（服务端不支持 HEAD）。

> **GitHub raw 镜像回退（CHG-11，2026-10-24）**：`shared/githubMirror.ts` 提供
> `withGithubMirrorFallback`——直连 `raw.githubusercontent.com`（及 gist / github.com `/raw/` 形态）
> 网络类失败（`E_NETWORK`/`E_TIMEOUT`）时按序换 `gh-proxy.org` / `ghfast.top` / `gh-proxy.com`；
> HTTP 4xx/5xx 不回退（资源本身的问题）。接线三处：订阅拉取（共享 10s 预算）、
> jar 预检 / 探活 A 段（HEAD jar）、直播列表拉取。

> **导入 jar 预检（CHG-10，2026-10-24）**：`importService.previewFromRaw` 对 `spider`（jar）
> 条目并发 HEAD jar 地址（并发 6、3s、不重试，同一 jar 共享结果），判死条目
> **取消默认勾选**并追加警示「jar 不可达（HTTP xxx），导入后无法浏览」。判定为
> dead 的口径：HTTP 4xx/5xx（状态码可读）；`E_TIMEOUT` / 405 / 501 不确定不判死；
> Web 端 `E_NETWORK` 可能是 CORS 假阳性，同样不判死（原生端网络错误视为域名失效）。

> **List/Map 形参必须显式声明**：`detailContent(ids: List)`、`playerContent(vipFlags: List)`
> 通过 `arrayArgs` 按位置下标传入，`categoryContent(extend: HashMap)` 用对象传入。
> Capacitor 桥接会把嵌套数组展平成字符串，直接传 `[['1']]` 会变成 `"1"` 而反射失败。

> **H5 环境**：dex 只能在 Android 上执行，Web 端爬虫源返回 `E_NOT_IMPLEMENTED`（「爬虫源仅支持在 App 内使用」）。

**豆瓣源（`douban`，发现源）**

豆瓣类 drpy 规则（如「聚玩盒子4K」的 `douban.js`）本质是豆瓣小程序 API 的客户端，
规则里 `二级:''`、`play_parse:false`、列表项无 `vod_play_url`——**只提供元数据，不提供播放**。
因此不为它接 JS 引擎，而用 TS 直接实现同一套请求（`src/sources/douban/doubanClient.ts`）：

| 能力 | 接口 | 说明 |

| 浏览 | 同上 + `start`/`count` 分页 | 每页 30 条 |

**播放：跨源借 CMS**

豆瓣没有片源，播放时按片名去**已启用的 site/spider 源**搜索并借用地址：

```
DoubanAdapter.resolvePlayUrl
  → doubanRuntime.resolvePlayFrom（按片名搜其它源）
  → pickPlayCandidate（片名归一化相等 + 年份一致）
  → 候选源自己的 adapter.resolvePlayUrl
```

匹配规则（`playMatch.ts`）：片名去掉年份/季/集/预告/画质后必须**完全相等**，年份双方都有时必须一致；
任一条件不满足返回 null，上层报「已启用的源里没有找到这部影片的可播放地址」——
**宁可播不出来，也不串片**。

> 依赖：豆瓣源要能播放，必须同时启用至少一个 site/spider 源。
> 装配在 `main.ts` 启动时通过 `initDoubanRuntime()` 完成（幂等）。

### 7.6 站点源接口约定（`site` 适配器）

TVBox 风格 HTTP API（GET，返回 JSON）：

| 请求 | 约定 |
| --- | --- |
| 分类 | `{api}?ac=list` → `{ class: [{ type_id, type_name }] }` |
| 列表 | `{api}?ac=detail&t={type_id}&pg={page}` → `{ list: [...], total, pagecount }`；返回空列表时自动回退一次 `ac=videolist`（老版 CMS 只认该参数） |
| 搜索 | `{api}?wd={keyword}&ac=detail` → `{ list: [...] }`；空结果同样回退 `ac=videolist` |
| 详情 | `{api}?ac=detail&ids={id}` → `{ list: [ { vod_id, vod_name, vod_pic, vod_year, vod_area, vod_remarks, vod_content, vod_play_from, vod_play_url } ] }` |

> 回退只在**列表/搜索**生效，且 `ext.listPath` / `ext.searchPath` 自定义路径时不参与（用户已显式指定）。详情按 `ids` 取单条，不回退。

字段映射：`vod_name→title`、`vod_pic→posterUrl`、`vod_year→year`、`vod_area→area`、`type_name→genres`、`vod_content→description`（去 HTML 标签）、`vod_remarks→episodeCount`（尽量解析数字）、`vod_play_from→线路名（用 $$$ 分隔）`、`vod_play_url→剧集（`集名$地址` 用 `#` 分隔，线路间用 `$$$` 分隔）`。

播放地址解析规则（`resolvePlayUrl`）：
1. 按线路索引取对应 `$$$` 段；
2. 按 `#` 拆集，按 `$` 拆"名称/地址"（无 `$` 则整段为地址）；
3. 地址若以 `/` 开头则拼源 `baseUrl`；
4. 若地址是另一层 `?url=` 包装（如普通解析接口），首版**不递归解析**，直接当直链尝试；失败 → `E_NO_PLAY_URL` 并提示"该源需要解析接口，暂不支持"。

### 7.7 解析失败与降级

| 情况 | 行为 |
| --- | --- |
| 非 JSON / 空响应 | 全局错误 `PARSE_JSON`，不导入（纯文本逐行 URL 的多仓索引除外，见 7.2） |
| JSON 含整行 `//` 注释 | **容错解析**：剥离整行注释后重试，成功则导入并附 `RELAXED_JSON` info 提示 |
| 字符串被硬折行截断 | **容错解析**：按"本行未转义引号为奇数"判定拼接点并续接下一行，附 `RELAXED_JSON` info 提示 |
| 两层容错后仍失败 | 基于**剥离注释后**的重新解析错误给出诊断（未转义换行 / 内容不完整 / 结构错误 / 多余逗号），仍为 `PARSE_JSON` |
| 无 `sites/sources` | 顶层有 `urls[]` → 多仓索引（`repos` 非空，`MULTI_REPO` info）；否则全局错误 `FORMAT_UNSUPPORTED` |
| 数组为空 | 全局错误 `EMPTY` |
| 条目缺 `key`/`name`/`api` | 该条 `valid:false`、`selected:false`，其它条可导入 |
| `ext` 字符串非法 JSON | 该条 `warning`（"ext 不是合法 JSON，已忽略"），仍可导入且 `ext = null` |
| 重复 key（同批） | 后者 `valid:false`，`issues=DUPLICATE_KEY` |
| 与已有源 key 冲突 | `duplicateOf` 标记，按 `onDuplicate` 处理 |
| > 500 条 | 全局错误 `TOO_MANY`，提示分批导入 |
| 响应体 > 2MB | `E_INVALID_INPUT`（"订阅内容过大"） |
| 网络失败/超时 | `E_NETWORK` / `E_TIMEOUT`，保留用户输入 |

## 9. 播放器实现方案

### 9.1 引擎选择

```
format === 'hls'
  ├─ 原生支持 (video.canPlayType('application/vnd.apple.mpegurl') !== '') → VideoEngine（原生）
  └─ 否则 → HlsEngine（hls.js，动态 import，独立 chunk）
format === 'mp4' | 'webm' → VideoEngine
format 未知 → 按 URL 后缀 guessFormatFromUrl()；仍未知 → 先试 MP4，触发 error 再报 E_UNSUPPORTED_FORMAT
```

- hls.js 配置：`{ enableWorker: true, lowLatencyMode: false, backBufferLength: 30, maxBufferLength: 30, capLevelToPlayerSize: true, xhrSetup: 注入 headers }`。
- 原生 HLS：`video.src = url`，无法注入 headers（首版接受该限制，站点源优先走 hls.js）。
- 多码率：`hls.levels` → 清晰度列表（按 `height` 命名 `1080p/720p/...`，`auto` 为 `currentLevel = -1`）。
- 错误恢复：`Hls.Events.ERROR` → `NETWORK_ERROR` 先 `startLoad()` 重试 1 次；`MEDIA_ERROR` → `recoverMediaError()` 1 次；仍失败 → `error` 事件（映射 `E_NETWORK`/`E_DECODE`）。
- 切换线路/清晰度：hls.js `currentLevel`；换线路则重建实例并 `seek` 到原位置。

### 9.2 字幕

1. 轨道来源：`PlaybackSource.subtitles`（适配器返回）、`resolvePlay` 后 UI 允许 `addLocalSubtitle(file)`。
2. `srt` → `SrtConverter.toVtt(text)`（纯函数）：处理 BOM、`\r\n`、`00:00:01,500 --> 00:00:03,000`、多行文本、HTML 标签保留；输出 WebVTT。
3. 注入：`URL.createObjectURL(new Blob([vtt], {type:'text/vtt'}))` → `<track src kind="subtitles" srclang label>` → `textTracks[i].mode='showing'`；切换时先 `hidden` 再 `showing`。
4. 渲染与偏移：**不使用浏览器原生字幕渲染与 `<track>` cue 平移**（原生渲染无法自定义字号/背景，cue 平移会破坏 OriginalTime）。做法：
   - `SubtitleManager` 自行解析 VTT 文本为 `Cue[]`（`{ startSec, endSec, text }`），按 `startSec` 升序存放；
   - `<track>` 仅用于把文件交给浏览器解析的备选路径，**首版不使用**；
   - 渲染：在 `timeupdate`（约 4Hz）中用二分查找命中 `currentTime + offsetSec` 落在哪个 cue，命中则把 `cue.text` 显示在 `SubtitleOverlay`（`PlayerSurface` 内的绝对定位层，`pointer-events: none`）；
   - 样式（字号/颜色/背景）通过 CSS 类作用于 overlay，完全可控；
   - `offsetSec` 变化无需重建任何对象，仅影响查找时的时间基准，满足 AC-44/AC-45 与 FR-19 的偏移设置。
5. 编码：`TextDecoder('utf-8', {fatal:true})` 失败时尝试 `gbk`；都失败 → `E_PARSE`（"字幕编码无法识别"），播放继续。
6. 失败不阻断：字幕错误仅 Toast + 轨道标记不可用（AC-46）。

### 9.3 手势映射（`GestureRecognizer`）

| 手势 | 判定 | 行为 | 反馈 |
| --- | --- | --- | --- |
| 单击 | 位移 < 8px 且时长 < 300ms | 切换控制条 | 无 |
| 双击 | 两次 tap 间隔 < 300ms | 播放/暂停 | 中央图标闪烁 |
| 水平拖动 | `|dx| > 8px` 且 `|dx| > 1.5*|dy|` | seek：`delta = dx / width * seekMaxSec * sensitivityFactor`（low 0.6 / medium 1.0 / high 1.5，默认 `seekMaxSec=90`）；松手才真正 `seek`，拖动中仅更新 HUD 与预览时间（钳制 0~duration） | HUD "快进 00:32 / 后退 00:18" |
| 右半区垂直拖动 | 起点 x > width/2，`|dy| > 8px` 且 `|dy| > 1.5*|dx|` | 音量：`delta = -dy / height * 100`，`clamp(0,100)` | HUD 音量条 + 数值；0 显示静音 |
| 左半区垂直拖动 | 起点 x ≤ width/2 | 亮度（画面遮罩）：同上，`clamp(0,100)`，映射到 `dim = 100 - value*0.8`（最低保留 20% 亮度） | HUD 亮度条 |
| 长按 | 500ms 无位移 | 临时倍速 `settings.gesture.longPressRate`（默认 2.0），松手恢复 | HUD "2x 快进中" |

- 手势层 `GestureLayer` 位于控制条下方（`z-index` 更低），控制条可见时按钮点击优先。
- 使用 Pointer Events（`pointerdown/move/up/cancel`）+ `touch-action: none`；区分多指（>1 指忽略）。
- 单元测试直接测 `GestureRecognizer`（纯类，输入事件序列 → 输出 intent）。

### 9.4 断点续播写回

| 触发 | 行为 |
| --- | --- |
| 每 5s（`timeupdate` 采样） | `historyService.saveProgress`（异步，不阻塞） |
| `pause` / `seeking` 结束 | 立即写回 |
| 页面 `beforeRouteLeave` / `pagehide` | `flushProgress()` 后 `destroy()` |
| App 后台（`deviceService.onAppStateChange('background')`） | `pause()` + `flushProgress()` |
| 播放结束 | 写 `positionSec=0, finished=true`（若 `autoPlayNext` 且有下一集则直接切集） |

- 写入前 `if (!Number.isFinite(duration) || duration <= 0) return`。
- 起播恢复：`startPositionSec > 5% 且 < 95%` 才 seek；否则从 0。
- 连续写库节流：`ProgressReporter` 内部 `lastWriteAt`，最小间隔 4s（避免与 5s 冲突产生双写）。

### 9.5 全屏、横竖屏与安全区

- 全屏 = CSS `position:fixed; inset:0; z-index:1000` + `deviceService.setStatusBarVisible(false)`（原生）+ `lockOrientation('landscape')`；退出恢复。
- 保持屏幕常亮在播放中开启（`keepAwake(true)`），离开关闭。
- 安全区：`padding: env(safe-area-inset-top/right/bottom/left)`；PlayerControls 在横屏时左右留出刘海区。
- Android 返回：`deviceService.onBackButton` → 全屏则退全屏返回 true；否则 `router.back()`。
- 竖屏播放页：视频 16:9 顶部居中，下方为标题/剧集/下载入口（保留滚动）。

### 9.6 后台 / 锁屏 / 音频焦点

- 首版**不做**后台音频与画中画。App 进入后台 → `pause()` + `flushProgress()`；回前台 → 显示 `NextEpisodePrompt` 风格浮层"继续播放 / 退出"，用户确认才继续。
- 锁屏同上（Web 的 `visibilitychange` 兜底）。
- 音频焦点丢失（Android 通话/其他 App 播放）：WebView 触发 `pause` 事件 → 视为用户暂停，记录进度；恢复后不自动播放。
- 唤醒锁：`keepAwake` 使用 `@capacitor/keep-awake`（`KeepAwake.keepAwake()/allowSleep()`）；Web 走其内置的 Screen Wake Lock 实现，能力不可用时静默降级。

### 9.7 起播与错误重试

- 调用链：`PlayerView` → `libraryStore.resolvePlay(mediaId, episodeId, lineId)` → `libraryService.resolvePlay`（内部优先本地下载）→ 得到 `PlaybackSource` → `PlayerController.load({ playback, startPositionSec, episodes, resolveEpisode })`。
- `load()` 内部顺序：选择引擎 → `attach` → `loadedmetadata`（超时 15s）→ `seek`（如需）→ `play()`。
- 网络错误自动重试 1 次（1s 后），重试前重建 hls 实例（若使用 hls.js）。`resolvePlay` 失败（如地址过期）由 store 重新解析一次后再调 `load`，播放器本身不重复解析。
- 错误映射表集中在 `shared/errors.ts` 的 `ERROR_MESSAGES`（AC-60 单测对象）。

### 10.4 系统投屏 / 分享 Intent

自定义插件 `CastShare`（`android/app/src/main/java/com/qoder/cinema/CastSharePlugin.java`）：

```java
@CapacitorPlugin(name = "CastShare")
public class CastSharePlugin extends Plugin {
  @PluginMethod public void shareFile(PluginCall call) { /* FileProvider.getUriForFile + ACTION_SEND + createChooser */ }
  @PluginMethod public void shareUrl(PluginCall call)  { /* ACTION_SEND text/plain */ }
}
```

- `FileProvider` authorities：`${applicationId}.fileprovider`，`file_paths.xml` 暴露 `files-path` 与 `cache-path`。

- JS 侧 `src/native/castPlugin.ts` 用 `registerPlugin<CastSharePlugin>('CastShare')`，Web 实现 `isSupported=false`。

## 12. 风险与缓解

| # | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| R1 | **CORS**：浏览器直连用户源被拦 | Web 端部分源不可用 | 原生启用 `CapacitorHttp`（patch fetch/XHR）；hls.js 走 XHR 可注入 headers；Web 端在错误文案中明确"CORS/需后端代理"，并提供演示源作为兜底；文档说明 Web 仅调试用 |
| R2 | **站点源接口失效/变更** | 播放失败、体验差 | 适配器隔离 + 统一 `SourceHealth` + 播放页"换线路/换源"；失败自动重试 1 次；不做自动抓取，减少被封风险 |
| R3 | **HLS 兼容性**（Android WebView 无原生 HLS、编码不支持） | 黑屏/无法播放 | hls.js 兜底 + `canPlayType` 检测；`MEDIA_ERROR` 恢复；`E_DECODE` 明确提示；演示源同时提供 MP4 与 HLS 用于验证 |
| R4 | **大文件下载**（内存、断点、限速） | OOM / 下载失败 | 流式读取（ReadableStream）+ 1MB 分片写；Web 单文件 >1GB 前置提示；Range 续传；并发 ≤3；每 2s 落库进度 |
| R5 | **IndexedDB 容量/清退** | 数据丢失、写入失败 | `navigator.storage.persist()` 申请持久化；配额错误映射 `E_STORAGE_QUOTA` 并引导清理；历史 500 上限；Blob 与元数据分表便于单独清理 |
| R6 | **凭据安全** | 备份泄露 Token | 默认脱敏导出；UI 掩码；不打印日志；仅本机存储（不做加密，首版接受；二期可用 WebCrypto） |
| R7 | **后台播放/下载被系统杀** | 下载中断 | 首版明确"前台下载"，切后台暂停并保存进度；回前台自动恢复（设置项）；文档与 UI 说明 |
| R8 | **播放地址过期**（AList/Jellyfin 直链有时效） | 播放中断 | `PlaybackSource.expiresAt`；播放错误时自动重新 resolve 一次再重试；下载前校验 HEAD |
| R9 | **WebDAV/AList 协议差异** | 适配器兼容问题 | 只支持最小公共集；`testConnection` 明确错误；适配器单测用固定 fixture |
| R10 | **两包并行契约漂移** | 集成失败 | 类型文件冻结 + 首日 stub + mock + 每日联调；API 变更必须走 PM 退回流程 |
| R11 | **合规风险** | 法律/商店风险 | 不内置片源；订阅导入仅解析用户提供内容；敏感词提示；合规声明版本化；不实现破解/DRM |
| R12 | **Android 10 与 14 行为差异**（存储、通知、后台） | 兼容问题 | 不使用分区存储外路径；不依赖后台服务；两台真机验收（AC-53） |

## 13. 工程约定

- 命名：文件 `PascalCase.vue` / `camelCase.ts`；类型 `PascalCase`；常量 `UPPER_SNAKE`；事件 `domain:action`。
- 导入顺序：类型 → 第三方 → 内部；统一 `@/` 别名。
- 禁止：UI 直接 `indexedDB`/`fetch` 源地址；数据层 `import` 任何 `.vue`。
- 错误：一律 `throw new AppError(code, message, { detail, retryable, httpStatus })`；UI 只读 `code/message`。
- 日志：`logger.debug` 仅开发；生产不打印 URL 中的 token 参数。
- 提交：一文件一职责；契约文件变更需单列 commit 并在 PR 描述标注。

## 17. 线路质量管理（v1.2 / CHG-05）

> 本章为 **v1.2 增量契约**，与第 4/6/7 章既有条目**并存**，不修改任何既有签名与编号。

### 17.1 背景与合规前提

用户提供了一批第三方 TVBox 订阅地址（49 条），实测分布：

| 实测结果 | 条数 | 对应契约分类（17.7） |
| --- | --- | --- |
| 200 且返回可解析的 TVBox JSON | 16 | 成功（`health = ok`） |
| 200 但返回 HTML / BMP / PNG / 纯文本 | 19 | `E_FORMAT_UNSUPPORTED`（分类标签，落码为 `E_UNSUPPORTED_FORMAT`）→ `bad_config` |
| 401 / 403 | 4 | `E_AUTH` → `auth_failed` |
| 404 | 2 | `E_HTTP_404` → `unreachable` |
| 超时 / DNS 失败 | 7 | `E_NETWORK` → `timeout` / `unreachable` |

> 上表合计 48 条，剩余 1 条实测记录未单独归类；不影响本章分级口径（口径只依赖 `SourceHealth` + `latencyMs`）。

**合规前提（不可协商）**：按 FR-46 / AC-105，App **不内置、不分发任何第三方线路或订阅地址**。本批 49 条地址**一条都不进仓库、不进打包产物、不进演示数据**。本章交付的是"用户自行导入后，能否看清线路质量、能否少踩坑"的能力；质量数据全部来自用户本机对用户自己配置的源所做的探测，不上传、不共享、不预置排行榜。

**能力边界**：不新增任何抓取/探测目标；探测目标恒等于用户已配置且已启用的源（与 FR-07 一致），不做后台定时轮询。

### 17.2 延迟分级（`src/shared/healthTier.ts`）

#### 17.2.1 契约

新建 `src/shared/healthTier.ts`（**唯一新增文件**），导出如下，**全部为纯函数/常量，无 IO、无 DOM、无 Pinia 依赖**：

```ts
import type { Source, SourceHealth } from '@/types';

/** 阈值常量（毫秒）。单测直接断言本对象，禁止在组件内写魔法数 */

  /** ≤ 300ms → fast */
  fastMaxMs: 300,
  /** 301 ~ 800ms → good */
  goodMaxMs: 800,
  /** 801 ~ 2000ms → fair */
  fairMaxMs: 2000,

/** 档位中文文案（HealthBadge / 排序菜单 / 无障碍标签共用） */
export const HEALTH_TIER_LABELS: Record<HealthTier, string> = {

  fast: 0,

/* ---------- 排序（17.4） ---------- */
```

#### 17.2.2 判定顺序（**必须按此顺序短路**，保证可单测）

| 步骤 | 条件 | 结果 |
| --- | --- | --- |
| 1 | `health === 'unknown'` | `unknown`（即使传了 `latencyMs` 也不升级） |
| 2 | `health !== 'ok'`（`auth_failed` / `timeout` / `unreachable` / `bad_config`） | `bad` |
| 3 | `latencyMs` 不可用：`null` / `NaN` / `Infinity` / `< 0` / 非 `number` | `bad` |
| 4 | `0 ≤ latencyMs ≤ HEALTH_TIER_THRESHOLDS.fastMaxMs`（300） | `fast` |
| 5 | `≤ HEALTH_TIER_THRESHOLDS.goodMaxMs`（800） | `good` |
| 6 | `≤ HEALTH_TIER_THRESHOLDS.fairMaxMs`（2000） | `fair` |
| 7 | 其余（`> 2000`） | `slow` |

阈值表（边界值即断言点）：

| tier | 文案 | 条件（精确） |
| --- | --- | --- |
| `fast` | 极速 | `ok` 且 `0 ≤ latencyMs ≤ 300` |
| `good` | 快速 | `ok` 且 `301 ≤ latencyMs ≤ 800` |
| `fair` | 一般 | `ok` 且 `801 ≤ latencyMs ≤ 2000` |
| `slow` | 较慢 | `ok` 且 `latencyMs ≥ 2001` |
| `bad` | 异常 | `health ∉ {ok, unknown}`，或 `ok` 但延迟不可用 |
| `unknown` | 未检测 | `health === 'unknown'` |

**设计约束**

- 阈值只能来自 `HEALTH_TIER_THRESHOLDS`，`HealthBadge.vue` / `SourceListView.vue` / 测试三处不得出现 `300 / 800 / 2000` 字面量。

### 17.4 排序

#### 17.4.1 排序模式

```ts
export type SourceSortMode = 'manual' | 'tier';
```

| 模式 | 语义 | 规则 |
| --- | --- | --- |
| `manual` | 手动排序（默认，兼容现状） | **完全沿用现有实现**：`builtin` 升序（`false` 在前）→ `sort` 升序。即演示源恒在最后 |
| `tier` | 按线路质量排序 | ① `HEALTH_TIER_ORDER[tier]` 升序 → ② `latencyMs` 升序（`null` 排在有值之后）→ ③ `sort` 升序 → ④ `name` 升序 → ⑤ `id` 升序（稳定性兜底） |

补充规则（确定性）：

- `tier` 模式**不**对 `builtin` 特判：演示源本地无网络请求，`latencyMs` 极小 → `fast`，自然靠前。此行为由 AC-108 断言。
- `name` 比较用 `a.name.localeCompare(b.name, 'zh-Hans-CN')`；仍相同按 `id` 升序，保证同一输入多次排序结果一致（可单测）。
- `latencyMs` 取自 `latencyOf(sourceId)`；返回 `null`/非有限数视为"无延迟"，排在所有有值项之后。
- `sortSources` **不修改入参**（`readonly Source[]`，内部 `[...sources].sort()`），返回新数组。

#### 17.4.2 偏好持久化（**不进 AppSettings、不改 `src/types/index.ts`**）

| 项 | 值 |
| --- | --- |
| 存储介质 | `localStorage`（WebView 同源持久） |
| key | `peanutmov.sourceSortMode`（**字面量，点号分隔**） |
| value | `'manual'` \| `'tier'`，纯字符串，不包 JSON |
| 缺省 | 读取失败 / 键缺失 / 值非法 → `'manual'` |
| 写入时机 | 用户在源管理切换排序模式时立即写入 |
| 写入失败 | `try/catch` 吞掉（隐私模式/配额），**内存态仍生效**，不 Toast、不阻断 |
| 不进 | `AppSettings`、备份文件、跨设备同步、`Source` 实体 |

> 注意：既有主题偏好使用 `peanutmov:theme`（冒号），本 key 按 PM 指定使用点号 `peanutmov.sourceSortMode`。**两者风格不一致属已知项**，本期不统一（改 key 会让已存偏好失效）；后续若要统一，须另起 CHG 并做兼容读取。

#### 17.4.3 数据来源（为什么 `sourceStore` 需要两行新增）

`Source` 实体**没有** `latencyMs` 字段（类型冻结，本期不加），延迟只在 `HealthCheckResult` 里。而 UI 按《开发任务拆分》2.2 白名单**不得 import `@/services/healthService`**，因此延迟必须由 `sourceStore` 代理（API-14 纯新增，见 17.8）：

```ts

latencyOf(sourceId: string): number | null;   // healthService.lastSnapshot()?.results[id]?.latencyMs ?? null
healthProgress: { done: number; total: number } | null;  // 订阅 sources:healthProgress（17.5）
```

`SourceListView.vue` 的 `ordered` 计算改为：

```ts
const sortMode = ref<SourceSortMode>(readSourceSortMode());
const ordered = computed(() => sortSources(sources.sources, sortMode.value, (id) => sources.latencyOf(id)));
```

`manual` 分支由 `sortSources` 内部原样实现现有 `builtin → sort` 比较，**不得**在两处各写一份。

### 17.5 批量测速

#### 17.5.1 并发与耗时

| 项 | 旧值 | 新值 | 位置 |
| --- | --- | --- | --- |
| 并发上限 | 3 | **6** | `src/shared/constants.ts`：`HEALTH_CHECK_CONCURRENCY = 6` |
| 单源超时 | 3000ms | 不变 | `TIMEOUT_TEST_CONNECTION_MS` |

耗时预算（并发 6，单源 3s 硬超时）：

| 场景 | 计算 | 结果 |
| --- | --- | --- |
| 目标场景：50 源，≥40 个快速返回（≤300ms），≤10 个超时（3s） | 总工作量 ≈ 40×0.3s + 10×3s = 42s；÷ 并发 6 ≈ **7s**；再加逐源落库与事件派发开销 | **< 25s**（AC-107 断言口径，余量充足） |
| 最坏上界：50 源全部超时 | `ceil(50 / 6) = 9` 波 × 3s | **27s**（回归上界，不作 AC 失败判据） |

> 并发从 3 提到 6 的代价：探测窗口内瞬时并发 HTTP 连接数翻倍。约束：只在**用户主动触发**（进入源管理 / 点"重新检测"）时发生，无后台轮询；探测请求 `retries = 0`（`httpClient.withProbeTimeout` 已保证），单源最多 1 次请求。**不得**为提速再提高并发或缩短单源超时。

#### 17.5.2 进度事件

```ts
/* src/services/events.ts —— AppEventMap 新增一行 */
'sources:healthProgress': { done: number; total: number };
```

| 规则 | 约定 |
| --- | --- |
| 发送方 | `sourceService.checkHealth(ids?)`（唯一发送方） |
| `total` | 本次目标源数 = 启用源 ∩ `ids`；`ids === undefined` 时为全部启用源 |
| 起点 | 循环开始前发一次 `{ done: 0, total }` |
| 步进 | **每完成一个源**（`markHealth` 落库之后，无论成功/失败）发一次 `{ done: n, total }`，`n` 严格 +1 |
| 终点 | 全部完成后发一次 `{ done: total, total }` |
| 节流 | 不节流（≤ 50 次事件，同步派发开销可忽略） |
| 空集合 | `total === 0` 时只发 `{ done: 0, total: 0 }`，不发终点重复事件 |
| 去重 | `healthService.checkAll()` 的 `running` 复用期内只发一组事件，不重复发 |
| 失败 | 单源失败不改变事件节奏；`checkHealth` 整体抛错时**不发**终点事件 |

UI 显示：`sourceStore.healthProgress` 非 `null` 且 `done < total` 时，按钮文案为 `` `检测中 ${done}/${total}` ``（例：`检测中 12/49`）；`healthProgress === null`（旧路径/未开始）时沿用 `检测中…`；完成后置 `null`。

### 17.6 失效自动跳过

#### 17.6.1 目标

用户在媒体库打开某个源、而该源实际已失效（`browse` 失败）时，**不要只给一个死胡同错误页**；若本机还有可用源，自动切一次并明确告知。**绝不静默切换**（用户必须知道自己在看谁的内容）。

#### 17.6.2 触发条件（全部满足才切）

1. 场景是"打开/刷新某源第 1 页"（`libraryStore.openSource()` 或 `loadFirstPage(page = 1)`）；
2. `libraryService.browse()` 抛错，且 `code ∈ {E_SOURCE_UNAVAILABLE, E_NETWORK, E_TIMEOUT, E_HTTP_5XX, E_PARSE, E_UNSUPPORTED_FORMAT}`（**源侧故障**）；
3. **不**触发：`E_SOURCE_DISABLED`、`E_NOT_FOUND`、`E_ABORTED`、`E_CANCELED`、`E_INVALID_INPUT`、`E_NOT_IMPLEMENTED`，以及离线态（`isOnline() === false`，离线应走缓存而不是换源）；
4. 存在候选：`enabled === true && health === 'ok' && id !== failedId`；
5. 本次会话内该 `(fromId → toId)` 组合未切换过（防抖，见 17.6.4）。

#### 17.6.3 候选选择（确定性，可单测）

`libraryService` 新增只读方法（API-06 纯新增）：

```ts
/** 失效源的最佳替代源；无候选返回 null。只读，不改任何状态 */
pickFallbackSource(failedSourceId: string): Promise<Source | null>;
```

选择规则（依次比较，取第 1 个）：

1. 过滤：`enabled && health === 'ok' && type !== 'demo' && id !== failedSourceId`；
2. `healthTierOf(health, latencyOf(id))` 的 `HEALTH_TIER_ORDER` 升序；
3. `latencyMs` 升序（`null` 最后）；
4. `sort` 升序 → `id` 升序。

> **CHG-08（2026-10-24）**：候选排除内置演示源（`type !== 'demo'`）。原规则演示源仅"排最后"，
> 但在爬虫订阅大量失效的真实场景下它会成为唯一健康候选，用户每次浏览失败都被切进演示片单，
> 失效被兜底内容掩盖。改为排除后：无健康候选 → `pickFallbackSource` 返回 null →
> 按 17.6.4 第 2 步原样抛出原始错误（就地显示「该源暂不可用」，不切换）。

#### 17.6.4 动作序列与防抖

1. 先落库失败态：`sourceService.markHealth(failedId, healthOfError(error), error.toShape())`（`E_PARSE` / `E_UNSUPPORTED_FORMAT` → `bad_config`，网络类 → `unreachable`）。已有 `markSourceUnreachable` 扩展为按 `healthOfError` 映射的 `markSourceFailed`。
2. `pickFallbackSource(failedId)`；为 `null` → 不切换，**原样抛出原始错误**（不改 code、不加包装，避免既有错误语义漂移）；UI 错误态页脚补一句"可手动切换其他源"。
3. 非 `null` → `sourceStore.select(fallback.id)` → 重跑 `listCategories` + `browse(page 1)` **一次**。
4. 发 Toast（**必须**，不得静默）：
   ```ts
   appEvents.emit('toast', {
     text: `「${failed.name}」暂不可用，已自动切换到「${fallback.name}」`,
     type: 'info',
   });
   ```
   `bootstrap.bindAppToasts()` 已把 `toast` 事件桥接到 `uiStore`，无需新增 UI 订阅。
5. 切换后仍失败 → **不再切换**，抛第二次的错误；错误态页脚提示"可手动切换其他源"。

防抖规则：

| 规则 | 约定 |
| --- | --- |
| 单次链路 | 一次 `openSource()` / `loadFirstPage()` 调用链最多自动切换 **1 次**（局部 `fallbackTried` 标志） |
| 会话内 | `(fromId → toId)` 组合在 store 生命周期内最多 **1 次**；命中过则不再尝试该组合 |
| 重置 | 用户**手动**在媒体库切源（显式 `openSource(sourceId)`）时清空该源的组合记录 |
| 记录位置 | `libraryStore` 内存（`Set<string>`），**不落库、不进备份** |

**为什么不在 `libraryService.browse()` 里静默换源并返回别家的 `items`**：`PageResult<MediaItem>` 不携带 `sourceId`，静默换源会让海报墙显示 B 的内容却挂着 A 的分类与"当前源"，用户无法判断自己在看谁的内容，也违反"必须告知"。故换源动作放在持有 `currentSourceId` 的 `libraryStore`，`libraryService` 只提供候选查询。

### 17.7 TVBox 错误分类（`SiteAdapter.probe`）

#### 17.7.1 原则

- **不新增 `ErrorCode`**。`src/types/index.ts` 的 `ErrorCode` 联合类型本期不动；`tests/unit/errors.spec.ts` 的枚举断言保持全绿。
- 用户口中的"E_FORMAT_UNSUPPORTED"是**分类标签**，落到代码是既有枚举 **`E_UNSUPPORTED_FORMAT`**（注意既有枚举是 `UNSUPPORTED_FORMAT` 语序，不要新造 `E_FORMAT_UNSUPPORTED`）。
- 具体原因写 `detail`（诊断用，不直接展示给用户）；展示文案走 `message`。

#### 17.7.2 分类表

| 实测现象 | 分类标签 | 抛出 code（既有枚举） | `message`（用户可见） | `detail`（诊断） | `SourceHealth` |
| --- | --- | --- | --- | --- | --- |
| 200 + 合法 JSON 且含 `list`/`class` | —（成功） | — | — | — | `ok` |
| 200 + `Content-Type` 含 `text/html` 但响应体是合法 TVBox JSON | —（成功，CHG-06） | — | — | — | `ok` |
| 200 + `Content-Type` 含 `text/html` 且响应体是 HTML 落地页 | `E_FORMAT_UNSUPPORTED` | `E_UNSUPPORTED_FORMAT` | 该地址返回的不是订阅 JSON，可能是网页地址或已被拦截 | `响应不是合法 JSON（前 80 字符：<!doctype html…）` | `bad_config` |
| 200 + `Content-Type` 含 `image/`（BMP/PNG 等） | `E_FORMAT_UNSUPPORTED` | `E_UNSUPPORTED_FORMAT` | 同上 | `响应为图片（Content-Type: image/png）` | `bad_config` |
| 200 + 非 JSON 文本（`JSON.parse` 失败） | `E_FORMAT_UNSUPPORTED` | `E_UNSUPPORTED_FORMAT` | 同上 | `响应不是合法 JSON（前 80 字符：…）` | `bad_config` |
| 200 + JSON 但既非数组也无 `list`/`class` | `E_FORMAT_UNSUPPORTED` | `E_UNSUPPORTED_FORMAT` | 该地址返回的 JSON 不是 TVBox 订阅格式（缺少 list/class 字段） | `顶层键：code,msg` | `bad_config` |
| 401 | `E_AUTH` | `E_AUTH` | 认证失败，请检查账号或 Token | `HTTP 401` | `auth_failed` |
| 403 | `E_AUTH` | `E_HTTP_403` | 无权限访问(403) | `HTTP 403` | `auth_failed` |
| 404 | `E_HTTP_404` | `E_HTTP_404` | 资源不存在(404) | `HTTP 404` | `unreachable` |
| 超时（> 3s 探测窗口） | `E_NETWORK` | `E_TIMEOUT` | 请求超时，请稍后重试 | `探测超过 3000ms` | `timeout` |
| DNS / 连接失败 | `E_NETWORK` | `E_NETWORK` | 网络不可用，请检查网络后重试 | `Failed to fetch` | `unreachable` |

> **CHG-06（2026-10-23）**：`Content-Type: text/html` 不再单独作为拒收依据。实测 17 个 CMS 采集站（`scripts/fixtures/cms-alive.json`）全部返回 `text/html;charset=utf-8`，但响应体是完全合法的 TVBox JSON（Cloudflare 代理/未设置 MIME 的常见特征）；按原规则会 100% 误判为 `bad_config`。现改为**只以响应体能否解析为合法 TVBox JSON 为准**，`image/` 与真正的 HTML 落地页仍会被拒。AC-111 的判定不变——真正的 HTML 响应依旧落到 `E_UNSUPPORTED_FORMAT`。

`SourceHealth` 列由既有 `healthOfError()`（`src/sources/base/BaseAdapter.ts`）自动得出，**不新增映射**：`E_UNSUPPORTED_FORMAT`/`E_PARSE` → `bad_config`，`E_AUTH`/`E_HTTP_401`/`E_HTTP_403` → `auth_failed`，`E_TIMEOUT` → `timeout`，`E_NETWORK`/`E_HTTP_404`/`E_HTTP_5XX` → `unreachable`。

#### 17.7.3 实现约束

1. 分类在 `SiteAdapter.request()` 内统一完成（`probe` / `browse` / `search` / `getDetail` 共用），避免只修健康检查而浏览链路仍报"数据解析失败"。
2. `httpClient` 抛出的 `E_PARSE`（detail `响应不是合法 JSON` / `响应体为空`）在 `SiteAdapter` 内**包装**为 `E_UNSUPPORTED_FORMAT`，保留原 `detail` 与 `cause`；**不得**改 `httpClient` 的 `E_PARSE` 语义（其它适配器依赖它）。
3. 为拿到 `Content-Type`，`request()` 改用 `httpClient.requestWithMeta`（已导出，签名不变）；拿不到响应头（如 CORS 限制）时退化为 `JSON.parse` 结果判定，`detail` 写 `Content-Type 不可读`。
4. `E_UNSUPPORTED_FORMAT` 为不可重试错误，`httpClient` 不会重试；探测窗口内 `effectiveRetries` 本就为 0，**不新增请求**。
5. `message` 文案只允许上表中的 6 句（format 类四条共用一句；401/403/404/超时/网络各一句），**不得**把 HTML 片段或响应体塞进 `message`。
6. 错误分类不改变 `SiteAdapter` 的成功路径：合法 JSON 的解析、字段映射、播放地址规则（7.6）全部不变。
