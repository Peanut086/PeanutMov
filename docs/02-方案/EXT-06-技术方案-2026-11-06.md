#### 3.1.2 `epgSourceService.add(input)` — FR-66

| 名称 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | `string` | 是 | trim 后 1~20 字符，否则 `E_INVALID_INPUT` |
| `endpoint` | `string` | 是 | 必须 `http(s)://`；与现有源去重（完全相等） |
| `protocol` | `'auto' \| 'diyp' \| 'xmltv'` | 否 | 默认 `auto` |
| `matchMode` | `'auto' \| 'channel-name' \| 'xmltv-id'` | 否 | 默认 `auto` |
| `sampleChannel` | `{ name: string; tvgId?: string \| null }` | 否 | 探测用样本频道；缺省取 `"CCTV1"` |

- 行为：先校验 → 再探测（单请求，8s 超时，`retries: 0`）→ 解析 ≥1 条节目才落库；`priority = max(priority)+1`；上限校验（用户源 ≤10、启用 ≤5）。
- 响应：`EpgSource`（同 3.1.1 单项）。
- 探测失败：不落库、不占优先级，错误码见 3.1.7。

#### 3.1.3 `epgSourceService.update(id, patch)` / `remove(id)` / `reorder(ids)` — FR-66

| 名称 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `patch.name` | `string` | 否 | 同 add 校验 |
| `patch.endpoint` | `string` | 否 | 变更后需重新探测成功才保存 |
| `patch.protocol` | `EpgProtocol` | 否 | 变更 → 清该源缓存 |
| `patch.matchMode` | `EpgMatchMode` | 否 | 变更 → 清该源缓存 |
| `patch.enabled` | `boolean` | 否 | 启用数超 5 → `E_INVALID_STATE` |
| `ids`（reorder） | `string[]` | 是 | 必须与现有 id 全集完全相同（长度与元素），否则 `E_INVALID_INPUT`；按下标重写 `priority = index+1` |

- `remove(id)`：`builtin=true` → `E_INVALID_STATE`；否则删记录 + `clearSourceCache(id)`；引用该源的提醒由 `reminderService` 在读取时标记 `epgSourceId=null`（不删提醒）。
- 响应（remove）：`{ "removed": true, "clearedCacheKeys": 12 }`

#### 3.1.5 `epgService.programmesFor(channel, date)` — FR-67（核心）

- 用途：按优先级合并多源，返回某频道某日的节目单与命中信息。
- 请求参数

| 名称 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `channel.name` | `string` | 是 | 频道名（m3u 逗号后名称 / txt 首列） |
| `channel.tvgId` | `string \| null` | 否 | 来自 `liveExtras`（m3u `tvg-id`） |
| `channel.tvgName` | `string \| null` | 否 | 来自 `liveExtras`（m3u `tvg-name`） |
| `date` | `Date` | 否 | 默认今天；按设备本地时区取日期键 |
| `options.sourceIds` | `string[]` | 否 | 仅查指定源（`programmes()` 兼容封装用） |
| `options.allowStale` | `boolean` | 否 | 默认 `true`：源不可达时返回过期缓存并置 `stale=true` |

- 响应结构（完整示例）

```json
{
  "channel": { "name": "CCTV-1 综合", "tvgId": "cctv1", "tvgName": "CCTV1" },
  "channelKey": "id:cctv1",
  "date": "2026-11-06",
  "programmes": [
    {
      "start": "20:00",
      "end": "20:30",
      "title": "新闻联播",
      "desc": "时事政治报道",
      "startSec": 72000,
      "endSec": 73800,
      "startAt": 1793697600000,
      "endAt": 1793699400000,
      "key": "1793697600000:新闻联播",
      "sourceId": "epg_9f2c1a"
    }
  ],
  "matchedSource": { "id": "epg_9f2c1a", "name": "备用 EPG", "matchLevel": 1 },
  "stale": false,
  "errors": [
    { "sourceId": "epg-builtin", "code": "E_TIMEOUT", "message": "请求超过 8000ms 未完成" }
  ]
}
```

- 合并算法（契约级）：
  1. 读取启用源，按 `priority` 升序；
  2. 逐源判定匹配级别（L1 `tvgId` === XMLTV `channel id`；L2 `tvgName` === `display-name`；L3 `normalize(name)` 相等 → 该源内的 EPG 频道 ID，随后按该 ID 拉取当日节目）；
  3. 第一个"匹配成功且当日节目非空"的源胜出并返回，后续源不再请求（提前终止）；
  4. 全部未命中/no-data → `programmes: []`、`matchedSource: null`；
  5. 同源内 `(startAt,title)` 去重；按 `startAt` 升序；
  6. 缓存键 `${prefix}:${sourceId}:${channelKey}:${date}`（`prefix='epgv2'`），TTL 24h；失败不写缓存。
- 并发：全局 in-flight 表（`Map<cacheKey, Promise<...>>`）+ 并发闸门 ≤3；同一 key 并发调用共享同一 Promise。

#### 3.1.6 `epgService.prefetch(channels, date, limit = 30)` / `clearSourceCache(sourceId)` — FR-67

- `prefetch`：对"收藏频道 + 当前可见分组前 N 个"去重后取 ≤30 个，按 3 并发逐批调用 `programmesFor`；失败静默（仅日志）。响应 `{ "requested": 30, "ok": 27, "failed": 3, "elapsedMs": 1840 }`。
- `clearSourceCache(sourceId)`：按前缀删除 `epgCache` 中该源条目（游标扫描 `key.startsWith(prefix)`），返回删除条数。

#### 3.1.6.1 兼容封装：`programmes(channel, date?, endpoint?)` — FR-55 回归

- 保持既有签名与返回类型 `Promise<EpgProgramme[]>`；内部**只走单源路径**：`endpoint`（缺省 `EPG_DEFAULT_ENDPOINT`）作为临时源参与匹配，不落 `epgSources`、不参与多源合并；缓存键改用 `epgv2:builtin:<channelKey>:<date>`。
- `LiveView` / `EpgView` 改为调用 `programmesFor`；`programmes()` 仅保留给兼容调用与单测（AC-170 门禁）。
- `nowPlaying` / `upNext` 一行不改（仍按 `startSec/endSec` 与当天秒偏移判定）。

#### 3.1.7 错误码（API-20）

| 错误码 | 触发场景 | 用户文案来源 |
| --- | --- | --- |
| `E_INVALID_INPUT` | 名称为空/超长、URL 非 http(s)、重复端点、优先级集合不一致、未知占位符 | `ERROR_MESSAGES.E_INVALID_INPUT` / 具体 detail |
| `E_PARSE` | 探测响应既非 diyp JSON 也非 XMLTV，或解析出 0 条节目 | 建议 detail："该地址没有可解析的节目单" |
| `E_TIMEOUT` | 探测/拉取超过 8s（探测）/ 6s（拉取） | 既有文案 |
| `E_NETWORK` | 连接失败、DNS 失败 | 既有文案 |
| `E_NOT_FOUND` | 端点 404 | 既有文案 |
| `E_INVALID_STATE` | 删除内置源、启用数 >5、全部源停用后仍请求 | "当前状态不允许该操作" |
| `E_DB` | IDB 读写失败 | 既有文案 |

| 方法 | 请求 | 响应 |
| --- | --- | --- |

| `reorderGroups(liveSourceId, groupIds)` | `string[]`（须为现有全集） | `{ "order": ["g_2","g_1"] }` |

### API-22 `reminderService`（节目提醒）— FR-71

#### 3.3.1 `upsert(input)` — FR-71

| 名称 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `liveSourceId` | `string` | 是 | 所属直播源 |
| `epgSourceId` | `string \| null` | 否 | 命中源；无则 `null` |
| `channelKey` | `string` | 是 | `channelKeyOf()` 结果 |
| `channelName` | `string` | 是 | 通知展示用 |
| `programmeKey` | `string` | 是 | `${startAt}:${title}` |
| `programmeTitle` | `string` | 是 | 通知展示用 |
| `startAt` | `number` | 是 | epoch ms；`startAt <= now` → `E_INVALID_STATE` |
| `endAt` | `number` | 是 | epoch ms |
| `leadMinutes` | `0 \| 5 \| 10 \| 15 \| 30` | 否 | 默认 5 |

- 唯一键：`id = r_${hash(channelKey + ':' + startAt)}`（确定性，重复设置落到同一记录）。
- `notifyAt = startAt - leadMinutes*60000`；若 `notifyAt <= now` 且 `startAt > now` → 立即排期到 `now + 5s`（不拒绝，避免"提前量选大了"直接失败）。
- 上限：非终态（`scheduled`）≤50 → 超出 `E_INVALID_STATE`。
- 响应（完整示例）

```json
{
  "id": "r_1f3c9a2b",
  "liveSourceId": "live_a1b2",
  "epgSourceId": "epg_9f2c1a",
  "channelKey": "id:cctv1",
  "channelName": "CCTV-1 综合",
  "programmeKey": "1793697600000:新闻联播",
  "programmeTitle": "新闻联播",
  "startAt": 1793697600000,
  "endAt": 1793699400000,
  "leadMinutes": 5,
  "notifyAt": 1793697300000,
  "state": "scheduled",
  "nativeId": 2011797813,
  "lastError": null,
  "createdAt": 1793600500000,
  "updatedAt": 1793600500000,
  "native": { "scheduled": true, "permission": "granted" }
}
```

#### 3.3.2 `list()` / `cancel(id)` / `cancelByChannel(channelKey)` / `cancelBySource(liveSourceId)` — FR-71

- `list(opts?: { state?: ReminderState; from?: number })` → `{ "reminders": [ ...同 3.3.1 ] }`，按 `notifyAt` 升序；读取时把 `epgSourceId` 已不存在的项改成 `null`（不落库，仅返回标记 `orphanEpgSource`）。
- `cancel(id)`：删记录 + `notificationScheduler.cancel(nativeId)`；返回 `{ "canceled": true }`。
- `cancelByChannel` / `cancelBySource`：批量，返回 `{ "canceled": n }`（直播源删除时级联调用）。

#### 3.3.3 `reconcile(now?)` / `syncNative()` — FR-71

- `reconcile`：启动 + `onAppStateChange('active')` 触发；对 `scheduled` 项：
  - `now > startAt + REMINDER_GRACE_MS(10min)` 且未触发 → `missed` + 取消原生；
  - `now >= notifyAt` 且 `now <= startAt + grace` → 标记 `firing`（由前台提示消费）并在 60s 内转为 `fired`；
  - 其余保持 `scheduled`，若 `|notifyAt - 原排期| > 60s`（时区/校时导致）→ 重新排期。
  - 响应：`{ "checked": 12, "fired": 1, "missed": 0, "rescheduled": 0, "elapsedMs": 84 }`
- `syncNative`：全量对齐（先 `getPendingIds()` 取原生待触发，取消列表中不存在的、补齐缺失的）。响应：`{ "scheduled": 12, "canceled": 1, "permission": "granted" }`。

#### 3.3.4 `onNativeReceived(cb)` — FR-71

- 订阅原生 `localNotificationReceived` 与 `localNotificationActionPerformed`；收到时按 `nativeId`→`reminder.id` 反查，更新状态；点击动作携带 `extra.route = '/live?source=<id>&channel=<name>'`，由 UI 路由跳转（不自动播放）。

错误码：`E_INVALID_INPUT`（提前量非法/字段缺失）、`E_INVALID_STATE`（节目已开始、超过 50 条）、`E_NOT_FOUND`（取消失败）、`E_DB`。原生权限失败**不是错误**，以 `native.permission='denied'` 返回并落 `lastError`。

    tx.objectStore('epgCache').clear();

    // 内置默认源（不可删除）

## 5. 关键技术决策

### D-07 多源合并 = 按优先级整段采用 + 4 级确定性匹配

- **决策**：第一个"匹配成功且当日有节目"的源独占该频道当日结果；匹配按 L1 `tvg-id`→L2 `tvg-name`→L3 归一化名称，命中即停，无模糊算法。
- **理由**：可解释（UI 显示"来源 + L1/L2/L3"）、可验收（AC-157/158 可写成纯函数断言）、错配不可见风险最低；回看地址按命中源与节目时间渲染，节目级混拼会拼出跨源的错误地址。
- **被否决**：① 节目级时间轴拼接（广告插播与边界误差不可判定）；② 每节目多源择优（两源同一节目标题不同，无法判定"更优"）；③ 编辑距离/包含匹配（会把"湖南卫视"匹配到"湖南卫视国际"，进而拼错回看 URL）。

### D-08 频道扩展属性用旁路解析，**不修改** `liveParsers`

- **决策**：新增 `src/sources/live/liveExtras.ts`，对同一份 m3u 文本做第二次扫描，输出 `LiveChannelExtrasMap`（key = 频道 URL），提供 `tvg-id`/`tvg-name`/`catchup*`；`parseM3u`/`parseLiveTxt`/`groupChannels`/`detectLiveFormat`/`parseLiveList` 一行不改。
- **理由**：`LiveChannel` 加字段会让 `tests/unit/liveParsers.spec.ts:38-47` 的 `toEqual` 整对象断言失败，违反"既有解析逻辑不得破坏"的硬约束；旁路映射对 txt 源天然为空（`?` 兜底），降级路径简单。
- **被否决**：① 在 `parseM3u` 内返回 `tvgId`（破坏既有断言，迫使评审改测试基线）；② 把 extras 写进 `lives` store（直播源内容高频变化，会引入无谓写库）；③ 用正则二次匹配 `#EXTINF` 与 URL 行配对（无法处理 `#EXTVLCOPT` 等中间行，故采用"行序配对 + 跳过注释行"的状态机，与 `parseM3u` 同构但独立实现）。

### D-09 回看地址 = 声明式模板 + 12 token（9 组语义），无表达式

- **决策**：模板只支持白名单占位符，渲染是纯字符串替换 + 严格编码校验；源级模板 + 频道级 `catchup-source` 覆盖。
- **理由**：可校验（未知占位符保存即拒绝）、可测试（AC-163 4 类样本 + 占位符全覆盖）、无执行风险（不 eval、不引入模板引擎依赖）；12 个 token 覆盖查询参数式/路径式/UTC/秒偏移式四类主流方言，成对 token（`start/end`、`utc/utcend`、`startSec/durationSec`）保证"起止必须成对"的方言也能表达。
- **被否决**：① JS 表达式模板（`new Function` 等于把用户配置当代码执行，安全与可维护性都不可接受）；② 每源硬编码适配器（新方言要发版）；③ 引入 mustache/Handlebars（体积与能力都超出需求，且允许嵌套逻辑）。

### D-10 提醒 = LocalNotifications 预定 + 启动/回前台 reconcile

- **决策**：每条提醒预定一条原生通知（`nativeId` 稳定派生），App 启动与回前台按 `notifyAt` 校准；不引入 WorkManager，不常驻定时器。
- **理由**：插件已在依赖中（`@capacitor/local-notifications@7`），与 `backupScheduler.syncNativeReminder()` 完全同模式（权限检查 → 取消旧排期 → 重新 schedule）；满足"App 未运行也能触达"的需求，且与 Q-05 的"不常驻定时器"口径一致。
- **被否决**：① WorkManager/原生 AlarmManager 自建插件（新增原生面 + 国产 ROM 功耗限制，收益不抵成本）；② App 内 `setInterval`（进程被杀即失效，无法满足 AC-168）；③ 每条提醒一个前台服务（通知栏常驻、耗电，用户不可接受）。

### D-11 分组/排序 = 每源一条 `channelPrefs` 记录；探测结果进 kv

- **决策**：`channelPrefs` 以 `liveSourceId` 为主键，`orders` 用 `scopeKey → channelKey[]` 整表覆盖写入；回看探测结果放 kv（`live-catchup-probes`），不落 store。
- **理由**：分组/排序是"每源一份配置"，一条记录读写即一次事务，200 频道写入 ≤100ms；探测结果是带 TTL 的临时数据，kv 与 `cacheRepo` 的设计意图一致。
- **被否决**：① 每频道一条记录（200 条记录 + 顺序字段，排序要写 200 次）；② 塞进 `AppSettings`（settings 走"整体覆盖/深合并"语义，大批量顺序数组会放大每次设置的写放大，且备份 schema 冲突）；③ 探测结果进 `epgCache`（键语义不同，TTL 也不同）。

### D-12 `epgCache` 键空间升级 + v4 升级时清空

- **决策**：缓存键由 `${channel}:${date}` 改为 `epgv2:${sourceId}:${channelKey}:${date}`；v3→v4 升级时 `tx.objectStore('epgCache').clear()`。
- **理由**：多源必须把源维度纳入键，否则 A/B 源互相覆盖；旧键在新代码下永不命中，会永久占用空间（`cacheRepo` 只在读时删过期项），因此必须主动清空；该 store 是纯缓存，清空不影响功能正确性。
- **被否决**：① 保留旧键并兼容读取（旧键没有源维度，读出来就是错数据）；② 写一次性迁移脚本把旧记录转成新键（无法补出 sourceId，只能标成内置源，收益低于成本）；③ 升级时删除并重建 store（违反"升级只做加法"的既有规则）。

### D-13 回看播放 = 新 `ReplayView` + 复用 `HlsEngine`/`VideoEngine`

- **决策**：新增 `/live/replay` 路由与 `ReplayPlayer.vue`，直接复用引擎 + `SeekBar.vue`；不经过 `PlayerController`，不写观看历史/进度。
- **理由**：`PlayerController` 绑定 `media/episodes/lines` 模型，伪造 media 记录会污染媒体库与历史；`LivePlayer` 没有进度条且 `isLive: true` 会走"5s 起播切路"的直播语义。复用引擎层（`attach/load/play/seek/destroy`）成本最低且不影响既有两条播放链路。
- **被否决**：① 伪造 media/episode 走 `PlayerView`（污染 `media`/`episodes`/`history`，需清理逻辑）；② 直接复用 `LivePlayer` 加可选进度条（`isLive` 语义、超时切路、无 `seek` 会互相打架）；③ 内嵌 WebView 系统播放器（无统一错误面板与全屏控制）。

## 6. 非功能设计

### 6.1 多源拉取与合并时序

```
UI: EpgView 打开(频道 ch, 日期 d)
  └─ epgService.programmesFor(ch, d)
       ├─ epgSourceService.list() → 启用源按 priority 升序 [S1,S2,S3]
       ├─ for Si in [S1,S2,S3]（提前终止）
       │    ├─ cacheRepo.getEpg(`epgv2:Si:key:d`) 命中 → 直接判定有/无数据
       │    ├─ 未命中 → in-flight 复用 or 入闸门(≤3)
       │    │     ├─ 构造 URL（diyp: ?ch=&date=；xmltv: 原样/追加 ch&date）
       │    │     ├─ httpClient.request(text, {timeoutMs:6000, retries:0})
       │    │     ├─ epgTime 归一化 + 匹配级别判定 + 去重排序
       │    │     └─ 有数据 → cacheRepo.putEpg（失败不写）
       │    └─ 命中且有数据 → 返回 {programmes, matchedSource:{Si, level}}
       └─ 全部未命中 → {programmes:[], matchedSource:null, errors:[...]}
```

- **提前终止**：命中即返回，后续源不发起请求（100 频道 × 2 源的实际请求数 ≈ 命中源数，而非源数×频道数）。
- **in-flight 去重**：`Map<key, Promise>`；`finally` 删除，避免内存泄漏。
- **过期兜底**：源请求失败时读同键过期记录（若存在）→ 返回并 `stale=true`；UI 在页头显示"节目单可能不是最新"。
- **时间预算**：单频道最坏 3 源 × 6s = 18s → 通过"提前终止 + 并发 3 + 只对可见频道发请求"约束实际值；AC-160 的 P95 ≤200ms 指缓存命中与单源命中场景。

### 6.2 频道列表与拖拽性能（100+ / 1万+）

| 关注点 | 设计 |
| --- | --- |
| 列表渲染 | 沿用现有渲染策略（`LiveView` 分组后按组渲染）；`visibleChannels` 改为"预计算 `Map<channelKey, index>`，同 rank 内按 order 索引排序"，避免 200 项每次 `findIndex` 的 O(n²) |
| 拖拽实现 | 指针事件（`pointerdown/move/up`）+ `transform: translateY()`；**拖拽中不写 store、不改数组**，仅记录 `dragKey` 与目标位次；松手一次性 `setOrder()` 整表覆盖 |
| 帧率 | 拖拽状态用 `shallowRef` + `requestAnimationFrame` 合并位移；只对被拖元素与发生位移的邻居改样式（`will-change: transform`），无自动滚动时 200 项 ≥57fps |
| 规模保护 | 进入排序模式时校验 `当前分组频道数`：>300 → 提示先分组筛选（`CHANNEL_ORDER_MAX`），不进入拖拽 |
| 保存 | 单条 `channelPrefs` put，200 频道的 `string[]` 序列化 + 写入 ≤100ms（实测目标，超出即判不达标） |
| 排序模式副作用 | 禁用频道点击换台与自动播放（`playing` 不变），退出排序模式恢复 |

### 6.3 离线与降级矩阵

| 场景 | 行为 | 依据 |
| --- | --- | --- |
| 离线 + EPG 缓存命中 | 正常展示，`stale=false` | FR-67 |
| 离线 + 缓存过期 | 展示过期数据 + "可能不是最新"标记，`stale=true` | FR-67 可靠性 |
| 离线 + 无缓存 | 空态"暂无节目单数据"，不阻塞播放 | FR-55 口径 |
| 源返回 HTML/空 | `E_PARSE` 记 `lastError`，该源当日不再重试（缓存失败不写，但内存标记 `failedUntil = now+5min` 防抖动） | 防第三方端点限流 |
| 回看探测失败 | 入口置灰 + 原因，6h 不复探 | AC-162 |
| 通知权限被拒 | 提醒保留，`native.permission='denied'`，UI 标注"仅 App 内提醒" | AC-169 |
| 媒体进度不可用 | 回看页不做断点续播；退出即丢进度（直播口径） | Out of Scope |
| 直播源被删除 | 级联删 `channelPrefs`、取消该源全部提醒 | API-21/22 级联 |
| EPG 源被删除 | 提醒保留，`epgSourceId` 返回 `null` + `orphanEpgSource` 标记 | FR-66 |
| DB 升级失败 | `E_DB`/`E_VERSION_UNSUPPORTED` 沿用既有处理，不清库 | §4.3 |

### 6.4 通知时序与状态机

```
upsert(leadMinutes)
  ├─ notifyAt = startAt - lead*60_000
  ├─ ensurePermission()
  │    ├─ granted → notificationScheduler.schedule({nativeId, at: notifyAt, allowWhileIdle:true})
  │    │              state='scheduled'
  │    └─ denied/unsupported → state='scheduled', lastError='notification-permission-denied'
  │                            Web: 前台轮询（setTimeout 到 notifyAt）→ 页面内提示
  └─ 返回 Reminder（含 native.permission）

触达
  ├─ App 前台：onReceived → 页面内提示（Toast/横幅），系统通知已弹出则不重复提示
  ├─ App 后台/被杀：系统通知（标题「频道名 · 节目名」，正文「HH:mm 开播」）
  └─ 点击通知 → extra.route='/live?source=<id>&channel=<name>' → 定位频道（不自动播放）

reconcile（启动 + 回前台 + App 内每分钟轻量检查，仅在前台）
  ├─ now > startAt + 10min 且未触发 → state='missed' + 取消原生
  ├─ now ≥ notifyAt 且 ≤ startAt+10min → state='firing' → 60s 内 'fired'
  └─ |notifyAt - 原生排期| > 60s → 重排
```

- 精确闹钟：声明 `SCHEDULE_EXACT_ALARM`；`AlarmManager.canScheduleExactAlarms()` 为 false 时插件会退化为非精确，UI 依据 `reminder.lastError='inexact-alarm'` 标注"可能延迟"。
- 重启：设备重启后到 App 首次启动前不承诺触发（依赖插件是否提供 BOOT 重排，未验证 → §9 R-04）；首次启动 `reconcile()` 把过期项标记 `missed` 并清理原生排期。
- 通知内容不含播放地址与任何 URL（安全约束）。

| `cacheRepo.getEpg/putEpg` | 签名不变（仅 key 值变化） | 其它调用点零改动 |
| IndexedDB 既有 13 个 store 与索引 | 不改名、不删除 | `src/db/schema.ts` 契约 |

### 8.2 允许的加法

追加 store/索引、追加可选字段、追加导出函数、追加 service 方法、追加常量、v4 升级时清空纯缓存 `epgCache`、在 `liveService.remove*` 内新增级联调用。

### 8.3 运行时约束（必须遵守）

- EPG 缓存 **24h TTL**（`EPG_CACHE_TTL_MS`），失败不写缓存；探测结果 **6h TTL**。
- 频道规模 **100+**（目标 1万+ 不退化）：合并只对可见/收藏频道发起；排序模式 ≤300 频道；列表渲染沿用既有策略。
- 并发：EPG 拉取 ≤3、回看探测 ≤2；不得在 `withTx` 内 await 非 IDB Promise。
- 不常驻定时器（对齐 Q-05）；前台每分钟检查用 `setTimeout` 且在 `visibilitychange` 隐藏时暂停。
- Android `minSdkVersion=29`；Web 端功能可用但通知降级。
- 不内置任何 EPG/回看/频道地址（FR-46 红线），内置源仅指向既有 `EPG_DEFAULT_ENDPOINT` 常量。

### 8.4 性能与体积边界

APK 增量 0（不新增依赖、不新增原生插件）；主线程单次阻塞 ≤50ms（合并计算按频道切片）；EPG 缓存 ≤8MB；频道偏好单记录 ≤64KB；提醒 ≤50 条。
