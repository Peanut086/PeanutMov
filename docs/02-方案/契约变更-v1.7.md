## 1. 为什么要改

用户实测反馈两条主诉：「很多资源导入之后无法使用」「检索功能一塌糊涂」。对 116 条社区订阅逐条体检（详见上游方案 §1）：

- ~25% 为死链/家庭宽带/垃圾/成人，**任何解析器都救不了**，只能靠评测标记 + 生命周期自动降级；
- ~15% 根本不是 TVBox 配置：官网主页/短链落地页（拉到 HTML 即 `FORMAT_UNSUPPORTED`）、gh-proxy 前缀 URL（代理失效后现有镜像回退不认带前缀地址）、gitee `blob/` 页、GitHub 仓库页、**CMS 采集 API 直连**、单流 m3u8；
- 检索侧：结果逐源流式追加，同一部片每源一条、无归并无相关度排序（`libraryStore.search` 仅按 `item.id` 去重）。

结论：解析器对合法单仓已足够好（CHG-06/07/10/11/12/13/16/17）；缺的是**导入前的 URL/内容归一化管道**、**导入后的订阅生命周期**、**检索跨源聚合层**，以及弹幕这一全新能力。

## 2. 改了什么

### 2.1 CHG-18：订阅导入归一化 + CMS 直连（FR-49 / FR-50）

**A. URL 归一化（拉取前，纯函数）**——新增 `src/shared/urlNormalize.ts`（SCF/PKG-A 所有）：

```ts
export interface UrlNormalization {
  /** 处理后的首选地址（blob→raw 已重写；代理前缀保留在 strippedProxy，首选仍走原地址） */
  url: string;
  /** 命中的代理前缀（gh-proxy.org / ghfast.top / gh-proxy.com ...）；无则 null */
  strippedProxy: string | null;
  /** 网络失败时的重试变体（剥代理直连 → 各镜像 → jsdelivr↔raw 互换） */
  variants: string[];
  /** 非致命提示（如 `?id-3` 疑似 `?id=3` 拼写），不改写仅提示 */
  notes: string[];
}
export function normalizeImportUrl(raw: string): UrlNormalization;
/** 订阅入口的直播列表预判：.m3u/.m3u8/.txt 后缀或已知直播 host */
export function isLikelyLiveListUrl(url: string): boolean;
```

- `blob/`→`raw/` 重写：gitee / gitlab / jihulab / github / cnb.cool；
- `withGithubMirrorFallback`（`src/shared/githubMirror.ts`）扩展：`isGithubRawUrl` 与 `mirrorVariants` 识别「代理前缀 + GitHub raw」形态，代理失败先剥前缀直连再换镜像；
- 常量（`shared/constants.ts`）：`URL_PROXY_HOSTS`、`CDN_VARIANT_MAP`（jsdelivr ↔ raw ↔ ghfast）。

**B. 内容识别扩展（拉取后）**——`src/sources/pipeline/rules/defaults.ts` 加三条规则（PKG-B）：

| 规则 id | 触发 | 行为 |
| --- | --- | --- |
| `sub.html-sniff` | `looksLike.html` 且 intent=subscription | 抽取**同域** `.json/.txt/.php` 候选链接 ≤3 条，二次拉取（共享原 10s 预算）；命中即按普通订阅解析。覆盖官网落地页/短链 meta refresh 与 JS 跳转 |
| `sub.cms-detect` | 响应 JSON 含 `code` + (`list` 或 `class`) 形态且无 `sites[]` | 生成**单条 site 源**预览（api=该 URL，`ext.cmsDirect=true`），走 `ImportSuggestion`（见 C）而非直接 entries |
| `sub.single-stream` | `#EXTM3U` 且 `#EXTINF` ≤1 | 生成「加入自定义频道」建议 |

**C. `ImportPreview` 增量（types 可选字段，向后兼容）**：

```ts
export type ImportSuggestion =
  | { kind: 'live-list'; action: 'add-live'; payload: string }        // m3u/txt 播放列表
  | { kind: 'single-stream'; action: 'add-channel'; payload: string } // 单流 m3u8
  | { kind: 'cms-api'; action: 'add-site'; payload: string };         // 采集接口直连
export interface ImportPreview { /* 既有字段不变 */ suggestions?: ImportSuggestion[]; }
```

`importService.previewFromUrl` 失败路径与 pipeline 规则均可产出 `suggestions`；预览页据此渲染「这不是普通订阅，但可以：加入直播源 / 加入自定义频道 / 添加为采集源」动作条。

**D. CMS 直连一等公民（FR-50）**：`SourceFormView` 新增「采集接口」快捷入口——粘贴 `.../api.php/provide/vod/...` 或任意 macCMS JSON 端点 → 探测确认（复用 `sub.cms-detect` 判定）→ 建 `site` 源（`ext.cmsDirect=true`，浏览/搜索/播放走既有 `SiteAdapter` macCMS 协议）。不新增 `SourceType`。

### 2.2 CHG-19：订阅生命周期与评测闭环（FR-51）

新增 `src/services/subscriptionLifecycleService.ts`（PKG-B）：

```ts
export interface SubscriptionSummary {
  subscriptionId: string; sourceCount: number; alive: number; dead: number;
  jarDead: number; lastRefreshAt: number | null;
}
export const subscriptionLifecycleService = {
  /** 启动时 + 每 24h（TTL 常量 SUBSCRIPTION_REFRESH_TTL_MS）后台刷新全部订阅，并发 ≤2，失败静默累计 */
  maybeAutoRefresh(signal?: AbortSignal): Promise<void>;
  /** 多仓索引逐仓评测（复用 subscriptionEvalService，并发 SUBSCRIPTION_EVAL_CONCURRENCY） */
  evaluateMultiRepo(url: string, signal?: AbortSignal): Promise<SubscriptionEvalResult[]>;
  /** 汇总每份订阅的健康摘要 */
  summarize(): Promise<SubscriptionSummary[]>;
  /** 连续 3 次（SUBSCRIPTION_AUTO_DISABLE_STREAK）体检 bad → enabled=false + autoDisabledAt=now；返回处置数 */
  applyHealthDegradation(): Promise<number>;
  /** 恢复被自动禁用的源（清 autoDisabledAt、enabled=true） */
  restore(sourceId: string): Promise<void>;
};
```

- `Source` 增可选字段 `autoDisabledAt?: number | null`（types；无既有行兼容问题）；
- `sourceStore` 增 `subscriptionSummaries` state 与 `loadSummaries/refreshAllSubscriptions/restoreAutoDisabled` actions；
- `EvalSubscriptionView`：多仓条目可「展开评测全部仓库」；评测结果行增「导入最优 N 源」（按 `aliveEstimate` 降序取前 N，跳过 jar 判死与成人标记，走既有 `importService.commit`）；
- `SubscriptionListView`：订阅摘要卡（源数/存活/死/最近刷新）+「全部刷新」。

### 2.4 CHG-21：播放兜底与加载优化（FR-53）+ ExoPlayer PoC

- **换线换源链**（`PlayerController`，PKG-A）：起播 `PLAYER_FAILOVER_WINDOW_MS`（10s）内失败 → 自动换线路（同源下一 line）→ 仍失败自动换源（`pickAlternate` 既有排序）→ 才弹 `PlayerErrorPanel`；每次切换 Toast 告知，集号与进度按 `episodeFallback` 既有逻辑保留；单次播放链路最多各 1 次。
- **下一集预载**：`NextEpisodePrompt` 倒计时触发时预取下一集 `resolvePlayUrl` 与 m3u8 清单（**不拉分片**），切集目标 <1s 起播。
- **缓冲调优**（`HlsEngine` + constants）：当前 level 高度 ≥1080 时 `maxBufferLength` 30→60s、`backBufferLength` 收紧；ABR 起始 level 记忆上次选择。
- **直播低延迟**：`liveSyncDurationCount=3` + 追帧；频道起播 5s 超时自动切同组下一路（`LivePlayer`）。
- **ExoPlayer PoC（Spike，决策 3）**：`src/native/exoPlayerPlugin.ts`（PKG-B wrapper）+ `android/app/src/main/java/.../ExoPlayerPlugin.java`（PKG-A，Media3 surface 模式）。设置页隐藏开关 `experimentalNativePlayer`（默认关）。**退出标准**：MuMu 模拟器 4K HLS 播放不掉帧、进度/倍速/字幕最小集可用即「PoC 达标」，是否转正另立 CHG；不达标则保持默认关闭不阻塞发布。

### 2.5 CHG-22：弹幕（FR-54，决策 1）

**只读不发**；无服务端定位不变；第三方请求仅含片名/年份/集号。

### 2.6 CHG-23：IPTV 强化（FR-55）

- 新增 `src/services/epgService.ts`（PKG-B）：diyp 风格 XMLTV 解析（`?epg=` 端点、epg.pw 数据源）+ `epgCache` 存储（key=频道+日期，TTL 24h）；

### 2.7 CHG-24：内置推荐订阅（FR-56，决策 4）

- 新增 `src/data/recommended/recommended.json`（PKG-B）：版本化清单（`{ version, updatedAt, items: [{ name, url, note, tags }] }`），初版 8~10 条，**从 116 条清单人工筛选，剔除成人/家庭宽带/死链**（候选：饭太硬、潇洒、kstore 系、PG/御制 drpy、影视仓 format=2、fanmingman ipv6、Guovin iptv-api、iptv-org）；
