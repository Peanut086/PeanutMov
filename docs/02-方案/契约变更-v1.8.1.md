## 1. 为什么要改（根因定案）

用户真机反馈四问题，逐一定案（排查过程含实证，非猜测）：

1. **搜索结果点入「详情加载失败」**：渐进搜索竞态——`libraryService.search` 的批量落库（`upsertMany`）要等**全部源 settle**，而 `onPartial` 单源完成即上屏；渐进窗口内（爬虫源预算 20s）点击 → `getDetail` 的 `mediaRepo.get` 为 null → `E_NOT_FOUND`。**验收报告 §2-① 怀疑的「单线路 `vod_play_from` 解析」已实证排除**：起 mock 服务跑 SiteAdapter search→getDetail 真链路，twin-a/allbad/badline 3/3 通过；badline 当时「稳定成功」是因为 AC-123① 流程已让它落过缓存。
2. **返回后搜索结果没了**：`App.vue` KeepAlive 只含 HomeView，SearchView 返回时重建；keyword 只从 `route.query.q` 初始化（页内输入时为空）→ 退回历史页。store 数据其实还在。
3. **顶部未留状态栏位置**：targetSdk 35 在 Android 15+ 被**强制 edge-to-edge**；Capacitor 7.6 默认 `adjustMarginsForEdgeToEdge: "disable"` 不补偿；Android WebView 的 `env(safe-area-inset-top)` 恒为 0，`--safe-top` 兜不住。MuMu（Android 12）不复现，故 v1.8 验收漏掉。
4. **搜索结果乱码（探测层缺陷）**：`decodeBody` 的 UTF-8 探测只验**前 4KB**——ASCII 头 + 中文在 4KB 之后的 GBK 页面（列表 JSON 常见）被误判为 UTF-8，产出不可逆乱码。GET 链路字节本身是保真的（Capacitor 拦截器回传原始 InputStream，已核实）。

## 2. 改了什么

### CHG-28-a：渐进搜索即时落库 + 详情兜底（问题 1）

- `libraryService.search` 的 `settleOne`：单源结果**先 `mediaRepo.upsertMany` 再 `onPartial` 上屏**（落库失败仅 warn 不阻断上屏）；末尾批量重写移除。
- `LibraryService.getDetail` 新增可选 `opts.item`（向后兼容）：条目未落库时以它兜底直接回源刷新，不再立刻 `E_NOT_FOUND`。
- `libraryStore.loadDetail` 自动从 `searchResultsAll` 传 hint。

### CHG-28-b：搜索页状态保持（问题 2）

- `SearchView` 加 `defineOptions({ name: 'SearchView' })` 并纳入 `App.vue` KeepAlive include——从详情/播放返回不重建。
- keyword 初始化兜底 `library.searchKeyword`；store 已有该关键词结果时不重搜直接复用（进程被杀恢复场景）。
- goBack 改为直接退出（原「先清结果再退」行为移除，清空交给输入框清除按钮）。

### CHG-28-c：状态栏边距（问题 3）

- `capacitor.config.ts`：`android.adjustMarginsForEdgeToEdge: 'auto'` + `StatusBar.backgroundColor: '#0b0b0f'`（Capacitor 按系统栏 insets 给 WebView 加边距，顶/底一次解决；已 `cap sync`）。

### CHG-28-d：解码探测全量化（问题 4 的探测层）

- `decode.ts`：UTF-8/GBK 探测由「前 4KB 前缀」改为**全量严格解码**（`TextDecoder fatal`，原生实现毫秒级）。BOM → header charset 次序不变。
- 残余通路**有意不修**（无现受益者/不可控）：CapacitorHttp 非 GET 原生路径强制 UTF-8（当前全 GET）；jar/drpy 爬虫内部解码（发生在 jar 自身 Java 代码）。待真机抓乱码样本定策略。

### CHG-28-e：平铺去重含年份（顺带）

- `titleKeyOf(title)` → `searchAggregate.titleDedupKey(title, year)`：同名不同年（如《三体》2008/2023）不再互相挤掉，平铺/聚合两视图口径对齐。

### CHG-28-f：详情错误面板动作化（顺带）

- `DetailView` 错误态对源故障码（E_SOURCE_* / E_AUTH / E_HTTP_401/403/404/5XX / E_PARSE）经 ErrorState `#extra` 槽显示「去源管理」。
