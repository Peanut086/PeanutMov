## 3. 接口契约

> 编号说明：既有 API-01 ~ API-15 不重排；本批新增 **API-16 ~ API-19**。前端 Service 扩展统一在 API-16，原生插件在 API-17/API-18，预检内部模块在 API-19。

### API-16 `DownloadService` 扩展（前端 Service 层，供 `downloadStore` 调用）

> 既有 API-09 的方法（`create/list/pause/resume/cancel/retry/remove/...`）签名不变；本节为**纯新增**。

#### 3.1.1 `preflight(inputs, options)` — FR-65 / FR-62

- 用途：入队前逐项预检并给出裁决；**不创建任务、不写库**。
- 请求参数

| 名称 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `inputs` | `CreateDownloadInput[]` | 是 | 长度 1~50，超出抛 `E_INVALID_INPUT` |
| `inputs[].format` | `MediaFormat` | 是 | `hls` 走清单预检；其余走直链探测 |
| `inputs[].headers` | `Record<string,string>` | 否 | 注入 LocalProxy 的请求头 |
| `options.hlsQuality` | `'max' \| '1080p' \| '720p'` | 否 | 默认取 `settings.download.hlsQuality` |
| `options.probeSegment` | `boolean` | 否 | 默认 `true`：HLS 探测 1 个分片 |
| `options.timeoutMs` | `number` | 否 | 单任务超时，默认 4000 |
| `options.maxParallel` | `number` | 否 | 并发上限，默认 4，上限 4 |

- 响应结构（完整示例）

```json
{

    {
      "episodeId": "m1:src_1:1:3",
      "ok": true,
      "format": "hls",
      "container": "ts",
      "drmProtected": false,
      "durationSec": 2400,
      "variants": [
        { "index": 0, "label": "1080p", "width": 1920, "height": 1080, "bandwidth": 4500000, "estimatedBytes": 1350000000 },
        { "index": 1, "label": "720p", "width": 1280, "height": 720, "bandwidth": 2200000, "estimatedBytes": 660000000 },
        { "index": 2, "label": "480p", "width": 854, "height": 480, "bandwidth": 900000, "estimatedBytes": 270000000 }
      ],
      "selectedVariant": { "index": 1, "label": "720p", "height": 720, "bandwidth": 2200000 },
      "estimatedBytes": 660000000,
      "estimatedBytesApproximate": true,
      "probe": { "segmentOk": true, "latencyMs": 210, "status": 206, "redirected": true },
      "subtitles": [
        { "lang": "zh", "format": "vtt", "available": true },
        { "lang": "en", "format": "vtt", "available": false }
      ],
```

阻断示例（DRM）：

```json
{

    { "episodeId": "m1:src_1:1:3", "ok": false, "format": "hls", "container": "ts", "drmProtected": true,
      "variants": [], "selectedVariant": null, "estimatedBytes": null, "probe": null, "subtitles": [],

  "elapsedMs": 640
}
```

- `blocked` 的 `reason` 枚举与映射

| reason | code | 是否阻断 | UI 动作 |
| --- | --- | --- | --- |
| `drm` | `E_DRM_PROTECTED` | 是 | 提示"不支持受保护内容"，禁止入队 |
| `unsupported-format` | `E_UNSUPPORTED_FORMAT` | 是 | 提示"暂不支持该格式" |
| `storage` | `E_STORAGE_QUOTA` | 是 | 展示所需/可用，建议清理 |
| `wifi-only` | `E_NETWORK` | 需确认 | 确认框"仅 Wi-Fi 下载已开启，本次仍下载？" |
| `unreachable` | `E_NETWORK` | **否** | 提示"检测失败，已按可下载入队" |
| `null` | — | 否 | 直接入队 |

- 错误码表（方法级，非 `blocked`）

| code | 触发条件 |
| --- | --- |
| `E_INVALID_INPUT` | `inputs` 为空或 >50；`timeoutMs` 非正数 |
| `E_NETWORK` | 预检自身不可执行（全局离线）；此时返回 `canStart=false` 且 `blocked.reason='unreachable'` 由 UI 覆盖为"放行" |
| `E_ABORTED` | 用户取消预检（UI 关闭面板） |

#### 3.1.2 `createBatch(inputs, options)` — FR-61

- 用途：批量创建，带容量裁决与 `batchId`；对已存在任务返回 `skipped`。
- 请求参数

| 名称 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `inputs` | `CreateDownloadInput[]` | 是 | ≤50，超出 `E_INVALID_INPUT` |
| `options.hlsQuality` | `'max'\|'1080p'\|'720p'` | 否 | 写入任务 `hlsQuality`；覆盖项不写回设置 |
| `options.batchId` | `string` | 否 | 缺省由服务生成 `batch_${ts}_${rand}` |
| `options.allowOverCapacity` | `boolean` | 否 | 默认 `false`；`true` 时超容量集进入 `rejected` 而非报错 |

- 响应结构（完整示例）

```json
{
  "batchId": "batch_1762483200000_a1b2c3",
  "created": [
    { "id": "9f1c...", "episodeId": "m1:src_1:1:1", "status": "queued", "batchId": "batch_1762483200000_a1b2c3", "hlsQuality": "720p" }
  ],
  "skipped": [
    { "id": "77aa...", "episodeId": "m1:src_1:1:2", "status": "completed" }
  ],
  "rejected": [
    { "episodeId": "m1:src_1:1:9", "code": "E_INVALID_STATE", "message": "队列已满(200)，请先清理" }
  ],
  "queue": { "before": 195, "after": 200, "capacity": 200, "full": true }
}
```

> `created[].*` 为 `DownloadTask` 的**裁剪投影**（完整字段见 §4.1），此处仅列新增/关键字段。

| code | 触发条件 |
| --- | --- |
| `E_INVALID_INPUT` | `inputs` 长度 >50 或 0 |
| `E_INVALID_STATE` | `allowOverCapacity=false` 且全部被容量拒绝（`queue.full=true` 且 `created=[]`） |

#### 3.1.3 `retryBatch(batchId)` — FR-61

- 请求：`{ "batchId": "batch_1762483200000_a1b2c3" }`
- 响应：

```json
{ "batchId": "batch_1762483200000_a1b2c3", "retried": 3, "skipped": 1, "failedIds": ["dl_88", "dl_92", "dl_95"] }
```

- 行为：筛选 `status='failed'` 且 `batchId` 匹配的任务，按 `episodeNumber` 升序调用既有 `retry()`（内部可走 `redownload`）；`canceled` 不参与。
- 错误码：`E_NOT_FOUND`（无该批任务）、`E_INVALID_STATE`（批内无失败项）。

#### 3.1.4 `setSpeedLimit(limit)` / `rateStats()` — FR-63

- `setSpeedLimit({ "limit": "low" })` →

```json
{ "limit": "low", "bytesPerSec": 524288, "appliedAt": 1762483260000 }
```

- `rateStats()` →

```json
{ "windowMs": 3000, "totalBps": 498000, "tasks": [{ "taskId": "dl_1", "bps": 300000 }, { "taskId": "dl_2", "bps": 198000 }] }
```

- 行为：更新设置 `download.speedLimit` → `downloadRateLimiter.setLimit` → 原生 `MediaTool.setSpeedLimit`（Android）；Web 仅 JS 侧。
- 错误码：`E_INVALID_INPUT`（档位不在四档内）。

#### 3.1.5 `findLocalPlay` 扩展 — FR-64

既有返回结构不变（`LocalPlayResult`），新增行为：

- `subtitles` 由 `task.subtitlePaths` 映射为 `SubtitleTrack[]`（`source='downloaded'`，Android 用 `toPlayableUrl(path)`，Web 用 Blob URL）；
- `revoke()` 同时回收字幕的 ObjectURL（Web）；
- `format`：转封装成功后 `task.format==='mp4'`；未转封装保持 `'ts'`（`hls` 仍映射为 `ts`，沿用既有逻辑）。

播放侧 `PlaybackSource.subtitles` 示例：

```json
[
  { "id": "downloaded:zh", "label": "中文（已下载）", "lang": "zh", "url": "https://localhost/_capacitor_file_/data/user/0/com.qoder.cinema/files/downloads/m1/ep3.zh.vtt", "format": "vtt", "source": "downloaded" }
]
```

#### 3.1.6 事件扩展

`DownloadEvent` 联合类型新增一项（既有 `progress`/`status`/`queue` 不变）：

```ts
| { type: 'postprocess'; task: DownloadTask; stage: 'remux' | 'subtitles'; state: 'start' | 'progress' | 'done' | 'skipped' | 'failed'; progress?: number; reason?: string }
```

`progress` 为 0~1，节流 ≤2 次/秒。UI 据此在列表项显示"转封装中 62%"。

### API-17 `MediaTool` 原生插件 —— `remuxMp4` / `cancelRemux`（Android）

- 注册：`MainActivity.onCreate` 中 `registerPlugin(MediaToolPlugin.class)`（必须在 `super.onCreate` 之前，REV-21）。
- 用途：TS→MP4 转封装（仅解复用/复用，不重编码），服务 FR-60。

**`remuxMp4` 请求参数**

| 名称 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `taskId` | `string` | 是 | 用于事件关联与日志追踪 |
| `inputPath` | `string` | 是 | 相对 `Directory.Data` 的路径（如 `downloads/m1/ep3.ts`）；**不得**为绝对路径或越界路径，否则 `E_INVALID_INPUT` |
| `outputPath` | `string` | 是 | 期望输出（如 `downloads/m1/ep3.mp4`）；内部写 `outputPath + ".part"` |
| `deleteInput` | `boolean` | 否 | 默认 `true`：成功 rename 后删除输入 |
| `timeoutMs` | `number` | 否 | 默认 120000，上限 600000 |

**响应（成功）**

```json
{
  "ok": true,
  "skipped": false,
  "reason": null,
  "outputPath": "downloads/m1/ep3.mp4",
  "inputBytes": 524288000,
  "outputBytes": 523968512,
  "durationUs": 2400000000,
  "durationMs": 11230,
  "container": "mp4",
  "tracks": [
    { "type": "video", "mime": "video/avc", "width": 1920, "height": 1080 },
    { "type": "audio", "mime": "audio/mp4a-latm", "channels": 2, "sampleRate": 44100 }
  ]
}
```

**响应（跳过）**

```json
{ "ok": true, "skipped": true, "reason": "no-video-track", "outputPath": null, "inputBytes": 524288000, "outputBytes": 0, "durationUs": 0, "durationMs": 640, "container": "ts", "tracks": [] }
```

**事件**

```json
{ "event": "remuxProgress", "taskId": "dl_1", "processedUs": 1800000000, "durationUs": 2400000000 }
```

**错误码表**

| code | 触发条件 | 调用方处理 |
| --- | --- | --- |
| `E_INVALID_INPUT` | 路径为空/含 `..`/输出与输入同路径/超时参数非法 | 视为失败，回退 TS |
| `E_FILE_MISSING` | `inputPath` 不存在或为 0 字节 | 回退 TS，并交由既有 `E_FILE_MISSING` 逻辑处理 |
| `E_UNSUPPORTED_FORMAT` | 解复用找不到视频轨，或编码无法封装（如部分 AC3/HEVC 组合） | 回退 TS（`remux.status='failed'`，`reason` 带 code） |
| `E_STORAGE_QUOTA` | 输出写入 IO 失败/空间不足 | 回退 TS，删除 `.mp4.part` |
| `E_TIMEOUT` | 超过 `timeoutMs` | 回退 TS，删除 `.mp4.part` |
| `E_CANCELED` | `cancelRemux` 被调用 | 删除 `.mp4.part`，按任务取消流程 |

**`cancelRemux`**：请求 `{ "taskId": "dl_1" }` → `{ "canceled": true }`；未找到进行中的任务返回 `{ "canceled": false }`。

### API-18 `MediaTool` 原生插件 —— `getStorageInfo` / `setSpeedLimit`

**`getStorageInfo`**（FR-65；Web 端由 `navigator.storage.estimate()` 兜底）

- 请求：`{ "path": "downloads" }`（相对 `Directory.Data`，缺省 `downloads`）
- 响应：

```json
{ "freeBytes": 62000000000, "totalBytes": 128000000000, "appBytes": 1830000000 }
```

- 错误码：`E_INVALID_INPUT`（路径越界）。

**`setSpeedLimit`**（FR-63）

- 请求：`{ "bytesPerSec": 524288 }`（`0` 表示不限速；负数 `E_INVALID_INPUT`）
- 响应：`{ "bytesPerSec": 524288, "appliedAt": 1762483260000 }`
- 语义：设置进程内 `DownloadRateLimiter` 的额度，**对所有** `RangeDownloader` 实例（单连接与多 Range 并发连接）生效；不影响 `DownloadPlugin` 的 `start/pause/resume/cancel/getStatus`。

### API-19 `downloadPreflight` 内部模块（Service 内部，UI 不得直接 import）

- 用途：被 `DownloadService.preflight` 调用；也可被 `createBatch` 复用于"同批同 master 只拉一次"。
- 方法

| 方法 | 签名 | 说明 |
| --- | --- | --- |
| `probePlaylist` | `(url, headers, opts) => Promise<{ variants, container, drmProtected, durationSec, baseUrl, notes }>` | 经 LocalProxy 拉清单（失败回退直连），复用 `parseM3u8`/`manifestBaseUrl`/`assertSupportedKeyMethods` |
| `estimateBytes` | `(variant, durationSec) => number` | `bandwidth/8 × durationSec`，`estimatedBytesApproximate=true` |
| `probeSegment` | `(segmentUrl, headers, opts) => Promise<{ ok, status, latencyMs }>` | 取首个分片的 `Range: bytes=0-65535`，不做完整下载 |
| `judge` | `(items, storage, network, settings) => { canStart, blocked }` | 见 API-16 `blocked` 枚举与优先级 |

**裁决优先级**（前者命中即返回）：`drm` → `unsupported-format` → `storage` → `wifi-only` → 放行；`unreachable` 不阻断。

**缓存**：以"master URL + headers 哈希"为键，TTL 60s，最多 50 条（与 LocalProxy `MAX_TARGETS=100` 兼容）。

## 5. 关键技术决策

### D-01 转封装实现：Android 平台 `MediaExtractor + MediaMuxer`

- **决策**：使用平台 API 做 TS→MP4 纯转封装；封装失败回退 TS。不引入 ffmpeg 系依赖。
- **理由**：0 APK 增量；不加第三方运行时依赖；解复用/复用不解码，速度受 I/O 限制（实测类场景 ≥40MB/s）；`minSdk=29` 下 API 稳定；失败可降级，风险可控。
- **被否决方案**
  - `ffmpeg.wasm`：core 25–30MB，需大内存（整片读入）、单线程慢、WebView 需 COOP/COEP 才有多线程；对 500MB~1GB 文件不可接受。
  - `ffmpeg-kit`：2025 年官方仓库归档退役、制品下架，维护与合规风险高；体积 +10–20MB/ABI。
  - `androidx.media3:transformer`：约 +2MB，能力与平台方案重叠；其优势在转码与特效，本需求不需要；保留为后续"特殊编码兜底"的候选（本期不做）。
  - JS 侧 `mux.js`/hls.js 内置 transmuxer：只能输出 MSE 流，落盘需全量内存缓冲，与 1GB 上限冲突。

### D-02 字幕：外挂 sidecar，不入容器

- **决策**：字幕下载到视频同目录同 basename，播放时作为 `source='downloaded'` 字幕轨挂载。
- **理由**：零转码；复用现有 `SubtitleManager` 与偏移设置；可开关，符合用户预期；失败隔离天然（不阻塞视频）。
- **被否决方案**
  - 硬烧录：需整片重编码，违反 AC-142 的 15s 目标，且不可关闭。
  - MP4 内嵌 tx3g：`MediaMuxer` 不支持写文本轨；自研封装需处理 SRT/VTT→tx3g 与时序换算，收益仅"单文件"，成本高。
  - 现有 `downloadAttachments` 已下载字幕但不挂载：不满足离线可用，等于无效功能。

### D-03 限速：JS 侧 sink 层全局令牌桶 + 原生共享令牌桶

- **决策**：JS 路径在 `DownloadSink.write()` 前 `consume(bytes)`（直链与 HLS 分片都经 sink，一处生效）；原生 OkHttp 路径在 `RangeDownloader` 读循环 `acquire(bytes)`，共享进程内单例；两者由同一档位驱动。
- **理由**：不触碰 `hlsDownloader` 的下载批次与重试逻辑（FIX-03/04 已稳定）；全局唯一额度符合 Q-11 默认口径；`Infinity` 直通保证 `unlimited` 零开销。
- **被否决方案**
  - 在 `hlsDownloader` 每个分片分支各自限速：并行 6 分片时额度被放大 6 倍，且需改动已修复的下载主循环。
  - OkHttp `Interceptor` 限速：需自定义 `SocketFactory`/`BufferedSink` 包装，侵入大、易破坏 Range 与多 Range 并发。
  - 仅 JS 限速、原生不限：Android 主路径（`sink==='filesystem'` 优先原生）实际走 OkHttp，会完全失效。

### D-04 预检：独立模块复用清单解析，纯加法导出

- **决策**：`hlsDownloader.ts` **只新增导出**（`parseM3u8`、`manifestBaseUrl`、`assertSupportedKeyMethods`、类型），下载/解密/拒绝流程一行不改；预检模块自行实现"LocalProxy 优先 + 直连回退"的清单拉取。
- **理由**：避免两套解析口径漂移（DRM 判定已要求共用 `findProtectedKeyEvidence`）；把 FIX-03/04 的回归面控制在"导出符号"级别。
- **被否决方案**
  - 复制解析逻辑到新模块：DRM/302 口径必然漂移。
  - 把解析整体搬到新模块、`hlsDownloader` 反向 import：改动面大，需重跑 FIX-03/04 全部用例。

### D-05 批量与容量：裁决在服务层，状态机不动

- **决策**：`batchId`、单次 50、队列 200 的裁决放在 `downloadBatch`；`DownloadQueue` 及其状态机/并发/重试**不改**。
- **理由**：状态机是 AC-71/74/140 的验收基线，改动风险高；容量是产品策略，放在服务层可独立测试。
- **被否决方案**：在 `DownloadQueue.enqueue` 内部做容量拒绝——会让队列承担业务策略，且 `requeuePending` 的恢复语义会被误伤。

### D-06 转封装时机：完成态落库之前，UI 用 `postprocess` 事件表达

- **决策**：`downloadEngine.runHls` 在 `hlsDownloader.run` 返回后、引擎 resolve 前执行转封装并回写 `filePath/format/container/remux`；期间 `status` 仍为 `downloading`、进度 100%，通过 `postprocess` 事件显示"转封装中"。
- **理由**：保证 `completed` 一旦出现即可播（AC-142）；不新增任务状态，避免动状态机（AC-74）。
- **被否决方案**：完成后异步补转封装——会出现"已完成但拿到 TS"的时间窗，且附件下载的 basename 可能先按 `.ts` 定名，导致字幕/封面路径不一致。

## 6. 非功能设计

### 6.1 下载完成时序（Android，HLS）

```
queue.lease(task) → engine.runHls
  ├─ resolveProxyBase(LocalProxy)                      # FIX-04
  ├─ fetchManifest(proxy) → parseM3u8 → assert DRM     # FIX-03/04
  ├─ selectVariant(quality)                            # FR-62
  ├─ sink.begin → 分片循环（每批 6）→ sink.write（consume 令牌）
  ├─ sink.finish → { filePath: *.ts }
  ├─ remuxService.remuxIfNeeded(task)                  # FR-60
  │    ├─ container==='fmp4' → rename *.ts → *.mp4（不拷贝）
  │    ├─ 否则 MediaTool.remuxMp4 → *.mp4.part → rename → 删 *.ts
  │    └─ 失败/超时/关闭 → 保留 *.ts，remux.status=failed|skipped
  └─ saveProgress(filePath, format, container, remux)
queue.markCompleted → downloadService.onStatus('completed')
  ├─ downloadAttachments（字幕/封面，basename 与最终文件一致）  # FR-64
  ├─ postprocess 事件 stage='subtitles'
  └─ sendDownloadCompleteNotification（一条，不重复）
```

- **转封装串行**：`downloadRemuxService` 内置长度 1 的串行队列；两个任务同时完成时后者排队（`postprocess` 事件 `state='start'` 延后），避免 CPU/IO 争抢。
- **通知与附件顺序**：先转封装、再字幕/封面、最后通知；通知文案不变（"下载完成"），避免用户收到"完成"却还在转封装的割裂感。

### 6.2 限速时序与精度

- **令牌桶**：容量 = `max(bytesPerSec × 1s, 64KB)`；每 `DOWNLOAD_RATE_TICK_MS`(50ms) 补充 `bytesPerSec × 0.05`；`consume(n)` 不足时按缺口 `await sleep`，单次睡眠上限 200ms，避免长时间挂起取消响应。
- **统计**：`rateStats()` 用 3s 滑窗（每 100ms 采样 `downloaded` 增量），供 AC-148/149 与 UI 展示。
- **精度预算**：JS 单块 256KB，512KB/s 档位单块需 ≈500ms → 配额误差由"桶容量 ≥1s 额度"吸收，稳态误差 ≤±15%；原生读缓冲 64KB 同理。
- **切换**：档位变更时清空桶（`bytes=0`，`lastTick=now`），避免旧额度残留导致 3s 内超限；已在阻塞等待的 `consume` 重新按新额度计算。

### 6.3 离线与降级矩阵

| 场景 | 行为 |
| --- | --- |
| 预检：清单拉取失败（网络抖动） | 放行入队，`notes` 记 `probe-failed`；引擎层错误照常按既有错误码呈现 |
| 预检：LocalProxy 不可用 | 回退直连（非原生环境本就走直连）；不因此阻断 |
| 转封装：平台不支持该编码 | 保留 TS，`remux.reason='E_UNSUPPORTED_FORMAT'`，提示一次 |
| 转封装：磁盘不足 | 删除 `.mp4.part`，保留 TS，提示"空间不足，已保留 TS 格式" |
| 字幕：任一失败 | 视频不受影响，任务详情标注"字幕：未下载" |
| Web 端 HLS 下载 | 不转封装，产物为 `video/mp2t` Blob；字幕 Blob URL 挂载；限速走 JS 桶 |
| 原生 `MediaTool` 未注册/旧 APK | `remuxMp4` 调用失败 → 回退 TS（能力探测 `isAvailable()` 失败即跳过） |
| 任务在转封装阶段取消 | `cancelRemux` → 删 `.mp4.part` → 按取消流程删 `.ts` 与记录 |

### 6.4 日志与追踪

- 字段：`taskId`、`batchId`、`stage`（`preflight|download|remux|subtitles`）、`container`、`selectedHeight`、`elapsedMs`、`reason`。
- **禁止记录**：最终落地 URL、完整播放地址、`headers` 值、字幕原始文本；仅记来源域（`new URL(u).host`）与 `taskId`。
- 预检与转封装各一条 `logger.info` 汇总（成功/跳过/失败），失败另记 `logger.warn` 带 code；不写每分片日志（避免 500+ 行噪音）。

### 6.5 性能边界

| 项 | 边界 | 保证方式 |
| --- | --- | --- |
| 内存（转封装） | ≤128MB | 平台 API 流式 copy（`readSampleData` 只读单样本），不做整片缓冲 |
| 内存（预检） | ≤8MB | 只保留清单文本（≤2MB）+ 单分片 64KB 探测 |
| 磁盘峰值 | 输入 1× + 输出 `.part` 1× | 预检 `requiredBytes = 估算 ×1.1 + 1× 估算`（仅 TS 任务） |
| CPU | 转封装单线程；限速额外开销 ≤3% | 转封装串行 1；限速按 50ms 节拍批量 sleep |
| 主线程 | 批量 50 集单帧 ≤50ms | 沿用 `createMany` 每 10 条让出事件循环 |
| 网络 | 预检每任务 ≤2 次请求（清单 + 1 分片） | 同 master 60s 缓存复用 |

## 8. 实现约束

### 8.1 不得修改（硬约束）

| 对象 | 原因 |
| --- | --- |
| `src/services/downloadQueue.ts` | 状态机/并发/重试是 AC-71/72/74/140 的验收基线 |
| `src/db/schema.ts`、`src/db/migrations.ts` | 不新增索引、不升 `DB_VERSION`；新增字段随值写入即可 |
| `downloadSink.nativeFilePathOf` 的命名规则 | 既有文件与字幕/封面 basename 依赖该规则（`{mediaId}/{episodeId}.{ext}`） |
| `LocalProxyPlugin.java` 的转发/302/清单重写逻辑 | FIX-04 已稳定；只允许调用，不允许改行为 |
| `SpiderProxyServer`、`ExoPlayerPlugin`、`DownloadPlugin` 的 `start/pause/resume/cancel/getStatus` | 与本次能力无关；`DownloadPlugin` 不改签名 |
| `src/shared/errors.ts` 的 `ERROR_MESSAGES` 既有文案 | 复用既有 code；`blocked.reason` 承载细分语义，不新增错误码 |
| `hlsDownloader` 的 DRM 拒绝、代理转发、分片重试、`stripSegmentPrefix` | FIX-03/04 的修复本体 |

### 8.2 允许的加法

- `DownloadTask` / `CreateDownloadInput` / `DownloadSettings` 的新增**可选**字段。
- `DownloadEvent` 联合类型新增 `postprocess` 分支（消费侧按 `switch(type)` 扩展，未处理分支保持忽略语义）。
- `hlsDownloader` 新增 `export`（不改实现）。
- `DownloadPlugin` 之外新增 `MediaTool` 插件；`MainActivity` 增加注册。

### 8.3 必须遵守的运行时约束

1. **CapacitorHttp 拒绝 3xx**：Android 上所有清单/分片/密钥/字幕/预检探测请求必须经 `LocalProxy`；代理失败才允许直连回退。
2. **302 落地地址是相对引用基线**：预检与下载解析清单时都必须用 `manifestBaseUrl` 语义；不得用请求地址拼相对分片。
3. **LocalProxy 不暴露最终 URL**：清晰度标签只能来自 `RESOLUTION`/`BANDWIDTH`/变体序号；日志与 UI 不得出现落地地址。
4. **HLS 必须走 JS 下载器**：`NativeDownloadManager.start` 对 `.m3u8` 直接拒绝（AND-14），转封装只能在 JS 编排侧发起。
5. **DRM 双保险**：预检阻断 + 清单解析阶段 `assertSupportedKeyMethods` 再次拒绝；任一环节不得被配置开关绕过。
6. **转封装不得改变编码**：禁止在 `MediaRemuxer` 中引入 `MediaCodec` 编解码。
7. **路径安全**：`MediaTool` 只接受 `Directory.Data` 相对路径，拒绝 `..`、绝对路径、空路径。
8. **限速不影响元数据**：m3u8/密钥/字幕/封面/预检请求不得占用限速额度。
9. **原生与 JS 单一额度源**：同一时刻只有一处额度生效（Android 以原生桶为准，JS sink 桶在原生路径上不重复扣减——`sink==='filesystem'` 且原生可用时跳过 JS 扣减）。

### 8.4 性能与体积边界

- APK 增量目标 **0**（不引入第三方 native/wasm 依赖）；允许的增量仅为本仓库新增 Java/TS 文件。
- 转封装：500MB ≤15s、内存 ≤128MB、串行 1 个。
- 预检：单任务 P95 ≤3s、20 集 ≤10s、每任务 ≤2 次网络请求。
- 批量：50 集创建 ≤2s、主线程单帧 ≤50ms。
- 限速：稳态误差 ≤±15%（验收按 AC-148 的 ×1.15 / ×0.7 判定）。

## 9. 风险与待确认

### 9.1 已知风险（需协调者关注）

| 编号 | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| R-01 | `MediaExtractor` 对部分 TS（HEVC、AC3/EAC3、多音轨、坏包）解复用失败 | 该集产物仍为 TS，用户可能仍无法用系统播放器播放 | 回退机制 + 任务详情标注原因；后续按真实失败样本评估 Media3 Transformer 兜底（不在本期） |
| R-02 | `ffmpeg-kit` 已于 2025 年归档退役，第三方 fork 维护不可控 | 若未来需要"转码/硬字幕"必须重选型 | D-01 已排除；如产品改口需重新立项并做合规与体积评估 |
| R-03 | `LocalProxyPlugin` token 表 LRU 仅 100 条，`redirectCache` 无上限（既有） | 批量 50 集 + 播放同时进行时可能挤掉 token → 404 | 预检串行/复用同 master token；**不改插件**，作为既有风险记录；如真机复现再单独立项 |
| R-04 | 限速精度受 JS 定时器抖动、512KB 缓冲写盘影响 | AC-148 边界可能在低端机不达标 | 桶容量 ≥1s 额度 + 统计窗口 3s；必要时把 `WRITE_BUFFER_LIMIT` 在限速档下临时下调（需评估，未纳入本期） |
| R-05 | `wifiOnly` 从"死配置"变为真实生效 | 老用户默认 `false` 不受影响；若用户曾手动开启而从未生效，升级后会被拦截 | 预检为"需确认"而非硬阻断，且提供"本次仍下载" |
| R-06 | 转封装使"下载完成"延后（几十秒级） | 用户感知任务变慢 | `postprocess` 事件显示"转封装中 x%"；通知只在转封装完成后发 |
| R-07 | `toDownloadInputs` 开始真正下载字幕/封面 | 批量 50 集时请求量增加（50×2） | 字幕只在 `attachSubtitles!=='none'` 时下载；封面失败忽略；沿用既有失败隔离 |
