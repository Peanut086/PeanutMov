## 1. 实现口径

### 1.1 聚合（`getUnifiedEpisodes`）

```
title 为空 ──是──▶ 返回空聚合（不列源、不搜索）
   │否
缓存命中（5 分钟 / 未 force）──是──▶ 返回 { ...cached, cached: true }
   │否（并发时复用同一个 in-flight Promise）
plans = 候选模式：直接用调用方给的 candidates
       聚合模式：sourceService.list() → 只留 enabled 且 type ∈ {site, spider}
                 → 取健康/延迟 → 按质量排序 → 截断 maxSources（默认 6，详情页传 4）
每个源并行（Promise.all，单源失败只记 misses）：
  search(title) ──超时──▶ miss timeout
                ──抛错──▶ miss source_error
                ──空────▶ miss no_result
                ──不合格 ▶ miss title_mismatch / year_mismatch
  getDetail(命中条目，最多 detailLimit=2 条) ──抛错──▶ detail_failed / detail_unavailable（E_NOT_IMPLEMENTED 等）
                                            ──无集──▶ miss no_episodes
  refsOf(detail)：每个集号一条 ref（source/item/line/episode/lineId/episodeId/episodeNumber/episodeTitle/tier/latencyMs）
合并：按集号分组 → 组内按「档位 → 延迟」稳定排序 → 输出 { number, title(取首选源), sources[] }
```

- 只聚合**可播源**（`site` / `spider`）：豆瓣本身没有剧集清单，且 `DoubanAdapter.getDetail()` 会反向调用本服务，
  把豆瓣纳入聚合会形成递归；`demo` 源不在真实播放链路上。
- 任何单源失败都**不抛错**（返回空 `episodes` + `misses`），调用方 `signal` 中止才抛错且不写缓存。
- `refsOf` 以「实际选中那一集的 `Episode.number`」为键去重：线路里的集号与标题集号不一致时，展示的集号必须等于播放的集号。

### 1.2 选源与降级链（`findBestEpisode`）

| 步骤 | 规则 |
| --- | --- |
| 排序键 1 | 健康档位 `healthTierOf(health, latency)`：`fast < good < fair < slow < bad < unknown` |
| 排序键 2 | 探测延迟 `latencyMs` 升序（`null` 视为 +∞） |
| 排序键 3 | 候选模式：保持调用方给的候选顺序（CHG-12 的质量排序）；聚合模式：源 `sort` → 名称（`zh-Hans-CN`）→ 原始顺序 |
| 输出 | `{ number, title, candidates[] }`，`candidates[0]` 为首选源，失败由调用方顺延 |
| 未命中 | 返回 `null`（**不返回第一集**）；仅当没给 `candidates` 且适配器实现 `findEpisodeByTitle` 时，对「可重试」的失败源做定向直查（最多 3 个） |

`title_mismatch` / `year_mismatch` / `detail_unavailable` 三类不重试（片子对不上或源根本不支持详情，再查一次也是同样结论）。

### 1.3 缓存

- 内存 LRU：默认 **50 部作品 / 5 分钟**；键 = `作品 id | 年份 | 片名归一键`（作品 id 缺省时退化为片名键）。
- 并发去重：同一键同时被多处请求只聚合一回（`in-flight` Promise 复用）。
- `force: true` 绕过缓存重新聚合；`clear()` 清空缓存与计数（换源/订阅变更后由调用方触发）；
  `stats()` 暴露 `entries / inFlight / cacheHits / aggregations / sourceSearches / detailFetches`。
- 详情页与播放链路共用同一份缓存：`getDetail` 用豆瓣 `item.id` 作键、`resolvePlayUrl` 用 `params.mediaId`（同一豆瓣条目 id），
  年份/片名一致即命中，避免「进详情一次 + 播放一次」重复打源站。

### 1.4 未命中原因（`unifiedMissText`）

| 原因 | 含义 | 是否参与直查兜底 |
| --- | --- | --- |
| `title_mismatch` | 该源搜到了同名近似项但片名不匹配 | 否 |
| `year_mismatch` | 片名匹配但年份不一致 | 否 |
| `no_result` | 该源搜不到这部作品 | 是 |
| `no_episodes` | 条目存在但没有剧集清单 | 是 |
| `detail_failed` | 详情读取失败（HTTP/解析/源站故障） | 是 |
| `detail_unavailable` | 源不支持详情查询（`E_NOT_IMPLEMENTED` / `E_UNSUPPORTED_FORMAT` / `E_SOURCE_DISABLED`） | 否 |
| `timeout` | 单源预算到点 | 是 |
| `source_error` | 搜索抛错 | 是 |

### 1.5 `DoubanAdapter` 改动

```
getDetail:
  fetchDoubanDetail(movie → 404 再 tv) → toDetail()（豆瓣原始：1 条「正片」/1 集）
  ├ type === 'movie' → 原样返回（电影无集数概念，省一次跨源搜索）
  └ 其它 → unifiedEpisodeService.getUnifiedEpisodes(item.id, item.title, { year, maxSources: 4 })
             ├ ≥2 集 → toUnifiedDetail()：线路「多源线路」，剧集 id = buildDoubanEpisodeId(sourceItemId, n)，item.episodeCount = N
             ├ <2 集 → 返回豆瓣原始「正片」占位
             └ 抛错（非取消）→ logger.debug + 返回原始占位（详情页不因聚合失败白屏）

resolvePlayUrl:
  parseDoubanEpisodeId → mediaRepo 取片名/年份 → resolvePlayFrom 取候选
  → findUnifiedCandidates(): unifiedEpisodeService.findBestEpisode(title, N, { mediaId, year, candidates, detailOf })
        detailOf 走 doubanRuntime.adapterGetter（与 FIX-05 同一条取数通道）
        命中 → attempts = 降级链（各自源的 lineId/episodeId）
        未命中/异常 → null（不抛错）
  → attempts 为空 → FIX-05 doubanEpisodeMapping.resolve()（逐候选映射，提供未命中明细）
  → 仍为空且 N === 1 → 旧透传兜底
  → 仍为空 → E_NO_PLAY_URL「已启用的源里没有第 N 集」（detail = 未命中原因）
  → 逐个候选解析地址，失败顺延（CHG-12 不变）
```

- 豆瓣剧集 id 保持 `douban_{movieId}_{n}`：`resolvePlayUrl` 从 id 解析集号，且 `libraryService.refreshDetail`
  会把这份清单落库（历史/收藏沿用同一套 id）。线路 id 保持 `douban-{mediaId}`。

### 1.6 `SiteAdapter` / `SpiderAdapter`

两个适配器现在返回**同一个形状**（`SiteEpisodeMatch` = `SpiderEpisodeMatch` = `EpisodeLookupMatch`），都含
`source`（源标识）、`item`、`line`、`episode`、`lineId`、`episodeId`、`episodeNumber`、`episodeTitle`。

`SiteAdapter.findEpisodeByTitle(title, episodeIndex, { source, year, signal, limit })`：

```
assertEnabled → search(pageSize=limit, 默认 8)
→ titleMatches 过滤（季号/续集号冲突直接排除）→ 年份过滤（任一缺失则放过）→ titleMatchScore 降序
→ 逐个 getDetail + selectEpisodeInDetail(index)
   命中 → 返回落点；没有这一集 → 继续下一个候选；详情抛错 → 记下继续
→ 全部候选都取不到详情 → 抛出最后一次真实错误（区别于「没有这一集」）
→ 否则返回 null（不返回第一集兜底）
```
