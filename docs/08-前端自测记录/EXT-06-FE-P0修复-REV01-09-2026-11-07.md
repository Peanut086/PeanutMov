## 4. 与评审条款的偏离（请复审裁定）

1. **REV-09 的抛错类型**：评审给的写法是 `throw new Error(...)`。实测 `toErrorShape()` 对原生 `Error` 只取 `ERROR_MESSAGES.E_UNKNOWN`（「操作失败，请重试」），自定义文案被塞进 `detail` 不展示 —— 直接照写会让用户看不到「请从直播页重新进入回看」这句关键指引。因此改抛 `new AppError('E_NOT_FOUND', '未找到该频道…')`（来自 `src/shared/errors.ts`，未修改该文件），错误文案原样上屏。行为（不回退、直接报错）与评审要求一致。
2. **REV-04 的「置灰」时点**：首屏未探测前按钮为可用态（否则用户无从触发探测）；探测结果为 `not_found` / `unreachable` 后置灰并展示原因。若要求在未探测阶段即置灰，需要额外的「批量预探测」，会引入首屏多次 HEAD，请裁定是否需要。

## 5. 遗留问题

1. **节目单日期栏仍限「昨天 / 今天 / 明天」**（`dateOffset` −1..+1），而回看窗口最长 7 天：第 2~7 天的节目在 UI 上不可达（数据层 `programmesFor` 支持任意日期）。建议后续把日期栏改成「最近 N 天（N = 回看窗口天数）」，需产品确认交互，本轮未擅自改。
2. **深链 `/replay/:channelId/:programId` 不带 `ch` 查询串时现在会报错**（REV-09 的必然结果）：页面无法仅凭源 id + 节目键确定频道。所有站内入口（节目单页「回看」）都会带 `ch`，仅外部直接输入 URL 会命中该错误提示。
3. **真实设备验证未做**：能力探测的真机命中率（不同源的 403 / 302 行为）、长稳（大屏连续运行 24h 的定时器与内存）仍需真机回归；当前为单测 + mock 口径。
4. `ReplayPlayerView` 在错误态下仍会渲染 `ReplayPlayer`（其内部再显示「回看地址尚未就绪」占位），这是修复前既有结构，不影响 REV-09 判定；如需「错误态不渲染播放器」属额外 UI 调整，未在本轮展开。
