## 1. 口径（唯一真值，均落在 `healthCenterService.ts`）

| 概念 | 口径 | 说明 |
| --- | --- | --- |
| 健康 / 失败 / 未检测 | `ok` → 健康；`timeout`/`unreachable`/`bad_config`/`auth_failed` → 失败；其余（仅 `unknown`）→ 未检测 | 三者互斥，`healthy + failed + unknown === total`（单测守卫） |
| 已禁用 | `enabled === false` 的源数量，作为汇总卡的上下文副标题 | 不计入失败/未检测的重叠 |
| 失败分布 | 只输出计数 > 0 的原因，按数量降序；并列按固定顺序 `timeout → unreachable → bad_config → auth_failed` | `percent = Math.round(count / failedTotal * 100)` |
| 失败文案 | 与 `healthService.labelOf` 逐字一致：连接超时 / 无法连接 / 配置有误 / 认证失败 | 避免两处对同一状态两种叫法 |
| 趋势点 | 最近 7 天（含今天）连续生成；无记录日 `recorded: false`、计数补 0 | `healthRate = Math.round(healthy / total * 100)`，`total = 0` 时为 0 |
| 趋势持久化 | 每次进入页面或批量操作后 `upsert` 一条「当日快照」（同日覆盖），最多保留 30 条 | 用生成日期键（本地时区）而非 UTC，避免夜间记录跑到次日 |

批量语义（与源管理页既有能力的差异已显式标注）：

| 动作 | 目标集合 | 实现 | UI 文案 |
| --- | --- | --- | --- |
| 复检失败源 | **启用中**的失败源 | 复用 `refreshHealth({ failedOnly: true })` | 按钮带目标数；进行中显示 `复检中 n/total` 并可取消 |
| 清理失败源 | **启用中**的失败源 → 标记 `enabled=false`（含 `timeout`） | `forEachLimited` + `batchDepth`，逐项 `sourceService.setEnabled(false)` | 确认框说明「不删除配置、含连接超时」 |
| 恢复已禁用源 | 全部 `enabled=false` 的源 | 逐项 `subscriptionLifecycleService.restore(id)`（清 `autoDisabledAt`、健康复位 `unknown`） | 确认框说明恢复后建议复检 |

分支：`isFirstLoading`（整页 loading）→ `healthCenterError`（`ErrorState`，可重试 / 返回设置）→ `summary.total === 0`（`EmptyState`，主按钮跳 `settings?sources=1`）→ 正常内容。

柱位规则：横轴恒 7 列（`grid-template-columns: repeat(7, minmax(0, 1fr))`），未采集日不渲染柱（只显示「—」），保证柱位不随数据天数漂移。

非 token 的可视值仅 3 处，均属结构性常量（无法用 CSS 变量表达），逐条说明：

1. `@media (min-width: 600px)` 断点：与 `tokens.css` 内既有断点（600/900px）一致，媒体查询不支持 `var()`；
2. `min-height: 100vh`（页面根节点）：沿用 `LogsView` 等二级页既有写法；
3. 数据驱动的内联样式（柱 `height: n%`、条 `width: n%`）与运行时最低可见高 `4%`：来源于数据，不是设计值；越界值在组件内收敛到 `0~100`。

`LoadingSpinner` 的 `size` 传 `24`（首屏）与 `16`（按钮内），为该组件既有数值 API，不是新样式值。

可读性：本页为工作台页面（非大屏），主文字 16/14px、辅助 12px；`--color-text-tertiary` 对比度已由 token 注释保证 AA；趋势轴标签 7 列在 390px 宽度下为 `(390 - 2×20 - 6×8) / 7 ≈ 43px`，`MM-DD` 5 字符 12px 等宽数字可容纳。

## 4. 三态与异常数据

| 层级 | 加载中 | 空数据 | 失败 | 异常数据 |
| --- | --- | --- | --- | --- |
| 页面 | 首屏整页 `LoadingSpinner` + 「加载中…」；刷新时保留内容、按钮转圈 | 无源 → `EmptyState`（可跳设置页源管理区） | 源表读取失败 → `ErrorState`（重试 / 返回设置），不渲染半截卡片 | — |
| HealthSummary | 4 个骨架块（占位高度 `calc(--space-10 + --space-3)`） | 总数 0：四项显示 0 + 「尚未添加任何源」 | 由页面承载 | 计数取服务层归一化结果 |
| HealthTrend | 骨架块替代柱图 | 全未采集：保留 7 列轴，全部「—」+ 说明「暂无历史趋势」 | 由页面承载 | 超过 7 点只取最后 7；健康率越界收敛 0~100；柱高 ≥4% 保证 0% 可见 |
| FailureDistribution | 2 行骨架 | 无失败源：成功色提示，不渲染 0 值条 | 由页面承载 | `percent` 越界收敛 0~100，进度条不溢出 |
| BatchActions | 当前动作按钮显示 spinner + 进度文案，其余按钮禁用 | 三个目标数均为 0：全部禁用 + 「当前没有可批量处理的源」 | 单项失败不中断，结果提示带失败数 | 复检中额外出现「取消复检」，走 `cancelHealthCheck()` |

其它边界：

- 批量操作进行中屏蔽其余批量入口（`healthCenterBusy !== null`），避免并发写库；
- `cleanupFailedSources` / `restoreDisabledSources` 内部用 `batchDepth` 抑制逐条 `sources:changed` 重载，结束后统一 `reload()` 一次；
- 页面卸载置 `alive = false`，异步批量完成后不再弹 toast；本页不注册定时器/全局监听，无泄漏面（复检的 `AbortController` 由 store 持有并在 `refreshHealth` 的 `finally` 中释放）。

## 8. 需协调者确认 / 遗留

1. **设置页缺少进入入口**：`src/views/SettingsView.vue` 不在本任务允许修改范围，因此 `/health-center` 目前只能通过路由直达。建议在设置页「源管理」区增加一行「源健康中心」入口（属其它文件的改动，需协调者派单）。
2. **复检范围受 `sourceService.checkHealth` 限制**：该方法内部过滤 `enabled` 源，因此「复检所有失败源」实际覆盖**启用中的失败源**，已禁用的失败源必须先「恢复」才会被探测。已在按钮下方文案与确认说明中写明；若要复检禁用源，需要改 `sourceService`（超出本任务文件范围，且影响既有 OPT-03 语义）。
3. **清理口径与源管理页不同**：本页「清理失败源」包含 `timeout`（源管理页 `disableUnhealthy` 排除 `timeout`，理由是可能为瞬时慢）。本页由用户显式确认且确认框已写明「其中含「连接超时」的源」，符合本任务「批量清理所有失败源」的字面要求；若产品希望两处统一排除 `timeout`，请给出结论后我调整。
4. **趋势是「访问驱动」而非后台每日采集**：快照在进入页面/批量操作后按日 upsert，应用未打开的日子没有记录（趋势图显示「—」）。若要后台每日自动记录，需在启动流程（`stores/bootstrap.ts`）挂钩子，不在本任务允许文件范围内。
5. **`clearHealthTrend` 已导出但无 UI 调用**：留给后续数据清理链路（重置全部数据/备份清理）复用，避免以后重复实现 key 与清洗逻辑。
6. **入口与导航标题**：路由 `title: '源健康中心'`，页面内 `AppHeader` 标题一致；`requiresLayout: false` 与其它二级页（logs/backup/about）一致，页面自行提供顶栏。
