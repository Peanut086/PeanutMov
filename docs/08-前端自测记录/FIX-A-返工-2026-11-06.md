## 1. REV-27（P1）master → 变体清单的 DRM 漏判

### 1.1 改动

- 顶层清单命中 `#EXT-X-KEY` / `#EXT-X-SESSION-KEY` 非 AES-128 → 立即返回证据；
- 顶层含 `#EXT-X-STREAM-INF` 时解析变体地址（相对地址按清单地址解析），**并发 3** 拉取子清单做同口径断言；
- 变体仍是 master 时继续展开一层，**总探测数上限 8**（含顶层），异常清单不会无限展开；
- 全程响应 `options.signal`：中止后不再发起新请求；单次请求超时仍为 `MANIFEST_PREFLIGHT_TIMEOUT_MS`（4s）；
- **子清单任何失败（CORS/网络/超时/非 2xx/取消）只跳过该子清单**，`drm` 保持 `null`，放行给 hls.js；
- 命中发生在 `attachEngine()` 内、创建任何引擎之前（`PlayerController.ts:254-258` 先 `supersedePreflight()` 再 `runManifestPreflight()`），不创建 `<video>`、不发分片请求；
- 子清单地址不再要求 `.m3u8` 后缀（来自 `STREAM-INF` 的地址本身就是清单），避免 CDN 无后缀导致漏扫。

### 1.2 验证（构造两级清单复现）

临时探针（不在 `tests/**`，跑完已删除）构造：

```
master.m3u8
  ├─ 360p/index.m3u8  → 普通清单
  └─ 1080p/index.m3u8 → #EXT-X-KEY:METHOD=SAMPLE-AES,URI="skd://license"
```

结果（探针用例 `REV-27 master → 变体清单 DRM 预检`）：

| 断言 | 结果 |
| --- | --- |
| `ctl.load()` 拒绝，文案命中「不支持受保护内容」 | 通过 |
| error 事件序列 `['E_DRM_PROTECTED']` | 通过 |
| `document.querySelector('video') === null`（未创建引擎） | 通过 |
| 网络请求恰为 3 次：master + 两个变体 | 通过 |
| 无任何 `.ts` 分片请求 | 通过 |
| 子清单 fetch 抛错场景：错误为 `E_UNSUPPORTED_FORMAT`（hls.js 不支持），**不含** `E_DRM_PROTECTED`，请求 3 次 | 通过 |

## 2. REV-28（P1）取消信号写入错误面板 + 一次切集两次加载

### 2.1 改动

1. `usePlayerController.load()`：`catch` 首行 `if (isCanceled(e)) return;`（`E_ABORTED`/`AbortError` 不再写 `player.error`）；成功路径 `if (player.error) player.patch({ error: null })`，旧一轮失败不残留。
2. 切集单一入口：`chooseEpisode` 只做 `router.replace`，删除其 `resolveAndLoad()` 调用；加载统一由 `watch(episodeIdParam)`（`PlayerView.vue:1133`）触发。线路切换仍用既有 `pendingLineSwitchEpisode` 精确吞掉自己发起的那一次。
3. 加载代次 `loadEpoch`：`resolveAndLoad()` 每次自增；`resolvePlay`/`preparePlayback`/`load` 之后以及 `catch`/`finally` 都校验代次——
   - 过期任务不得写 `loadError`、不得关掉新任务的 `pageLoading`；
   - 慢的旧任务不会反过来顶掉新任务（在调用 `load()` 前就被代次拦下）。

### 2.2 验证

- 探针用例「被取代的加载不得写错误面板」：第一集加载挂起 → 第二集加载完成 → 第一集以 `E_ABORTED` 被拒绝 → `player.error` 仍为 `null`，**通过**。
- 调用点静态核对（`grep -n "resolveAndLoad()" src/views/PlayerView.vue`）：

```
410: async function resolveAndLoad            // 定义
531: onMounted 首次加载
642/654: switchLine 成功/回退
724: retryWithNativeEngine
812/847: 自动/手动换源
1137: watch(episodeIdParam) → await resolveAndLoad()
```

`chooseEpisode`（L991-1002）体内已无 `resolveAndLoad()`；选集后只有 watcher 一条加载链路，即「一次切集一次加载」。

- 局限：页面级「清单请求数不翻倍」的端到端断言需要真实路由 + fetch 计数，建议由评审&测试补（见第 7 节第 4 条）。

## 3. REV-30 / REV-31（P2）标签大小写绕过 + SESSION-KEY 未扫描

### 3.1 改动

- 判定收敛为唯一实现 `findProtectedKeyEvidence`（`sourceGuard.ts:54`）：
  - 标签正则 `^#EXT-X-(?:SESSION-)?KEY:(.*)$/i`（覆盖 `#ext-x-key:`、`#ext-x-session-key:`）；
  - 属性名大小写不敏感，允许 `METHOD = "SAMPLE-AES"` 的空格写法；
  - 支持集合仅 `NONE` / `AES-128`，其余（SAMPLE-AES / SAMPLE-AES-CTR 等）一律判受保护。
- 下载侧 `assertSupportedKeyMethods`（`hlsDownloader.ts:322`）直接复用该判定，错误 detail 带命中行，双端口径不再漂移；
- `parseAttributes`（L230）属性名统一大写、值去空白，允许等号两侧空格。

## 8. 局限与说明

- REV-27 的验证基于 mock fetch（happy-dom），未在真机/真实 CDN 复测；子清单因 CORS 拉取失败时按约定放行（AC-40 要求不把网络失败误判 DRM），此为已知取舍。
- `SESSION-KEY` 只做「命中即拒绝」，不解析其 URI/AES-128 一致性；本单只要求纳入同一断言。
- 下载侧 `parseMediaPlaylist` 的标签识别仍按 HLS 规范大小写（`#EXT-X-KEY:`）；拒绝对话在解析前的守卫，未扩大改动面。
- 网盘列表状态在 App 重启后仅能依据 cookie 文件内容推断（`a` 字段由原生侧仅在账号校验通过时写入非空昵称，AND-07 已保证），建议真机复核非夸克平台的「已保存，账号未验证」文案。
- 对契约/设计无疑问，未自行变更任何字段与接口行为。
