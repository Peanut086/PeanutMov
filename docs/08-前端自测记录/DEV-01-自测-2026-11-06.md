## 5. 未验证项、风险与遗留

1. **真机 302 未复测（FIX-04）**：Node 环境无 CapacitorHttp，302 的「代理跟随跳转 / 回退直连」只在 JS 契约层验证。Android 侧 `LocalProxyPlugin` 的清单改写与本批后端改动（`isM3u8` 用最终地址判定、`EXT-X-*` 通用 URI 改写）已核对代码，仍需真机用本地 302 mock 复验；建议放在批次 2 真机验收（OPT-10）。
2. **代理改写 token 的兼容路径**：LocalProxy 对 `/p/{token}/{encoded}/{子地址}` 请求生成的新 URL 使用的是「按 target.url 反查 token」，子清单场景会得到未登记 token。JS 侧已通过 `unwrapProxiedUrl` 还原 + 重新编码规避；若后续原生侧改为直接复用请求 token，本逻辑仍幂等，可保留。
3. **下载队列重试策略**：`downloadQueue.decideAfterFailure` 只看 `retries < maxRetries`，不读 `retryable`，因此 DRM 任务会按通用策略重试到上限才置 failed（每次都重新拉清单、仍不会写分片、不会完成）。不在本任务改动范围（`src/services/downloadQueue.ts` 未改），建议批次 2 统一按 `AppError.retryable` 短路。
4. **`SourceListView.vue` 仍为未注册路由的死视图**：本任务按要求只做最小类型标注，未删除；FIX-01/Q-04 决定其去留。
5. **测试文件由 QA 并行维护**：本次运行结果对应共享工作区当时状态；若 QA 后续调整用例，以 QA-01 的交付记录为准。
6. **未改动**：`tests/**`、`android/**`、接口契约、设计 token；未新增 TODO / `console.log`（临时自测脚本已删除）。
