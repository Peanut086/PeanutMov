## 1. 实现口径

### 1.1 标题归一化（`TitleNormalizer`）

| 输入 | `normalizeTitleKey` 结果 | 说明 |
| --- | --- | --- |
| `庆余年第二季` / `庆余年 第二部` / `庆余年 第2季` | `庆余年` | 季/部/篇剥离 |
| `繁花 第5集` / `进击的巨人 第五话` | `繁花` / `进击的巨人` | 集/话/期/回剥离 |
| `The Office Season 2` / `Part 3` / `S03` | `theoffice` | 英文季号剥离 |
| `庆余年 高清 完整版` / `流浪地球2 HD 1080P` | `庆余年` / `流浪地球2` | 修饰词剥离 |
| `庆余年（2024）` / `庆余年[高清]` / `庆余年【特别篇】` | `庆余年` | 括号内容整体剔除 |
| `繁花 2023 版` | `繁花` | 仅剥**末尾**年份 |
| `2001太空漫游` | `2001太空漫游` | 年份在片名中，不得误剥 |
| ` 三体· 黑暗森林 ` | `三体黑暗森林` | 标点/空白剔除 |

匹配评分 `titleMatchScore()` 的三条硬规则（宁可不播，不可串片）：

1. 两侧都有季号且不同 → `0`（`庆余年第二季` ≠ `庆余年第一季`）；
2. 剥掉季号后两侧尾部数字不同 → `0`（`流浪地球` ≠ `流浪地球2`）；
3. 单侧有季号时做消解：`庆余年第二季` ↔ `庆余年` / `庆余年2` 均判 `1`；
   其余按编辑距离相似度，短名被长名包含（≥2 字且占比 ≥0.6）抬到 `0.9`；阈值 `DEFAULT_TITLE_THRESHOLD = 0.82`。

### 1.2 豆瓣剧集标识与集数定位

- 构造：`buildDoubanEpisodeId(movieId, n)` → `douban_{movieId}_{n}`；`n` 非法（≤0/NaN）兜到 1。
- 解析：`parseDoubanEpisodeId()` 兼容 `douban_{movieId}_{n}`、旧 `douban-{mediaId}-{n}`（含 `douban-src:100~x-2`）；
  空串视为第 1 集（电影只有「正片」）；非空但无法解析 → `null`，调用方报 `E_INVALID_INPUT`（**不猜集数**）。
- 定位：`selectEpisodeInDetail(detail, n)`
  1. 线路按**剧集数降序**（避免「预告」这类单集线路抢走第 1 集），同数量按 `index`；
  2. 先按 `Episode.number === n`，再按剧集标题解析出的集号（`第5集` / `EP05` / `05`）；
  3. 都不中返回 `null`。

### 1.3 映射服务（`EpisodeMappingService.resolve`）

对每个候选（保持 `pickPlayCandidates` 的质量排序、按 `源 id + 条目 id` 去重）：

```
片名 titleMatches? ──否──▶ miss: season_mismatch / title_mismatch
   │是
年份双方都有且不等? ──是──▶ miss: year_mismatch（detail = "2024 / 2019"）
   │否
getDetail（缓存） ──抛错──▶ E_NOT_IMPLEMENTED/E_UNSUPPORTED_FORMAT/E_SOURCE_DISABLED → detail_unavailable
   │                       其余错误 → detail_failed（detail = 原始 message）
   │成功
episodes 为空? ──是──▶ miss: no_episodes
   │否
selectEpisodeInDetail(n) ──null──▶ miss: episode_out_of_range（detail = "共 N 集"）
   │命中
target = { source, item, line, episode, lineId, episodeId, episodeNumber, episodeTitle }
```

缓存：映射级（含**否定结论**）+ 详情级，各默认 64 条 / 5 分钟，LRU 淘汰；`clear()` 供换源/订阅变更后清空；
`stats()` 暴露 `detailEntries / mappingEntries / cacheHits / detailFetches`。

### 1.4 `DoubanAdapter.resolvePlayUrl` 新流程

```
assertEnabled → parseDoubanEpisodeId(episodeId) ──null──▶ E_INVALID_INPUT「无法识别的剧集标识」
→ mediaRepo.get(mediaId) 取片名/年份 → resolvePlayFrom 取候选
→ doubanEpisodeMapping.resolve({ title, year, episodeIndex, candidates })
→ attempts = 映射命中集（有则用）——否则仅当 episodeIndex === 1 时透传旧 id——否则空
→ attempts 为空 → E_NO_PLAY_URL「已启用的源里没有第 N 集」（detail = 各源未命中原因）
→ 逐个候选调目标适配器（传目标源自己的 lineId/episodeId），失败顺延（CHG-12 不变）
```

- 旧实现把豆瓣自己的 `episodeId`/`lineId` 透传给目标源，目标源的 `list[i>=0?i:0]` / `lines[i>=0?i:0]`
  会静默落到第一集 → 修复后 `N > 1` 且映射不中时**直接报错**。
- 「第 1 集」保留透传兜底：首集本身就是用户点的集，不存在降级；这样单集电影/历史 id 场景不会因目标源
  拿不到剧集清单而突然不可播（同时保证既有 `tests/unit/doubanAdapter.spec.ts` 的 CHG-12 顺延语义不变）。
- 目标适配器的 `getDetail` 通过 `doubanRuntime.adapterGetter` 在调用时取（装配滞后，不能在建实例时捕获），
  适配器不支持详情 → `E_NOT_IMPLEMENTED` → 映射记为 `detail_unavailable`。

### 1.5 `SpiderAdapter` 改动

- `locateEpisode(lines, rawEpisodes, lineId, episodeId)`：
  1. 指定线路且该线路有这一集 → 用它；
  2. 线路 id 失效（库缓存过期）但**别的线路**有这一集 → 换线路，**不换集**；
  3. `episodeId` 为空（单集电影/未指定集）→ 首条线路第 1 个有地址的剧集（语义正确的默认）；
  4. `episodeId` 非空但哪条线路都没有 → `null` → 抛 `E_NO_PLAY_URL`「该源没有这一集」（`retryable: false`）。
- `findEpisodeByTitle(title, episodeIndex, ctx)`：`search` → `titleMatches` + 年份筛选 → `titleMatchScore` 排序 →
  逐个 `getDetail` + `selectEpisodeInDetail` → 返回 `SpiderEpisodeMatch`；没有这一集返回 `null`，
  候选详情**全部**失败时抛出最后一次真实错误（与「没有这一集」区分）。

## 5. 对契约 / 设计的疑问（上报协调者）

- **Q1（需要口径决定，本次未实施）**：豆瓣详情只有 1 集（`toDetail` 造一条「正片」），而本任务的场景是
  「选第 N 集」。要让用户在豆瓣条目上真的能选第 N 集，必须让豆瓣详情具备集数——可选方案：
  (a) 扩展 `doubanClient` 解析豆瓣条目的集数/分集信息（需改 `doubanClient.ts`，超出本次文件范围）；
  (b) 豆瓣详情阶段就跨源借用目标源的剧集清单（等于把映射前移到详情，改动面更大，且会放大详情页的请求量）。
  两方案都超出「只改 4 个文件」的授权，故本次只保证 `resolvePlayUrl(episodeId)` 的映射正确与不降级。
- **Q2（口径待确认）**：`SiteAdapter.resolvePlayUrl` 的「找不到 lineId 取第 0 条、找不到 episodeId 取第 0 集」
  与本任务「不静默降级」的要求相冲突，但该文件不在允许修改范围。是否后续任务统一收紧为与 `SpiderAdapter`
  相同的 `locateEpisode` 口径？（本次未改，避免越界。）
- **Q3（类型外扩，需确认可接受）**：为让映射拿到目标源详情，`DoubanAdapter.ts` 内的 `DoubanAdapterGetter`
  增加了**可选**成员 `getDetail?(params)`。这是模块内装配类型、不是 API 契约字段，`doubanRuntime.ts` 现有
  `sourceRegistry.forSource`（完整 `SourceAdapter`）结构性兼容、类型检查已通过；如协调者认为装配类型也属契约，
  可退回改为「单独注入 `detailGetter` 字段」。
- **Q4（错误文案归属）**：映射失败时对外文案是「已启用的源里没有第 N 集」，未命中原因（片名不符/季数不符/共 N 集）
  放在 `AppError.detail`。若产品希望 UI 上给出「换源」引导或区分「片子对但集数不够」，需要设计/文案口径。
