### 1.1 CMS 采集入口（AC-115 / FR-50）

- 入口路径：我的 → 内容「片源管理」→ 新增源 → 源类型「采集接口」
- 操作步骤：
  1. 打开「新增源」，类型卡出现第 5 项「采集接口 / macCMS JSON」；
  2. 服务器地址填 `http://127.0.0.1:59999/api.php/provide/vod/at/json`，失焦后名称自动填 `127.0.0.1`；
  3. 「子路径」字段隐藏，提示文案为「粘贴 macCMS 采集端点（provide/vod JSON）。建议先『测试连接』探测，再保存；保存后可直接搜索与播放。」；
  4. 点「测试连接」（端点不可达）→ 就地显示失败「网络不可用，请检查网络后重试」；
  5. 点「保存」→ 列表新增，类型显示 `SITE`。
- 结果：**通过（创建链路）**。读 IndexedDB 确认落库为
  `type: "site"`、`ext: { cmsDirect: true, searchable: true }`、名称取主机名。
- 限制：搜索/播放端到端需可达的 macCMS 端点，本次用不可达端点仅验证了「探测 → 创建」；
  搜索/播放沿用既有 site 适配器，建议评审&测试用真实端点回归。

### 1.5 批量清理（FIX-01）

- 入口路径：我的 → 片源管理 → 「禁用 N 个失效源」/「清理 N 个已禁用源」
- 操作步骤与结果：
  1. 造 1 个 `unreachable` 启用源，点「禁用 1 个失效源」→ 确认弹窗列出源名，说明「连接超时不会被禁用，可随时重新启用」；
  2. 确认后：按钮变「禁用 0 个失效源」，「清理 1 个已禁用源」变为可点；
  3. 点「清理 1 个已禁用源」→ 二次确认（不可撤销、内置/在用源不受影响、下载文件不删除）；
  4. 确认后：列表只剩内置演示源。
- 结果：**通过**；批量执行使用并发 4 + 进度文本（`处理中 n/total`），批量期间抑制 `sources:changed` 逐条 reload，结束统一刷新一次，
  避免 183 源场景 N 次串行阻塞。
- 说明：清理范围 = `enabled=false && builtin=false`；「禁用失效源」不含 `timeout`（瞬时网络慢），与旧 `SourceListView` 口径一致。

## 2. OPT-03：健康检查可取消 / 仅失败源 / 超时口径

- **取消**：检测中按钮变为「取消」；点击后 UI 立即回到「健康检查」状态（实测 400ms 内），
  未完成的源保持「未检测」，无错误 toast。
  实现：`cancelHealthCheck()` → `AbortController.abort()` → `healthService` → `sourceService.checkHealth(ids, signal)`；
  `runWithConcurrency` 增加 abort 事件与 `Promise.race`，所有 worker 都在飞行中时也能**立即返回**（否则要等单个探测超时）；
  未完成探测返回后检查 `signal.aborted` 并丢弃结果（不 `markHealth`）；取消后刷新一次列表，让取消前已完成的探测结果可见。
- **仅检测失败源**：复用 `healthService.check(ids, signal)`，不会写 10 分钟缓存之外的错误数据；
  目标为 0 时按钮禁用，点击给出「没有需要复检的失败源」提示。
- **超时口径**：`shared/constants.ts`、`sourceService.checkHealth` 注释统一为
  「最坏耗时 ≈ 启用源数 × 单源探测超时 ÷ 并发数（183 个冷启 spider ≈ 183 × 35s ÷ 6 ≈ 17.8 分钟）」，
  删除「183 条全量检测要 2 分钟」的错误口径；UI 只展示实时进度，不承诺固定时长。
