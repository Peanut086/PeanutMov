## 1. 口径（唯一真值，均落在 `ImportDiagnosticService.ts` / `importService.ts`）

| 概念 | 口径 | 说明 |
| --- | --- | --- |
| 阶段 | `parse` → `probe` → `import` → `done` | 步骤条顺序即数组顺序，`stageIndexOf('idle') = -1`（不点亮任何阶段） |
| jar 目标 | 条目 `type === 'spider'` 且 `valid` 且 `normalized.ext.kind === 'jar'` 且 `ext.jarUrl` 去空格后非空 | 非爬虫 / python 爬虫 / 缺地址 / 非法条目都不探测 |
| jar 判定 | `ok` / `dead` / `unknown`（沿用 CHG-10） | `dead` = HTTP 4xx/5xx；`unknown` = 超时 / 405 / 501 / Web 端网络错误（不据此判死） |
| 只保留存活源 | **判死 jar 的条目一律取消勾选且不写入**：`applyJarSummaries` 幂等回写，`importWithDiagnostic` 在提交前无条件再跑一次 | 不依赖调用方传入的预览是否已标记过；`selectedKeys` 显式传数组，避免 `commit` 的空数组=全量语义 |
| 失败分类（预览侧） | `jar_missing` / `jar_unreachable` / `invalid_config` / `duplicate` | 无效条目按 `issue.field === 'jar'` 精确归到 jar 缺失；`duplicate` 仅在 `onDuplicate === 'skip'` 且确有导入结果时产生 |
| 失败分类（健康侧） | `timeout` / `unreachable` / `bad_config` / `auth_failed` | 与 `healthCenterService.FAILURE_REASON_META` **逐字复用** label/hint（单测守卫），仅在 `subscriptionId` 非空时追加，同 key 去重（预览侧优先） |
| 分类聚合 | 只输出计数 > 0 的原因，按数量降序；并列按固定顺序 `jar_missing → jar_unreachable → timeout → unreachable → bad_config → auth_failed → invalid_config → duplicate → unknown` | `percent = Math.round(count / 失败总数 * 100)` |
| 存活 | 存活 = 健康（`ok`），复用 `summarizeSources` | `alivePercent = Math.round(healthy / total * 100)`，`total = 0` 时为 0 |
| 耗时估算 | 只算 `ok` 的 jar；体积取 `content-length`，缺失按 `DEFAULT_JAR_BYTES`(3MB) 计入并在 `assumedCount` 标注 | 吞吐按探测平均延迟分档：`<150ms → 1500KB/s`、`<400 → 800`、`<900 → 400`、其余 `180`；`seconds = 体积/吞吐/2 + 探测开销`，下限 1s |
| 报告 | `version: 1`，含 `summary / alive / buckets / failures / probes / warnings` | `summary.total` 取预览条目总数，`failed` 取失败明细条数，`jarDead` 取判死 jar 数，`durationMs` 取诊断真实耗时 |
| 自动禁用 | 写入成功后按 `subscriptionLifecycleService.applyHealthDegradation()`（连续 3 次 bad → 禁用），`autoDisable: false` 可关闭 | 动态 `import()` 规避与 `subscriptionLifecycleService`（其顶部 import `importService`）的循环依赖 |
| 取消 | 解析/探测阶段即时中止；写库前检查 `signal.aborted` → 返回 `status: 'canceled'`（仍产出报告，`pending` = 未处理条目数） | `commit` 是单事务，开始后不可中断，不做"半途回滚"的假承诺 |

```

                                                                    └─► importWithDiagnostic（复用 preview/probes）
```

非 token 的可视值（全部结构性、无法用 CSS 变量表达）：

1. `@media (min-width: 600px)`：与 `tokens.css` 既有断点一致，媒体查询不支持 `var()`；
2. `min-height: 100vh`（页面根节点）：沿用 `HealthCenterView` / `LogsView` 等二级页写法；
3. `line-height: 1.6`（多行明细/说明）：与 EXT-01 `Footer` 的 `1.65` 同类，用于 12px 长文可读性；
4. 数据驱动的内联样式（占比 `width: n%`、存活率 `width: n%`）：来源于数据，组件内已收敛到 `0~100`。

可读性：工作站页面（非大屏），主文字 16/14px、辅助 12px；`--color-text-tertiary` 对比度由 token 注释保证 AA（深色 4.7:1 / 浅色 6.2:1）。URL 明细用 `truncate-1` 单行省略 + 完整值仍在报告 JSON 中可查。

## 4. 三态与异常数据

| 层级 | 加载中 | 空数据 | 失败 | 异常数据 |
| --- | --- | --- | --- | --- |
| 页面 | 主按钮「诊断中…」+ 步骤条 spinner + 取消入口 | 未开始/已预取 → `ImportSummary` 空态引导（「完成一次诊断后…」）；解析成功但 0 条目 → `EmptyState`「订阅里没有可导入的源」 | `ErrorState`（可重试），不渲染半截预览 | 非 http(s) 地址在本地拦下；`jarProbe: false` 时跳过探测但仍出报告 |
| 步骤条 | active 阶段显示 12px spinner | `idle` 时全部灰色待办 | — | 越界阶段下标 → `stageIndexOf` 返回 -1，不点亮 |
| ImportSummary | 4 个骨架块 | `result === null` → 引导文案，不渲染 0 值宫格 | 由页面承载 | 计数非数字按 0；存活率收敛 0~100；无可达 jar 时估算文案改为「没有可达的 jar」 |
| FailureClassification | 2 行骨架 | 无失败条目 → 成功色「本次导入没有失败条目」 | 由页面承载 | `percent` 收敛 0~100；空名称/空地址/无错误码显示「—」；超过 `maxVisible`（10）折叠为「展开全部 n 条」 |
| 源状态行 | 由步骤条进度承载 | 无条目走 `EmptyState` | — | jar 判死 → 「jar 不可达」+ 探测明细；无效 → 「配置无效」+ 首条 issue；未勾选 → 「未勾选」 |

其它边界：

- 页面卸载：`alive = false` + `abortRef.abort()`，异步完成后不再写状态/弹 toast；无定时器、无全局事件监听，无泄漏面（`downloadFailureReport` 内部的 60s `setTimeout` 与备份导出一致，只做 ObjectURL 回收）；
- 诊断与导入同一时刻只允许一个在途（`busy`），进行中隐藏同名策略选择器，避免中途改口径；
- 导出前校验 `result.report` 存在，`downloadFailureReport` 返回 `false` 时提示失败而不是假装成功；
- 清理失败源复用 `store.cleanupFailedSources`（内部 `batchDepth` 抑制逐条重载），确认框说明「不删除配置，可随时恢复」。

## 8. 需协调者确认 / 遗留

1. **设置页缺少进入入口**：`src/views/SettingsView.vue` 不在本任务允许修改范围，`/import-diagnostic` 目前只能通过路由直达（`?url=` 可预填地址）。建议在设置页「源管理」区补一行「导入诊断」，需另行派单。
2. **`applyHealthDegradation()` 是全局口径**：它按「连续 3 次体检 bad」禁用**所有**满足条件的源，不限于本次订阅。这符合 FR-51 的既有语义，但「导入后自动禁用」的字面范围可能被理解为「仅本次导入的源」。若要收窄，需要在生命周期服务新增按 `subscriptionId` 过滤的入口（超出本任务文件范围）。当前实现会在结果里如实报告本次禁用数量（`autoDisabled`）。
3. **耗时估算是经验档位，不是真实测速**：`content-length` 可读时按真实体积，吞吐按 HEAD 延迟分档推断；跨域读不到体积时按 3MB 估算并在 UI 标注「其中 n 个按默认体积估算」（`assumedCount` / `measured`）。若要求更高精度，需要下载引擎先做小样本测速（跨模块改动）。
4. **`importWithDiagnostic` 会再跑一次 `applyJarSummaries`**：即使调用方传入的预览已把某条目标记为可导入，只要探测结论是 `dead`，提交前仍会取消勾选（安全优先，且幂等不重复拼文案）。若希望「用户手工勾选死 jar 也允许写入」，需要在契约里明确例外规则——当前按「只保留存活源」执行。
5. **取消只覆盖写库之前**：`commit` 是单事务，无法中途回滚；已进入写库的取消请求会被忽略并在完成后返回 `status: 'done'`。视图侧取消按钮仅在 `busy` 期间出现，避免给出"事务可中断"的错觉。
6. **`jarProbe` 降级路径**：`httpClient.requestWithMeta` 不可用时（受限环境/轻量替身）退化为 `request`，此时拿不到 `content-length` 与状态码，判死仍依赖错误码（如 `E_HTTP_403`），估算全部走默认体积。生产环境走 `requestWithMeta`，不影响需求。
7. **契约登记**：本任务在 `ImportService` 接口上新增了 `prefetchImport` / `importWithDiagnostic` 两个方法（只增），未改 `ImportPreview` / `ImportResult` / `ImportCommitOptions`。若方案文档 API-05 需要补登这两个入口，请由架构师更新（按角色约束我不改契约文档）。
8. **既有浮动用例（非本任务引入，未越权修改）**：`tests/views/HealthCenterView.spec.ts > 无源时展示空态，主按钮跳转设置页源管理区` 在全量并行高负载时偶发失败（断言时仍处于「加载中…」，即 `settle()` 轮询次数不够）。该文件不在本任务允许修改范围，建议由 EXT-01 维护者把 `settle()` 改为条件等待（如 `await vi.waitFor(() => expect(...))`）。
