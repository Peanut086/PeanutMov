## 1. 能力分级口径（唯一真值）

| 平台 key | 名称 | `capabilityLevel` | `memberApi` / `accountApi` | UI 声明 |
| --- | --- | --- | --- | --- |
| `quark` | 夸克网盘 | `full-api` | 均具备 | 状态显示 `未登录` / `已登录（昵称）`；有会员类型时显示 `会员：xxx` |
| `uc` | UC网盘 | `cookie-only` | 均无 | `Cookie 直填、账号能力未验证` + `不提供会员/容量信息` |
| `123` | 123云盘 | `cookie-only` | 均无 | 同上 |
| `tianyi` | 天翼云盘 | `cookie-only` | 均无 | 同上 |
| `ali` | 阿里云盘 | `cookie-only` | 均无 | 同上 |

配套约束（由单测守卫，漂移即红）：

1. `full-api` 平台必须同时具备 `accountApi` 与 `memberApi`，且**不得**带 `capabilityNote`；
2. `cookie-only` 平台**不得**出现任何 `*Api` 字段，且必须带 `capabilityNote`；
3. 展示顺序固定为 `['quark','uc','123','tianyi','ali']`——`Record` 的 `'123'` 是类整数键，`Object.values()` 会把它排到最前，把「完整支持」的夸克挤到第二位；`getAllPlatforms()` 改为按 `NETDISK_PLATFORM_ORDER` 输出（未列入的 key 追加在尾部，新增平台不会丢失）。

## 4. 三态与异常数据处理

| 场景 | 表现 | 实现位置 |
| --- | --- | --- |
| 空数据 | 平台清单来自静态配置（恒 5 项）；由组件用例断言 5 张卡片 | `tests/components/NetdiskSettingsCapability.spec.ts` |
| 加载中 | 首帧 `saved=false` → 全部 `未登录`；`readCookieFile` 逐平台返回后覆盖，无骨架屏（沿用既有实现，未新增跳变） | `checkLoginStatus()` |
| 接口失败 | `readCookieFile` 抛错 → 该平台回落 `未登录`；权限查询失败 → 顶部授权横幅；登录失败 → toast，不写文件 | `checkLoginStatus()` / `checkPermissions()` / `login()` |
| 异常数据（状态未知） | `capabilityLevel` 非 `full-api` 一律按 cookie-only 处理（白名单写法，未知值不会误报「已登录」） | `isCookieOnly()` |
| 异常数据（能力说明缺失） | `capabilityNote(platform)` 回退到 `COOKIE_ONLY_CAPABILITY_NOTE`，不会渲染空提示 | `capabilityNote()` |
| 异常数据（昵称/说明超长） | `overflow-wrap: anywhere`，卡片高度自适应 | 样式层 |
