# TVBox 爬虫源（type 3）支持 — 实现与实测记录（2026-10-23）

订阅：`http://xhztv.top/4k.json`

## 1. 背景

该订阅共 53 条源，改造前只能导入 14 条，其余 39 条被 `URL_INVALID` 跳过：
它们的 `api` 是 `csp_XBPQ` / `py_cctv_full` 这类 TVBox 爬虫类名，不是 http(s) 地址。
本次实现 jar 爬虫运行时后，**53 条全部可导入**。

## 3. 原生运行时要点

1. **类名映射**：`api` 为 `csp_XBPQ` 时，jar 内实际类是 `com.github.catvod.spider.XBPQ`（去掉 `csp_`/`py_` 前缀）。插件依次尝试 `XBPQ` → `csp_XBPQ` → 裸类名。
2. **初始化必须走实例类型**：`init(Context,String)` / `initApi(SpiderApi)` 若用基类 `Spider.class.getMethod()` 会命中 stub 的空实现，爬虫配置全部丢失（表现为 `homeContent` 返回空）。必须 `spider.getClass().getMethod(...)`。
3. **List/Map 形参**（实测踩坑）：
   - `categoryContent(tid, pg, filter, HashMap)` —— 第 4 参必须传对象，传 `'{}'` 会报 `argument 4 has type java.util.HashMap, got java.lang.String`。
   - `detailContent(List<String> ids)`、`playerContent(flag, id, List<String> vipFlags)` —— Capacitor 桥接会把嵌套数组 `[['1']]` 展平成 `"1"`，反射报 `argument 1 has type java.util.List, got java.lang.String`。解法：JS 侧用 `arrayArgs: { 0: ['1'] }` 按位置下标显式传数组。
4. **md5 校验**：`jarUrl` 含 `;md5;hash` 时下载后比对，不一致直接丢弃。

## 4. 导入失败的真实原因（DataCloneError）

改造后首次真机导入报「本地数据读写失败」。根因不是数据库，而是：

```
DataCloneError: Failed to execute 'put' on 'IDBObjectStore': #<Object> could not be cloned.
```

订阅预览存在 Vue 的 `ref` 里，`ext` 被包成**响应式 Proxy**，IndexedDB 的结构化克隆无法克隆 Proxy。
站点源的 `ext` 多为 `null` 所以历史上没暴露；44 个爬虫源全带 `ext`，整批写入即失败。

修复：`sourceRepo.toStorableSource()` 用 JSON 往返还原纯值，覆盖 `save` / `saveMany` 与导入的批量写入。
回归用例：`tests/unit/importProxyClone.spec.ts`（含真实 4k.json 53 条整批导入）。

## 7. 已知限制

- **JS 爬虫（drpy）不执行**：`api` 为 `.js` 的条目可导入但带警示，浏览时不可用。
- **全局 `spider` 失效**：本订阅顶层 `spider` 指向的 `fan.txt` 返回 403，依赖它的 20 个条目虽能导入但加载失败。
- **H5 端不支持**：dex 只能在 Android 执行，网页端返回 `E_NOT_IMPLEMENTED`。
- **`proxy()` 未接播放器**：爬虫代理流已实现插件方法，但播放器尚未走代理（直链可直接播放）。

## 8. 补充：豆瓣源改为「发现源 + 跨源播放」（2026-10-24）

### 8.1 为什么不做 QuickJS

扫描 95 个订阅地址，得到 15 个 drpy 源，规则可下载 6 个，其中 3 个规则里带播放逻辑。
逐个实测，**可用 0 个**：

| drpy 源 | 规则有播放逻辑 | 实测失败原因 |
| --- | --- | --- |
| 🦉 夜猫秒播 | 有 | 通用框架，host 从 ext 读取，该订阅未配置 |
| 🐠 斗鱼直播 | 有 | 列表接口 `{"code":2,"data":"分类信息不存在"}`；取流靠 `live.yj1211.work`，域名解析失败 |
| 🐯 虎牙直播 | 有 | 列表可用（10 个房间），但所有取流路径都指向已失效的 `live.yj1211.work`，无备用 |
| 🥇 JRKAN 直播 | 有 | 赛事列表是空模板，数据靠 JS 动态渲染 + crypto-js 加密，CSS 选择器抓不到 |
| 🎬 荐片 P2P | 有 | `api2.rinhome.com` 整体 404（带 `JPAUTH` 鉴权头也一样），服务下线 |
| 📻 有声小说吧 | 无 | 音频源，无 `vod_play_url` |

结论：接 JS 引擎救不回任何一个，失败原因都在「依赖服务下线 / 站点动态渲染 / 框架缺配置」，
与缺 JS 引擎无关。**放弃 QuickJS 路线。**

### 8.2 改为 TS 原生实现豆瓣 + 跨源播放

「聚玩盒子4K」的规则 `douban.js` 只是豆瓣小程序 API 的客户端。豆瓣 7 个分类接口实测全部可用
（需带微信小程序 UA + Referer + apikey），但**豆瓣不托管视频**：
详情里的 `linewatches`/`vendors` 是优酷/B站/爱奇艺的 App 深链（`youku://play?...`），要会员；
`trailers` 只有预告片。所以规则作者没写播放逻辑。

方案：**豆瓣负责发现，CMS 负责播放**。

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 客户端 | `src/sources/douban/doubanClient.ts` | 7 分类 / 搜索 / 详情，纯 TS 请求豆瓣 API |
| 匹配 | `src/sources/douban/playMatch.ts` | 片名归一化 + 年份校验，防串片 |
| 适配器 | `src/sources/douban/DoubanAdapter.ts` | 浏览/搜索/详情；`resolvePlayUrl` 跨源借地址 |
| 装配 | `src/sources/douban/doubanRuntime.ts` | 注入「搜其它源 → 匹配 → 取适配器」 |

解析器按 `ext` 是否含 `douban` 把这类源改判为 `douban`（`SourceType` 新增 `'douban'`）。
