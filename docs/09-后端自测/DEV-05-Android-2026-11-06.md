## 1. REV-33：版本号解析改为"可读则读，不可读则回退"

### 1.1 改动位置

`android/app/build.gradle:8-43`

### 1.2 行为对比

| 场景 | 改动前 | 改动后 |
| --- | --- | --- |
| package.json 存在且可解析 | `JsonSlurper` 读取，`0.1.0 → 100` | 同左（优先路径不变） |
| package.json 缺失 | 构建脚本配置阶段抛 `FileNotFoundException`，**构建直接失败** | 使用 `FALLBACK_VERSION_NAME='0.1.0'`、`FALLBACK_VERSION_CODE=100`，并打印 `WARN: package.json not found, fallback to 0.1.0 (100)` |
| package.json JSON 损坏/字段异常/无 Groovy JSON 支持 | 构建失败 | `catch (Throwable)` 兜底，回退字面版本并打印 WARN |
| package.json 版本解析为 0.0.0/空 | 会得到 `0.0.0 (0)` | 视为无效，回退字面版本并打印 WARN |
| 版本来源 | 强制依赖 package.json | 优先 package.json；回退值与 package.json 当前版本一致，保证两条路径产物口径相同 |

> 说明：Gradle 读取 package.json 使用的是内置 `groovy.json.JsonSlurper`，**不会启动 node 进程**。REV-33 描述中的"无 node 环境"实际对应"package.json 不可读/构建环境裁剪"；本轮同时验证了"从 PATH 移除 node"仍可构建（见 1.4）。

## 2. AND-18：LocalProxy token 表线程安全 + 未命中明确失败

### 2.1 改动位置

`android/app/src/main/java/com/qoder/cinema/LocalProxyPlugin.java`

| 位置 | 改动 |
| --- | --- |
| `:58-71` | token 表由裸 `LinkedHashMap` 改为 `Collections.synchronizedMap(new LinkedHashMap(...accessOrder=true){ removeEldestEntry })`，保留 100 条 LRU |
| `:178` | token 未命中/过期返回 404 `proxy token not found or expired`（明确失败） |
| `:215` | `forward(...)` 新增 `token` 参数，token 直接来自请求路径 `/p/{token}` |
| `:285` | m3u8 重写使用请求路径中的 token，不再反查 |
| 原 `getTokenFromUrl()` | 已删除（该方法在未命中时会 `UUID.randomUUID()` 伪造 token） |

### 2.2 行为对比

| 场景 | 改动前 | 改动后 |
| --- | --- | --- |
| proxy() 写入 token 与 IO 线程读取并发 | 裸 `LinkedHashMap`（accessOrder）`get()` 会改链表顺序，非线程安全 | `synchronizedMap` 保证 get/put/clear 串行 |
| 代理请求 token 不存在/已被 LRU 淘汰 | 404 `not found` | 404 `proxy token not found or expired`（语义更明确） |
| m3u8 重写需要的 token | `getTokenFromUrl(target.url)` 反查；找不到时生成随机 token → 子分片地址全部指向无效 token | 直接使用请求路径中已解析的 token，**构造上不可能未命中**，也不生成随机 token |
| LRU 上限 | 100 | 100（`MAX_TARGETS`） |
| 并发迭代 | `getTokenFromUrl` 会迭代 token 表，无锁 | 已删除该方法，代码中不再有跨线程迭代 |

### 2.3 对既有 302 / m3u8 重写的影响确认

- **302 逻辑**：`forward()` 中 `redirectCache`（ConcurrentHashMap）、`MAX_REDIRECTS`、跨协议手动跟随、最终 URL 缓存均未改动（`:222-246` 区域）。
- **m3u8 重写**：`rewriteM3u8(manifest, baseUrl, token)` 实现未改；仅 token 来源由"反查"改为"请求路径直传"。相对 URL 仍以 302 后最终地址为基准；`#EXT-X-MAP/KEY/MEDIA` 等 `URI="..."` 标签重写逻辑未改。
- **分片请求**：`/p/{token}/{encoded_url}` 仍先按 token 取 headers，再用分片 URL 转发；token 语义未变。

## 3. AND-20：getPlaybackStats 主线程快照

### 3.1 改动位置

`android/app/src/main/java/com/qoder/cinema/ExoPlayerPlugin.java:422-449`

### 3.2 行为对比

| 场景 | 改动前 | 改动后 |
| --- | --- | --- |
| 插件线程调用 `getPlaybackStats()` | 直接在 CapacitorPlugins 线程读 `player.getCurrentPosition()/getDuration()/getPlaybackParameters()` | `getBridge().executeOnMainThread(...)` 投递主线程后读取 |
| 与 `progress()` 的一致性 | `progress()` 已投递主线程；统计接口未投递，存在同类崩溃风险 | 两个接口统一主线程访问 |
| 返回值一致性 | 多个字段可能跨线程读到不同时刻状态 | 主线程一次读取，返回同一时刻快照 |
| 未初始化 player | 返回基础字段 | 同左（player==null 时跳过 player 相关字段） |

`getPlaybackStats()` 目前无 JS 调用方（AND-20 原文），本改动为消除潜在崩溃路径，不改变接口契约。
