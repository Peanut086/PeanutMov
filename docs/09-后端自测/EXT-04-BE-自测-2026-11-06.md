## 1. 实现清单（FR/AC → 代码位置）

| 需求点 | 落地位置 | 说明 |
| --- | --- | --- |
| FR-60 纯转封装 | `MediaRemuxer.copySamples` | 逐样本 `readSampleData` → `writeSampleData`；单样本缓冲（初始 256KB，上限 16MB），不整片读入 |

| AC-142 原子性 | `MediaRemuxer`（`{output}.part` → fsync → `ATOMIC_MOVE`） | 三级降级：`Files.move(ATOMIC_MOVE)` → `renameTo` → 删目标后 `renameTo` |

## 4. 失败回退矩阵（AC-143）

| 场景 | `code` / `reason` | `.ts` | `.mp4.part` | `remux.status`（前端按 reason 落库） |
| --- | --- | --- | --- | --- |
| 编码不支持（AC3/部分 HEVC） | `E_UNSUPPORTED_FORMAT` / `unsupported-codec` | 保留 | 删除 | `failed` |
| 无视频轨 | — / `no-video-track`（`ok:true, skipped:true`） | 保留 | 无（未创建） | `skipped` |
| 无可用样本（含始终无关键帧） | `E_UNSUPPORTED_FORMAT` / `no-samples` | 保留 | 删除 | `failed` |
| 磁盘不足 | `E_STORAGE_QUOTA` / `insufficient-space` | 保留 | 删除 | `failed` |
| 超时 | `E_TIMEOUT` / `timeout` | 保留 | 删除 | `failed` |
| 用户取消 | `E_CANCELED` / `canceled` | 保留（取消流程由上层删） | 删除 | —（任务被取消） |
| 输入缺失 | `E_FILE_MISSING` / `input-missing` | —（不存在） | 删除 | `failed` |
| 插件不可用（旧 APK） | 前端 `isPluginAvailable=false` 直接跳过 | 保留 | 无 | `skipped` |

## 5. 原子性与取消语义的代码级验证

1. `.part` 路径 = `outputPath + ".part"`；`outputPath` 必须是 `*.mp4`，因此临时文件恒为 `{base}.mp4.part`（与任务书、AC-143 表述一致）。
2. 写入完成顺序：`muxer.stop()`（写完 moov）→ `FileOutputStream(fd).sync()` → `Files.move(ATOMIC_MOVE, REPLACE_EXISTING)`；同目录保证同文件系统，跨设备不支持时降级 `renameTo`。
3. 任何 `!result.ok` 路径在 `finally` 中 `deleteQuietly(part)`；`return`（skip）路径同样经过 `finally`。
4. 插件 `load()` 异步清理历史 `*.mp4.part`，清理只匹配 `.mp4.part`，**不会误删** `RangeDownloader` 断点续传用的 `.part` 与 `.sidecar`。
5. 取消链路：`cancelRemux` → `AtomicBoolean` → `copySamples` 检查点（每 64 样本）→ `RemuxFailure(E_CANCELED)` → `finally` 删 `.part` → 插件返回 `ok:false`。
6. 前台服务配对：`beginPostprocess` 在 `executor.execute` 之前、`endPostprocess` 在任务 `finally`；插件销毁时按 `openPostprocess` 计数兜底归零（`shutdownNow` 丢弃的排队任务不会漏减，避免服务永远停在"转封装中"）。

| Q5 | **API-18 未实现**：同文件里前端已调用 `getStorageInfo` / `setSpeedLimit` | 本次按任务范围只交付 API-17；两方法缺失时前端 `try/catch` 静默降级 → Android 上预检的"存储阻断"（AC-153）会退化为 `navigator.storage.estimate` 兜底 | 需确认 API-18 由哪个任务补齐（涉及 `DownloadRateLimiter.java` 与 `RangeDownloader` 改动，不在本任务交付物内）。**在补齐前 AC-153 在 Android 端不成立**，请勿按已验收处理 |
| Q6 | `deleteInput` 默认 `true`（API-17 约定），前端 JS 桥未传该字段 | 按契约默认 `true`：成功 rename 后由**原生**删除 `.ts` | 前端 `downloadRemuxService` 必须容忍 `.ts` 已不存在（不能因 `E_FILE_MISSING` 把 `remux.status` 记成 `failed`） |
| Q7 | fMP4 直通的 "交付 `.mp4`" 谁来做 rename？ | 原生 `remuxMp4(container:'fmp4')` 只返回 `skipped`，**不动文件** | 由 JS 侧 `rename(*.ts → *.mp4)`（方案 §6.1 时序已如此写），请在前端实现时对齐 |
