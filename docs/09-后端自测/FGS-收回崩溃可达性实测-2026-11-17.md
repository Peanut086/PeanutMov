# FGS 收回崩溃（ForegroundServiceDidNotStartInTimeException）可达性实测

- 设备/包：华为 DCO-AL00（HarmonyOS 12，arm64-v8a），debug 包，`lastUpdateTime` 2026-11-17 21:14:29
- 关联提交：`50b3efd`（收回闸门 + 桥层 getLong 收口）、`a5c8b65`（桥接 start 收口到 `DownloadService.start`）
- 所属批次：闪退加固批次（F1~F4 / G1~G7 同一条线，见记忆 `crash-f1-f4-batch`）
- 数据源：`.tmp/fgs_live.log`（实时 `logcat -v epoch` 落盘，仅取本轮时间窗）+ `.tmp/probe_req.log`（本地探针服务请求流水）

## 一句话结论

**崩溃机制是真的（合成场景复现 2 次，18ms 落地即杀进程），但从生产 UI 入口做「起活↔收回」抖动打不中窗口；唯一 Δ 可以任意小的真实形态是 EXT-04 转封装前后那一对，闸门已在真机上把它接住（观测到 `stop deferred`）。**

## 崩溃机理

`startForegroundService()` 已发出、服务 `onStartCommand` → `startForeground()` 尚未落地时，若 `stopService()` 插进来，AMS 当场判 `ForegroundServiceDidNotStartInTimeException` 并杀整个进程（不是抛给 app 捕获）。因此收回必须延后到前台坐实之后，见 `android/app/src/main/java/com/qoder/cinema/download/DownloadService.java:226`（`stop()` 置 `stopWhenReady`）与 `:72`（`onStartCommand` 补做收回）。

## 路径分档（本次要钉死的东西）

### A. 已钉死：生产入口打不中窗口

| 路径 | 代码位置 | 实测 Δ(start→stop) | 判定依据 |
| --- | --- | --- | --- |
| 切后台时队列已跑空 → 收回保活 | `src/services/downloadService.ts:1633` → `:2068` → `:2041` | 192–200 ms（下限） | 窗口实测 ≤60 ms，至少 3 倍余量 |
| 回前台无条件收回保活 | `src/services/downloadService.ts:1650` | 122 ms | 同上，且这条只 stop 不 start |
| 队列摘要触发收回（下载终态/暂停） | `src/services/downloadService.ts:178`（`emitQueueSummary` → `syncKeepAliveIfBackground`） | 与上行同量级 | 每轮都走 IndexedDB 查询 + 动态 `import()`，天然不止 60ms |
| 原生直链下载全程 | `NativeDownloadManager.stopServiceIfIdle()`（`:321`） | 不经桥 | 整轮 0 条 `methodName: startForegroundService/stopForegroundService`，JS 侧根本不下发起停 |

起停窗口 W_start（桥下发 → `DownloadService started`）实测：热态 10/12/16/18/20/49/60 ms；冷态（`am force-stop` 后首起）20/31/32/34/35 ms。**冷进程并不比热进程慢**——原先"冷态窗口可能放大到 >190ms 从而撞上 Δ 下限"的假设被本组数据推翻，已撤回。stop 下发 → `destroyed` 15–30 ms。混档起停 12+3+4+4 轮，0 次崩溃、0 条 `Bringing down service`。

### B. 仍靠闸门兜住（不可拆除）

| 形态 | 为什么会贴近 0 | 真机证据 |
| --- | --- | --- |
| EXT-04 转封装对：`beginPostprocess` → `endPostprocess` → JS 收回 | `MediaToolPlugin.java:301/306` 与 `DownloadService.java:254/267` 是同一次调用栈内的配对，ts 小/解码快时 begin→end 可以短到 104 ms，随后紧跟收回 | 21:08 epoch 924.706 start → 924.741 started → 927.973 `MediaTool.remuxMp4` → 928.087 destroyed → 928.147 JS `stopForegroundService` → **928.168 `stop deferred`**；进程存活、文件正常落盘、通知正常释放 |
| `DownloadPlugin.stopForegroundService` 的 remux 例外分支 | `DownloadPlugin.java:236` 在 `isPostprocessing()` 时直接 resolve，靠的是后处理计数，不是前台状态 | 与上一行同轮观测（转封装期间未出现 destroyed） |
| 合成场景：桥 `start` 紧跟 `stop` | Δ 完全由调用方决定，加固前 18 ms 即崩溃 | 崩溃记录 18:02:57 / 18:20:35（各 1 次，`am force-stop` 之前的加固前构建）；加固后同脚本报 `stop deferred`，进程存活 |

**口径**：A 档是「按现有代码与实测时序，生产 UI 造不出 ≤60ms 的 Δ」，属观测上界而非形式化证明。任何一方把 start/stop 收进同一批微任务、同一轮 `Promise.all`，或新增插件方法绕过 `DownloadService.start()/stop()` 自己拼 Intent（起服或 `stopService`），A 档结论即刻失效——闸门是唯一防线。

### C. 闸门管不到的残余风险（已知、未修）

1. **两套空闲判定互盲**：`NativeDownloadManager.hasActiveTasks()` 只看原生队列，看不见 JS 侧在飞的 HLS/转封装；JS 的 `foregroundServiceActive` 也看不见原生任务。原生直链因此完全绕开桥。
2. **`stopWhenReady` 是进程内静态量**：进程被系统强杀后标记丢失。危害限于"多留一条常驻通知"，与本崩溃无关，未处理。
3. **设备覆盖**：仅华为 DCO-AL00 + debug 包。**OPPO Reno12（真正报闪退的机型）、release 包、Android 14+ 的 `FOREGROUND_SERVICE_TYPE_DATA_SYNC` 配额路径均未测**——不同 ROM 的 AMS 时序与 iAware 类强杀会改变 Δ 分布。

## 本次附带修掉的洞（`a5c8b65`）

`DownloadPlugin.startForegroundService` 原先自己拼 Intent 起服务，绕过 `DownloadService.start()` 里的 `stopWhenReady = false` 清零 ⇒ 一次过期收回置位后，下一个桥接 start 会在 `onStartCommand` 里立刻 `stopServiceIfIdle()`，而 JS 侧 HLS 在飞时原生闸门恒判"无任务" ⇒ 保活被无声摘掉（服务一坐实就被上一次过期收回停掉）。改为统一走 `DownloadService.start()`。真机复验：过期收回后桥接 start → `isForeground=true` 保持 2.5s，再显式收回才 `destroyed`。

## 复现方法

1. 起本地探针服务：`python .tmp/probe_srv.py`（8899：TVBox 清单 + 限速 mp4 + hold/gate 闸门）。HLS 分片必须以 `0x47` 起始，否则 App 判「TS 同步字节错位」直接失败。

4. 全部经生产入口：搜索 → 详情 → 点「下载」→ `KEYCODE_HOME`，不直接调桥方法（直调桥只用于制造 B 档的合成场景）。
5. 判据：`logcat -b crash -d | grep -E "ForegroundServiceDidNotStart|Bringing down service"` 为 0，且 `pidof` 未变。

## 测试坑（每条都会直接造出假结论）

1. 搜索有**本地结果缓存 + 体检结论过滤**：新片要用没搜过的词进；「重试失败源」只点一次——连点会把 core2/max8/queue32 的原生池压在 11 个死源上，探针查询永远排不到。
2. `adb install -r` **不杀正在跑的进程**，旧 dex 继续执行；装完必须 `am force-stop`。我因此把一批数据错标成"未加固"，实际已带闸门。
3. python 经 `.tmp/h.py` 的 TextIOWrapper 输出是块缓冲，长任务要重定向到文件，不能用管道（管道还会吞掉 `BUILD FAILED`）。
4. CDP `eval` 在页面/进程切换时抛 `ConnectionAbortedError`，需重建会话；WebView 后台会冻结，观测只能在 foreground 做。
5. `logcat -d -b crash` 会保留历史行，必须按时间窗过滤；崩溃中心里的 `21:19:26 共崩溃 1 次` 是我自己 `am force-stop` 产生的退出记录，不是 FGS 崩溃（装机后 `ForegroundServiceDidNotStart` 命中 0）。
